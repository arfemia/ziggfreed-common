> Built on Hytale Update 7 (0.7.0), like 2.5.0: the manifest's `ServerVersion` and `Dependencies` are unchanged, and no module gains an edge. Additive over 2.5.0: nothing is removed or changes shape, so a consumer built against 2.5.0 links unchanged. New: zc-entity's `stats/RollbackStatSweep` and `EntityBootstrap.installRollbackSweep`, zc-commerce's `CurrencyEngine.creditLanded` and the default `ItemWallet.giveIntoBag`, zc-loot's `LootRewardKinds.handIntoBag` and `loot/claim/ClaimKinds` (`name`, `kindOf(Claim)`, `kindOf(String)`, `KEY_PREFIX` and the word keys `BOSS`, `DUNGEON`, `BONUS`, `QUEST`, `EVENT` and `ADMIN`), zc-instance's `RewardChestPage.OPENED_MOMENT` and `RARITY_ARG`, zc-presentation's `TilePainter.GOLD_CARD_WIDTH` and `GOLD_CARD_HEIGHT`, and zc-almanac's `AlmanacCollectionAsset.Slot.missingMod()` and `Slot.passesModGate()` and `AlmanacEntryAsset.FINDING_COLLECTION_SLOT_CONDITION_IGNORED`.

## New

- **The rollback sweep, `stats/RollbackStatSweep` (zc-entity).** When a player is ready, every saved stat modifier keyed `zigtrack:` is removed, on any stat the server loads. This version never writes that prefix; a later version keys its track grants with it, so a server rolled back to 2.5.1 keeps none of them. One INFO line names each player swept, with the count (`[stats] rollback sweep: removed <N> saved zigtrack: stat modifier(s) from <name> (<uuid>)`), and a clean player logs nothing. `EntityBootstrap.installRollbackSweep` hangs it on `PlayerReadyEvent` at `FIRST` from the library's root, so a server running the library with no consumer sweeps too, and the sweep itself runs on the player's world thread. A stat type the server does not load keeps its saved values in the engine's unknown section, out of reach and inert. Test: `RollbackStatSweepTest`.
- **An Almanac collection slot can gate on a mod (zc-almanac).** A `Collection` slot takes its own `Requires`, the same block a file's top level and a reward row write (`PresenceRequiresCodec`, read through `ModGates`), and where that mod reads a definite 0 `AlmanacCollectionAsset.slots()` leaves the slot out, so the grid, its cap, the audit and the owned marks never see it and the next slot takes its place (`Slot.missingMod()` names the missing mod, `Slot.passesModGate()` answers the gate). The slot reads nothing else there: any other condition, `Max: 0` included, warns `COLLECTION_SLOT_CONDITION_IGNORED` (`AlmanacEntryAsset.FINDING_COLLECTION_SLOT_CONDITION_IGNORED`) among the page's own findings, never failing the file. A left-out slot is never counted in a log line. The Asset Editor lists the leaf; a slot without it reads as before, and nothing saved moves. Test: `AlmanacEntryAssetTest`.

## Changed

- **A reward chest's cards say where each reward came from (zc-loot, zc-instance, zc-presentation).** The new `loot/claim/ClaimKinds` is the one table of payout kinds: a Claim's kind is read from its source's site, the part before the first colon, each kind the lang key of its one word (`ziggfreedcommon.loot.claim.kind.*`): `boss` Boss Kill, `dungeon` Dungeon Clear, `chest` Bonus, `quest-drop` Quest, `reward` Event and `admin` Gift. `kindOf(Claim)` reads a reward chest's own roll by its chest key, as the boss's when the chest is filed under a boss fight's run and as a bonus under a `chest:<uuid>` key. A consumer whose own code writes Claims names its site once at setup with `ClaimKinds.name(site, wordKey)`; a library site keeps its word, and a site nobody named shows no word. The word rides the card's line as `DetailLine`'s `tag`, which `TilePainter.rewardCards` shows over the picture on both faces. Nothing saved moves: every Claim already carries its source and chest key, so Claims waiting from before this version get their words too. New en-US keys in `ziggfreedcommon.loot.lang`: `claim.kind.boss`, `.dungeon`, `.bonus`, `.quest`, `.event` and `.admin`. Test: `ClaimKindsTest`.
- **Gold cards read rarity as items do, five a row (zc-presentation, zc-instance).** `TilePainter.rewardCards` sizes a gold card by one whole Anchor, `GOLD_CARD_WIDTH` x `GOLD_CARD_HEIGHT` (110 x 154), so five sit a row in the 596-wide grid while item cards keep 140 x 172, four a row. Both faces read the quality their line names through one path: the quality's slot art behind the picture and its word in its colour, Common included, on a gold card as on an item's (a gold card named a rarity only above Common before). A reward with no chance shows none. `ClaimsView.chestCards` sums alike non-items only within one kind, so one reward from a boss and from a dungeon clear is two cards.
- **A reward chest opens with a flash and a sound (zc-instance, zc-presentation).** The page's first build shows `#OpenBurst`, a one-shot `Sprite` behind the chest's picture (`RepeatCount` 1, `KeepLastFrame`), and fires the feedback moment `Reward_Chest_Opened` (`RewardChestPage.OPENED_MOMENT`, its arg `rarity`, `RARITY_ARG`, the rarest reward's rarity as its drop's chance reads; absent when none carries a chance). The shipped file plays `SFX_Chest_Wooden_Open`, with `SFX_Discovery_Z1_Short` for Rare, `SFX_Memories_Unlock_Local` for Epic and `SFX_Chest_Legendary_FirstOpen_Player` for Legendary; a pack's same-named file or the owner layer replaces it. Epic and Legendary cards carry a looping `Sprite` sheen. All of it plays on the client: an open costs its one page build and one sound, and a press's rebuild repeats neither. The sheets are drawn by `tools/ui/make_reward_sprites.py`. Tests: `ShippedFeedbackMomentsTest`, `ZigKitDocumentsTest`.

## Fixed

- **An item currency paid into a full bag lands (zc-commerce).** `NativeItemWallet.give` hands an item currency over through `LootRewardKinds.handToPlayer` (pickup routing with the pickup notice, the rest to the overflow policy) and counts the part at the feet as landed. It gave through `InventoryUtil.give`, which dropped whatever did not fit. Every hand-over through the item wallet rides it: an item currency's credit, refund and admin set, and an item price handed back when a purchase is refunded or fails partway (`CostEngine`). Test: `ItemCurrencyLandsLikeAPickupTest`.
- **A capped credit receipts what landed (zc-commerce).** The new `CurrencyEngine.creditLanded` answers what a credit landed, and `CurrencyObserver.earned` hears that amount. `CurrencyRewardKind` receipts what landed: the cut amount at a cap, no row when nothing moved, and an item currency's row marked pickup-noticed. Test: `CurrencyRewardKindTest`.
- **A capped item currency holds its cap (zc-commerce, zc-loot).** A capped item currency lands in the bag alone: `CurrencyEngine` credits, refunds and admin-sets it through the new `ItemWallet.giveIntoBag` (a default method, `give` unless a wallet overrides it), which `NativeItemWallet` answers through the new `LootRewardKinds.handIntoBag`, the pickup delivery with no overflow. What the bag cannot take within the cap is cut and receipted as cut: the cap reads the bag, so a pile at the feet would pass every later cap check and, picked up, carry the wallet past it. An uncapped item currency still drops the rest at the player's feet. Test: `CappedItemCurrencyHoldsItsCapTest`.
- **A dungeon's entry refund lands (zc-instance).** `DungeonEntryCost.refund` hands an item entry cost back through `LootRewardKinds.handToPlayer` (pickup routing with the pickup notice, the rest to the overflow policy as one pile at the feet). It gave through `InventoryUtil.give`, which dropped whatever did not fit and only logged it. Both refunds ride it: a spend whose take falls short partway, and a teleport the engine refuses after the cost was spent. Test: `DungeonRefundLandsLikeAPickupTest`.

## For a consumer

- Never key a stat modifier of your own `zigtrack:`: the sweep removes it at every ready.
- A payout that reports what it handed over reads `CurrencyEngine.creditLanded`, never a balance delta: a full bag sends part of an uncapped item currency to the player's feet, where the balance cannot see it, and cuts a capped one to what the bag takes.
- An Almanac page that shows another mod's item gates that slot on the mod (`Min` 1), so a server without it never lists an item it cannot have.
- A consumer whose own code writes Claims under a source site of its own names that site's word once at setup with `ClaimKinds.name`; never reuse a library site's spelling, and never change a site's spelling once Claims carry it.
