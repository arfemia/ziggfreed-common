> Built on Hytale Update 7 (0.7.0), like 2.4.0: the manifest's `ServerVersion` and `Dependencies` are unchanged. Additive over 2.4.0: nothing is removed or changes shape, so a consumer built against 2.4.0 links unchanged. New: zc-core's `npcbuilder/ZigBuilderActionBase`.

## Fixed

- **The Asset Editor's schema pass.** The engine builds each NPC builder's schema (`BuilderBase.toSchema`, the pass behind `SchemaGenerator.generateAssetSchemas`, which the Asset Editor runs as it starts and `--generate-asset-schema` runs headless) by calling `readConfig` with null data and the schema and descriptor modes on. The engine's own getters register their field and return in those modes; a raw `getOptionalJsonElement` read does not, and dereferences the null data. Three of the library's builders kept a field as raw JSON that way, and the first of them the pass reached stopped it whole with a `NullPointerException` (`Cannot invoke "com.google.gson.JsonElement.isJsonObject()" because "data" is null`): `BuilderActionZigGrant`'s `Loot`, `BuilderActionZigFeedback`'s `Args` and `BuilderActionPlacementInteract`'s `Open`. Each now extends `ZigBuilderActionBase` and reads its field through `getOptionalRawJson(data, name, shortDescription)`, which in the schema mode registers the field as any JSON (the builder's schema sets `additionalProperties: false`, so a field left out would read as unknown), in the descriptor mode adds it as an optional attribute, and otherwise reads it as before, still marking the key as one the builder asked for. A file is read exactly as in 2.4.0.

## For a consumer

- A consumer's own NPC builder that keeps a field as raw JSON (an `ActionBase` builder reading `getOptionalJsonElement(data, ...)` in its `readConfig`) has the same crash. Extend `ZigBuilderActionBase` and read the field through `getOptionalRawJson`, or guard the read on `isCreatingSchema()` and `isCreatingDescriptor()` and register the field there yourself.
