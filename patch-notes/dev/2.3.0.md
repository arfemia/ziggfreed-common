> Built on Hytale Update 7 (0.7.0): the manifest's `ServerVersion` is `>=0.7.0-pre.0 <0.8.0`, and the jar calls Update 7's renamed members, so it does not link on 0.6.x. Additive over 2.2.0: every public and protected member a consumer built against 2.2.x links is unchanged; `EventTitles` gains its style forms, a FeedbackMoment banner its `Style` and `SoundEventId`, and `ToastablePage` its `writeInPlace`, zc-world gains `world/TickingSections`, and the NPC placement runtime gains `PlacementFortifySystem`.

- **Changed: built on Update 7.** `ServerVersion` reads `>=0.7.0-pre.0 <0.8.0`: the engine matches pre-releases npm-strict, so the 0.6 range read every 0.7.0 pre-release as outdated. A 0.6.x server keeps 2.2.0. Test: `ManifestTargetTest` (the range admits the server jar the build compiles against and that line's release, and claims no later line).
- **Changed: `EventTitles` draws through the engine's `EventTitleStyle` overload.** Update 7 marks both boolean `EventTitleUtil.showEventTitleToPlayer` overloads `forRemoval`. `show(PlayerRef, Message, Message, boolean)` and its 8-argument form keep their descriptors and map `major` to `EventTitleStyle.Major`, else `Default`, inside, exactly as the engine's boolean overloads did; the short form still sends 4 s, a 1.5 s fade in and out, and no icon, for both sizes. A null secondary goes out as an empty line, because the style overload dereferences it (the headline used to throw inside the guard and show nothing). Failures log through `SafeLog` at FINE.
- **New: `EventTitles` takes the engine's styles and a sound.** `show(PlayerRef, Message, Message, EventTitleStyle, String soundEventId)` and `show(PlayerRef, Message, Message, EventTitleStyle, String icon, float duration, float fadeIn, float fadeOut, String soundEventId)` draw any `EventTitleStyle` (`Default`, `Major`, `GoblinBreach`, `VoidEviction`); the short form fades in as the engine fades that style in (`defaultFadeIn(EventTitleStyle)`, the engine's `getDefaultFadeInDuration`). A non-blank sound id plays to the same player after the banner, flat (`SoundUtil.playSoundEvent2dToPlayer`, `SoundCategory.SFX`), the way the engine plays an authored `EventTitleConfig`'s `SoundEventId`; an id no pack ships plays nothing. Test: `EventTitlesTest`.
- **New: a FeedbackMoment banner's `Style` and `SoundEventId`.** `Broadcast` gains `Style` (a string leaf offering the four styles in the Asset Editor, read whatever its case; it wins over `Major` when authored, and an unknown name falls back to `Major`) and `SoundEventId` (each viewer hears it as the banner appears). `Broadcast.style()` and `soundEventId()` read them, and `FeedbackEngine` shows the banner through the style form. Test: `BroadcastStyleTest`.
- **Fixed: `NativeInputGate` reads a durability condition on Update 7.** Update 7 renames the protocol's durability operator enum to `ComparisonOperator` (the same six constants) and retypes `DurabilityConditionInteraction.operator`; a 0.6.8-built jar threw `NoClassDefFoundError` in `probe`, logged it and answered `Verdict.NONE`, so a durability-gated native root (vanilla bows and crossbows gate their shots and signatures that way) never had its press deferred to it. The comparison is a package-private `compare(ComparisonOperator, double, double)`. Test: `NativeInputGateTest`.
- **Fixed: in-place page updates on Update 7; new `ToastablePage.writeInPlace`.** Update 7 renames `PageManager`'s in-place page update to `updateLegacyCustomPage`, with the same body; a 0.6.8-built jar threw `NoSuchMethodError` inside a swallowed catch, so a toastable page's toast pushes and the Play page's status pushes stopped. `ToastablePage.writeInPlace(Player, CustomPageLifetime, UICommandBuilder)` (protected, final) is the library's one caller of the engine's in-place update; the toast push and `PlayModePage`'s status push write through it after their own world-thread recheck.
- **Technical: `EngineSeamHygieneTest`** (the wiring root) fails a library main source that names `EventTitleUtil` outside `feedback/EventTitles`, calls `updateLegacyCustomPage` outside `ui/toast/ToastablePage`, or names either member Update 7 renamed, with comments and literals blanked.
- **Fixed: `BuildPermission` reads the environment off the section on Update 7.** `world/BuildPermission.environmentAllowsModification` (zc-world) read `BlockChunk.getEnvironment(III)` through the section's column, which Update 7 removes; a 2.2.0 jar threw `NoSuchMethodError` into its own catch and the environment half failed open, so a non-creative placement the engine refused in a protected environment still wrote the placed-block ledger and fired `PLACE_BLOCK`. It now reads the cell's `EnvironmentSection` off its chunk section (`ChunkStore.getChunkSectionReferenceAtBlock`, then `EnvironmentSection.get(x, y, z)`), the read the engine's own `BlockPlaceUtils` makes. Cannot tell still reads as allowed (no section in memory, no environment data, an unknown id, any throw), and every public descriptor is unchanged. The root `BlockAccessorHygieneTest` now also fails a main source calling `getEnvironment(...)` with arguments. Tests: `BuildPermissionTest`, `BlockAccessorHygieneTest`.
- **Fixed: a world spawn point is asked for without waiting.** Update 7 replaces `ISpawnProvider.getSpawnPoint(World, UUID)` with `getSpawnPointAsync`, answering a `CompletableFuture<Transform>`; a 2.2.0 jar threw `NoSuchMethodError` at all three callers, and the `WorldSpawn` placement anchor never resolved. The new `npc/SpawnPoints` (zc-dialogue) asks a provider (`ask`), reads a point that has landed without blocking (`now`, `failureOf`) and continues on the world thread once it lands (`whenLanded`), never joining the future, since a provider fitting its point to the ground loads the spawn column first. The `WorldSpawn` anchor keeps one query per world on its way across sweep passes, forces a sweep when it lands with a point (so it places even after the retry budget is spent) and logs a failed query once per world at WARNING. `NpcAutoSpawn.ensureSpawned` places at once when the point is at hand, else on the world thread when it lands, checking its once-per-world marker again first. `NpcSpawnService.resolveSpawnPosition` keeps its signature and answers only a point already at hand, else the player's position. Tests: `SpawnPointsTest`, `WorldSpawnPointsTest`, `NpcAutoSpawnTest`.
- **Changed: the inventory snapshot and strip manage Update 7's rune sections.** `InventorySections.ALL` (zc-core `inventory/`) adds `InventoryComponent.ABILITIES_SECTION_ID` (-11) and `RUNE_BAG_SECTION_ID` (-12), so `InventorySnapshot.capture`, `strip` and `apply` and `InventoryStripPolicy`'s default (`STRIP_ALL`) cover slotted rune abilities and the rune bag. `apply` now clears only the sections its snapshot captured: a snapshot taken by a build that did not manage a section never stripped it, so its restore leaves that section alone instead of wiping what the player carried through the round. Public descriptors unchanged. Test: `InventorySectionsTest`.
- **Changed: what a stack's quality reads on Update 7.** Update 7 stores a quality on a stack only when one is stamped on it (`ItemStack#withQuality`, saved under `QualityOverride`); an unstamped stack reads its item's current quality. So `ItemReadings.quality(ItemStack)`, `qualityId(ItemStack)` and `hytale:item_quality` follow an item's reload for an unstamped stack and differ from the item readings (`hytale:tool_quality`) only for a stamped one: a "made with" quality must be stamped. A quality stamped on 0.6.8 (saved under the old `Quality` key) is dropped at its first Update 7 load, by the engine's inventories and this library's own stores alike: it is the one key the item codec renamed (`Quality` to `QualityOverride`), so stamped stats, a rename and a tooltip (`Metadata`) and a durability bonus (`MaxDurability`) load as saved, and nothing here migrates the quality. The reads and their descriptors are unchanged; the javadocs and the zc-entity router say so.
- **Technical: the quality and pending-reward tests assert Update 7's mechanics.** `ItemReadingsTest`, `HytaleFactorsTest` and `ItemMetadataKeysTest` pin Update 7's quality storage (the stack-versus-item split on `TestItems.requalified`, an unstamped stack following its item through a reload, a stamp saved under `QualityOverride`), and the unreadable-stack case now fails the metadata read, since Update 7's encoder reads every field directly. `PendingRewardStoreTest.everyWriteCarriesTheVersion` is tagged `engine-items`: Update 7's `FileUtil` logs at class init, which only the engine's log manager allows; a new untagged test pins that a write the engine cannot make never reaches the caller.
- **Fixed: entities go only into a ticking chunk section (new `world/TickingSections`, zc-world), and placement is idempotent.** On Update 7 a chunk section loads non-ticking whatever its column's state, and the column's flag no longer reaches its sections (0.6.8's `ChunkSystems.OnNonTicking` is gone). An entity added into a non-ticking section is parked into the section's entity list on the spot (`UpdateLocationSystems`): `Store.addEntity` answers null, `NPCPlugin.spawnEntity` skips its post-spawn, and the entity comes back as a `LOAD` add when a player's hot sphere or a `SET_TICKING` section request wakes the section; the parked copy is saved with the section. The placement sweep asked for the anchor's column (`getChunkReferenceAsync(SET_TICKING)`) and checked only `ChunkFlag.TICKING`, so a `WorldSpawn` placement placed at boot was parked with no ledger row and no `Fortify`, every later sweep in that state parked another copy, and a `Respawn` placement over a sleeping section `REPLACE`d its parked NPC. `TickingSections` reads a block's section (`stateAt`: `TICKING`, `PARKING`, `ABSENT`), wakes it (`wake`: `getChunkSectionReferenceAsync` with `SET_TICKING | HIGH_PRIORITY`; on the world thread a section in memory ticks before it returns), wakes one in memory and answers whether an add stays (`ensureTicking`, which never loads), runs a step once the section ticks (`whenTicking`), and holds a ticking section's active timer and its column's (`holdTicking`, which never wakes, so a system may call it). The sweep's place pass decides on the anchor's section: it wakes a sleeping section in memory on the spot and places into it on a second round of the same sweep, never the round that woke it, so the despawn pass first adopts any copy the wake brought back (one per instance; the rest are removed in that pass); a section not in memory is requested ticking, and only a landed request (a section ref still valid) sweeps again. Before any spawn the place pass checks for a copy of the instance by its persisted `ZiggfreedCommon:PlacedNpc` stamp (placement id and anchor key; a parked copy has no ledger row, so not by a row's uuid), among the copies the despawn pass kept or adopted and among the holders the anchor's section holds parked or saved (`EntitySection.getEntityHolders()`), and a found copy means no spawn; the check guards beside the round rule (a copy a wake brings back inside the same place pass is held back by that section's wait for the next round), so no boot or sweep adds a second copy. `Fortify` moved out of `NpcPlacementService.place`'s post-spawn, which the engine skips for an NPC it parks, and it cannot go in `preAddToWorld` (the holder has no `EntityStatMap` yet): the new `PlacementFortifySystem`, a holder system ordered after `EntityStatsSystems.Setup` and `BalancingInitialisationSystem` (the engine's own shape for health at the add), puts the bonus on every add of a placed NPC, spawn or load, and fills the enlarged pool on a spawn or when the bonus was missing; the modifier is saved with the entity, so a parked copy keeps it and one back from a park gets it. Every copy the despawn pass keeps or adopts, never a surplus one, gets its upkeep (`NpcPlacementService.upkeep`): its cached position from its transform, its keep-alive pin at that position and its `Fortify`, each idempotent. Before this an adopted copy got only its ledger row, and after a restart an instance had no pin and no cached position (both live in memory) until it was placed again; now the first sweep that finds it awake takes them again (the boot sweep skips a hub still parked, and `Fortify` is saved with the entity). `NpcSpawnService.spawnRole` never adds into a non-ticking section (it wakes one in memory and refuses one that is not, with a WARNING); `NpcAutoSpawn` places through `whenTicking`; `EncounterSpawner.trySpawn` wakes or refuses the same way and `spawnWhenLoaded` requests the section; `EncounterChunkHold` holds the section's timer as well as the column's, and the encounter tick holds its subject's section as well as its own. The keep-alive pins read the column's residency instead of its ticking flag, so a pin taken after a section wake holds and an unpin after the column stopped ticking no longer leaks the keep-loaded count. A placement logs one INFO line when it places. Public descriptors unchanged (`NpcPlacementService.fortify` keeps its descriptor and still fills the pool); `NpcPlacementService.isChunkLoaded` and `requestChunk` keep their column reads for 2.2.0 linkage, and nothing in the library calls them. The root `SectionTickingHygieneTest` fails a main source reading `ChunkFlag.TICKING` or passing `SET_TICKING` outside `TickingSections`. Tests: `TickingSectionsTest`, `AnchorSectionsTest`, `NpcPlacementReconcilerTest`, `NpcPlacementServiceTest`, `SectionTickingHygieneTest`.
- **Fixed: a stopping world answers a section wake once.** A world that takes no more tasks (its `execute` throws while it stops) failed only the future behind the continuation, so `TickingSections.whenTicking` never reached its `refused` callback and `EncounterSpawner.spawnWhenLoaded` never completed, which left `/zigencounter spawn` with no reply when it ran as the server stopped. Each now answers exactly once: `whenTicking` refuses on the thread that landed the wake, and `spawnWhenLoaded` answers `Refusal.ENGINE_FAILED` with one WARNING. A wake still loading when the world stops may get neither answer. Public descriptors unchanged. Tests: `TickingSectionsTest`, `EncounterSpawnerWakeTest`.
- **Fixed: a world's placement ledger rows survive a server stop (M133).** `NpcPlacementReconciler.onWorldRemoved` (the library's world-removal evictor) dropped a removed world's `NpcPlacementLedger` rows and cached positions, and the engine removes every world when the server stops (`RemoveWorldEvent` as `EXCEPTIONAL`, the reason a crash carries), so each boot re-adopted the world's placed NPCs instead of matching their rows, and a placement without `Respawn` whose NPC had been killed stood again after a restart. It now drops them only for a world deleted with its removal, read from its `WorldConfig`'s `DeleteOnRemove` or `DeleteOnUniverseStart` (an instance or portal world torn down, a pruned world), so a torn-down instance still leaves no orphan row; a world unloaded with `/world remove` keeps its rows, and sweep state still clears on any removal. Rows a stop dropped before 2.3.0 stay dropped, so the first boot on 2.3.0 re-adopts once. Public descriptors unchanged. Test: `NpcPlacementWorldRemovalTest`.
- **New: content validators for calendar events, titles and the Almanac (M141).** Each has an `audit()` that never throws, for a consumer to fold, over a pure `audit(...)` core.
  - `CalendarEventValidator` (zc-calendar, domain `calendar`) files an event's load problems as findings (an error when it can never run, a warning for an unknown `Clock`) and reports an `Icon` naming no loaded item, a Presentation or Herald key no lang file ships, a Herald line with no `TitleKey` (`CalendarHerald` drops it), and a calendar spawn with no `Event`, no `Spawn` body, or an `Event` nothing loads. An event switched off in its own file is skipped.
  - `TitleValidator` (zc-objectives, domain `title`) reports a title id the save format refuses, a `Text` key no lang file ships, a title nothing names (a note), and a `Title` reward in the achievement or quest catalogue naming no title or one no file defines (read only once `ProgressionRuntime` is built).
  - `AlmanacValidator` (zc-almanac, domain `almanac`) folds a page's own warnings with a page named for no loaded calendar event (asked of the `Occurrences` slot), an `Icon` or `Hero.Composition` item naming no loaded item, a tally line with no `Kind` or one nothing registers or fires, and a key no lang file ships. Nothing while the Almanac is switched off.
  - `validation/TextKeyAudit` (zc-core) is the one check of an authored lang key (`UNKNOWN_TEXT_KEY`, a warning; every key reads as shipped while no catalogue is loaded), and `TitleRewardKind.isTitleReward` answers whether a reward is of the Title kind.
  - Tests: `TextKeyAuditTest`, `CalendarEventValidatorTest`, `TitleValidatorTest`, `AlmanacValidatorTest`.
