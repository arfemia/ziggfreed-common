> Built on Hytale Update 7 (0.7.0): the manifest's `ServerVersion` is `>=0.7.0-pre.0 <0.8.0`, and the jar calls Update 7's renamed members, so it does not link on 0.6.x. Additive over 2.2.0: every public and protected member a consumer built against 2.2.x links is unchanged; `EventTitles` gains its style forms, a FeedbackMoment banner its `Style` and `SoundEventId`, and `ToastablePage` its `writeInPlace`.

- **Changed: built on Update 7.** `ServerVersion` reads `>=0.7.0-pre.0 <0.8.0`: the engine matches pre-releases npm-strict, so the 0.6 range read every 0.7.0 pre-release as outdated. A 0.6.x server keeps 2.2.0. Test: `ManifestTargetTest` (the range admits the server jar the build compiles against and that line's release, and claims no later line).
- **Changed: `EventTitles` draws through the engine's `EventTitleStyle` overload.** Update 7 marks both boolean `EventTitleUtil.showEventTitleToPlayer` overloads `forRemoval`. `show(PlayerRef, Message, Message, boolean)` and its 8-argument form keep their descriptors and map `major` to `EventTitleStyle.Major`, else `Default`, inside, exactly as the engine's boolean overloads did; the short form still sends 4 s, a 1.5 s fade in and out, and no icon, for both sizes. A null secondary goes out as an empty line, because the style overload dereferences it (the headline used to throw inside the guard and show nothing). Failures log through `SafeLog` at FINE.
- **New: `EventTitles` takes the engine's styles and a sound.** `show(PlayerRef, Message, Message, EventTitleStyle, String soundEventId)` and `show(PlayerRef, Message, Message, EventTitleStyle, String icon, float duration, float fadeIn, float fadeOut, String soundEventId)` draw any `EventTitleStyle` (`Default`, `Major`, `GoblinBreach`, `VoidEviction`); the short form fades in as the engine fades that style in (`defaultFadeIn(EventTitleStyle)`, the engine's `getDefaultFadeInDuration`). A non-blank sound id plays to the same player after the banner, flat (`SoundUtil.playSoundEvent2dToPlayer`, `SoundCategory.SFX`), the way the engine plays an authored `EventTitleConfig`'s `SoundEventId`; an id no pack ships plays nothing. Test: `EventTitlesTest`.
- **New: a FeedbackMoment banner's `Style` and `SoundEventId`.** `Broadcast` gains `Style` (a string leaf offering the four styles in the Asset Editor, read whatever its case; it wins over `Major` when authored, and an unknown name falls back to `Major`) and `SoundEventId` (each viewer hears it as the banner appears). `Broadcast.style()` and `soundEventId()` read them, and `FeedbackEngine` shows the banner through the style form. Test: `BroadcastStyleTest`.
- **Fixed: `NativeInputGate` reads a durability condition on Update 7.** Update 7 renames the protocol's durability operator enum to `ComparisonOperator` (the same six constants) and retypes `DurabilityConditionInteraction.operator`; a 0.6.8-built jar threw `NoClassDefFoundError` in `probe`, logged it and answered `Verdict.NONE`, so a durability-gated native root (vanilla bows and crossbows gate their shots and signatures that way) never had its press deferred to it. The comparison is a package-private `compare(ComparisonOperator, double, double)`. Test: `NativeInputGateTest`.
- **Fixed: in-place page updates on Update 7; new `ToastablePage.writeInPlace`.** Update 7 renames `PageManager`'s in-place page update to `updateLegacyCustomPage`, with the same body; a 0.6.8-built jar threw `NoSuchMethodError` inside a swallowed catch, so a toastable page's toast pushes and the Play page's status pushes stopped. `ToastablePage.writeInPlace(Player, CustomPageLifetime, UICommandBuilder)` (protected, final) is the library's one caller of the engine's in-place update; the toast push and `PlayModePage`'s status push write through it after their own world-thread recheck.
- **Technical: `EngineSeamHygieneTest`** (the wiring root) fails a library main source that names `EventTitleUtil` outside `feedback/EventTitles`, calls `updateLegacyCustomPage` outside `ui/toast/ToastablePage`, or names either member Update 7 renamed, with comments and literals blanked.
- **Fixed: `BuildPermission` reads the environment off the section on Update 7.** `world/BuildPermission.environmentAllowsModification` (zc-world) read `BlockChunk.getEnvironment(III)` through the section's column, which Update 7 removes; a 2.2.0 jar threw `NoSuchMethodError` into its own catch and the environment half failed open, so a non-creative placement the engine refused in a protected environment still wrote the placed-block ledger and fired `PLACE_BLOCK`. It now reads the cell's `EnvironmentSection` off its chunk section (`ChunkStore.getChunkSectionReferenceAtBlock`, then `EnvironmentSection.get(x, y, z)`), the read the engine's own `BlockPlaceUtils` makes. Cannot tell still reads as allowed (no section in memory, no environment data, an unknown id, any throw), and every public descriptor is unchanged. The root `BlockAccessorHygieneTest` now also fails a main source calling `getEnvironment(...)` with arguments. Tests: `BuildPermissionTest`, `BlockAccessorHygieneTest`.
- **Fixed: a world spawn point is asked for without waiting.** Update 7 replaces `ISpawnProvider.getSpawnPoint(World, UUID)` with `getSpawnPointAsync`, answering a `CompletableFuture<Transform>`; a 2.2.0 jar threw `NoSuchMethodError` at all three callers, and the `WorldSpawn` placement anchor never resolved. The new `npc/SpawnPoints` (zc-dialogue) asks a provider (`ask`), reads a point that has landed without blocking (`now`, `failureOf`) and continues on the world thread once it lands (`whenLanded`), never joining the future, since a provider fitting its point to the ground loads the spawn column first. The `WorldSpawn` anchor keeps one query per world on its way across sweep passes, forces a sweep when it lands with a point (so it places even after the retry budget is spent) and logs a failed query once per world at WARNING. `NpcAutoSpawn.ensureSpawned` places at once when the point is at hand, else on the world thread when it lands, checking its once-per-world marker again first. `NpcSpawnService.resolveSpawnPosition` keeps its signature and answers only a point already at hand, else the player's position. Tests: `SpawnPointsTest`, `WorldSpawnPointsTest`, `NpcAutoSpawnTest`.
- **Changed: the inventory snapshot and strip manage Update 7's rune sections.** `InventorySections.ALL` (zc-core `inventory/`) adds `InventoryComponent.ABILITIES_SECTION_ID` (-11) and `RUNE_BAG_SECTION_ID` (-12), so `InventorySnapshot.capture`, `strip` and `apply` and `InventoryStripPolicy`'s default (`STRIP_ALL`) cover slotted rune abilities and the rune bag. `apply` now clears only the sections its snapshot captured: a snapshot taken by a build that did not manage a section never stripped it, so its restore leaves that section alone instead of wiping what the player carried through the round. Public descriptors unchanged. Test: `InventorySectionsTest`.
- **Changed: what a stack's quality reads on Update 7.** Update 7 stores a quality on a stack only when one is stamped on it (`ItemStack#withQuality`, saved under `QualityOverride`); an unstamped stack reads its item's current quality. So `ItemReadings.quality(ItemStack)`, `qualityId(ItemStack)` and `hytale:item_quality` follow an item's reload for an unstamped stack and differ from the item readings (`hytale:tool_quality`) only for a stamped one: a "made with" quality must be stamped. A quality stamped on 0.6.8 (saved under the old `Quality` key) is dropped at its first Update 7 load, by the engine's inventories and this library's own stores alike: it is the one key the item codec renamed (`Quality` to `QualityOverride`), so stamped stats, a rename and a tooltip (`Metadata`) and a durability bonus (`MaxDurability`) load as saved, and nothing here migrates the quality. The reads and their descriptors are unchanged; the javadocs and the zc-entity router say so.
- **Technical: the quality and pending-reward tests assert Update 7's mechanics.** `ItemReadingsTest`, `HytaleFactorsTest` and `ItemMetadataKeysTest` pin Update 7's quality storage (the stack-versus-item split on `TestItems.requalified`, an unstamped stack following its item through a reload, a stamp saved under `QualityOverride`), and the unreadable-stack case now fails the metadata read, since Update 7's encoder reads every field directly. `PendingRewardStoreTest.everyWriteCarriesTheVersion` is tagged `engine-items`: Update 7's `FileUtil` logs at class init, which only the engine's log manager allows; a new untagged test pins that a write the engine cannot make never reaches the caller.
