A draft, and an open one: 2.0.1 is expected to collect more than this before it ships. What is in it so far is an NPC placement pass - an NPC nothing placed can still answer press F, the owner file can hold whole placements, and the engine has an admin surface of its own for the first time - a new primitive for sharing a key with a weapon, and enhanced gear that works on a bare server.

- **Fixed: an NPC nothing placed still answers press F.** The stamp binding an NPC to its placement is attached only by the placement sweep, so one spawned by a command, an egg, a prefab or another mod carried none: `ZigPlacementInteract` rendered its prompt and then did nothing, with the only trace a fine-level log line. A base role can now author its own `Dialogue` or `Open` on that action, used when there is no placement to read. It is a FALLBACK, never an override, so a placement standing the NPC still decides and one shared role can be re-pointed per standing. `Dialogue` is computable, so a native `Variant` binds it per character; `Open` is read as the authored value and decoded at first press-F rather than at role load.
- **Where governs placement, and only placement.** An NPC standing in a world the placement does not target, by whatever route it got there, answers normally. This is what the interact path always did; the schema documentation and the shipped comments now say so.
- **New: `mods/ziggfreedcommon/npc-placements.json` carries whole placements.** An entry may now hold the same fields a pack authors beside the `enabled` switch, decoded against whatever the packs already say about that id, so writing one leaf changes that leaf and keeps the rest. The file stays schema 1 and every existing file reads unchanged: the switch is the lower-case `enabled` leaf and an asset's own fields all start upper-case, so the two can never be confused. Only an entry naming one id may carry a body; settings under a wildcard key are skipped and named.
- **New: `/zignpc place`.** Writes a placement where the caller is standing, in their world, facing their way, then re-reads and sweeps so the NPC appears immediately. It refuses a role the server cannot spawn - an unknown one, or an abstract template other roles are built on - rather than writing a placement that could never appear, and refuses an id already in use rather than replacing somebody. A consumer aliasing the verb calls the same `NpcPlacementAuthoring` path, so the two cannot drift.
- **New: an NPC placement admin page.** Every placement targeting the world the admin is in, with the state the sweep would act on and a switch each; a denied placement is painted as blocked rather than as off, since its gate and not the switch is what stops it. A filter and a Place button stand a new one where the admin is, offering only roles the server can spawn, the way the first-party entity tool's spawn page lists what it may spawn. Opened only through `NpcPlacementAdminPages.open`, never as a registered destination, and its audience seam defaults to DENY: the page writes, and the library cannot know what an admin is on a given server.
- **Fixed: an NPC standing somewhere nobody walks now actually gets placed.** A placement's spot has to be loaded before the NPC can be put there, and some spots never are: a world spawn point every returning player skips, an anchor off any route through the world. The NPC simply never appeared, and the server log filled with the engine trying again. The world now loads the spot it needs, stands the NPC there, and lets the chunk go back to sleep on its own afterwards, exactly as if a player had walked past.
- **Fixed: the placement log is quiet again.** Walking through a world kicked a fresh round of retries for every structure marker it sighted, so one placement that could not be resolved turned into dozens of overlapping retry rounds, each re-scanning the world and each ending in the same warning. One field log carried 127 of them in a minute. There is one round per world now, it is shorter, and the line saying a world has given up is printed once. A later sighting, an arriving chunk or a manual reconcile still gets a fresh look, just without the burst.
- **Fixed: two startup lines that were not problems.** A `Where` aimed at an instance world reported a warning on every boot for being aimed at something that is not running, which is what content aimed at an instance always looks like; it is a note now, while a world named by a pattern that matches nothing keeps its warning, since that is usually a typo. And registering a generated language pack warned on the very first boot for tidying up a registration that did not exist yet.

- **New: a way to ask whether a native interaction can actually do anything right now.** A mod that puts its own interaction on a key a weapon already uses has to decide which of the two a press belongs to, and the honest answer depends on the weapon: a signature move with an empty energy bar has no claim on the key, and a reload has none with a full magazine. `NativeInputGate` reads that off the weapon's own opening conditions without running it, so a mod can route the press instead of swallowing it. It reports two separate things - whether the conditions pass, and whether the chain spends a resource at all - because a chain that costs nothing is as ready on the thousandth press as the first and so never means a move is waiting. Anything it cannot read reports as not ready, which is safe for the intended pairing: run the weapon's own chain anyway when your alternative declines, and it re-checks the same conditions itself.

- **New: rolling stats onto an item a player already owns works with no other mod installed.** The library rolled and budgeted the stats but left the writing to whoever registered a writer, so a server running it alone stamped items nothing could read or apply. It now owns the whole path: the write, the tooltip, and turning a stamped stat into a real one when the item is worn or held. A consumer supplies vocabulary and nothing else.
- **A mod that adds a stat does not have to register a name for it.** The client already names every stat it can show, and that is the first place a stamped line looks. A stat the game defines reads correctly with nothing authored, and so does a mod's own stat as soon as it ships the label it needs anyway for the ordinary tooltip.
- **New: `Server/ZiggfreedCommon/StatDisplays/<StatId>.json` renames or recolours one stat.** `Key` is the translation key naming it, handed the points as a `{value}` argument; `Color` is a hex colour. Both optional and independent. An authored file outranks whatever a mod decided in code, so a server owner or a pack can correct any stat's wording without waiting on whoever invented it.
- **New: `Durability` is a stat id a pool can roll.** It raises the item's maximum durability instead of storing a stat entry, because durability belongs to the item rather than being a stat channel. The roll engine treats it as an ordinary entry throughout: it takes a pick, it costs budget, and a per-stat ceiling holds it.
- **New: a pool or a stamp can say what the item becomes.** `StampName` is a translation key handed the item's own name, so one key reads correctly on anything it lands on. `Quality` names an item quality asset, which is the game's own per-instance rarity channel, so the client colours the name, the tooltip frame and the slot for it natively. Both are authored or absent: nothing is renamed or re-tinted unless a file asks, and there is no built-in tier vocabulary.

- **New: a listed step is drawn with a picture, not just a sentence.** Every surface that lists quest or achievement steps now shows one: the item a step names drawn as itself, a creature as the still the client already renders of it, a wallet or a board as its own icon, another quest as the picture it is listed under everywhere else. It is decided in one place, so a step cannot be pictured one way on a giver's screen and another in the objective book, and a step nothing can picture reads as its text alone rather than borrowing an unrelated thing's art. An item is only ever drawn when the server really ships one under that id.
- **New: an objective KIND is a file.** `Server/ZiggfreedCommon/ObjectiveKinds/<Id>.json` is the one place a kind is described: `ValueBased` and `Producible` (what it counts and whether content may use it), `TargetNames` (whether its target is a place, an item, a creature, a wallet, a board, or another piece of content), and `Presentation` (`TextKey`, `Icon`, and `TargetIcons` for the individual targets that need a picture of their own). The filename is the id content writes as its `Kind`.
- **A kind file MERGES over the code that registered it, leaf by leaf.** A file usually means to state one fact, so a leaf it does not mention is not an instruction: writing a picture keeps the arithmetic the mod that invented the kind registered, and turning a kind off keeps its picture. A file naming an id nothing registered adds that kind outright, which is how a server describes a step kind its own producer already fires. The library ships a file for each of its 23 built-in kinds.
- **New: `icon.IconSpec` and `ui.icon.IconRenderer`, the one picture reference and the one seam that paints it.** A picture is either an item id, drawn as that item's own generated icon, or a Common-rooted texture path; the item wins when both are set, decided once at the seam rather than per caller. Any row wanting a picture declares an `ItemIcon #IcoItem` and an `AssetImage #IcoTex` and hands the spec to the renderer.
- **New: `icon.Portraits`, where the client keeps its still of each creature.** A live 3D preview is not something a server can drive, but every creature the game ships has a pre-rendered portrait under one well-known path, and pointing an `AssetImage` at it is. The path and the shared fallback texture live here once, so a mob inspector and a quest step showing the same creature cannot disagree.
- **New: `inventory.ItemIds.exists`, the honest question about an item id.** `ItemStack#getItem()` never answers null - it falls back to the unknown item - so `isValid()` is true for every id that was ever spelled, and anything that probed it and then drew the id painted the unknown-item picture at a player. The asset map's own answer is asked here once, and it is safe before assets load.
