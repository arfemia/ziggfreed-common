# zc-commerce (currencies, prices, rotation, shops, boards)

- The engine packages (`currency/`, `cost/`, `rotation/`, `shop/`, `board/`) hold runtime values only: no codec, asset store or file. The authoring half (`commerce/asset/`, `currency/asset/`, `shop/asset/`, `board/asset/`) holds the codecs, stores, folds and validators and imports nothing from the engine. Only `commerce/fold/` sees both.
- A price has two forms: an authored `commerce.asset.CostAsset` folds into the charged `cost.Cost`. Never add a codec to a runtime value or a second parser beside the store.
- A payout is one `RewardGrants.grantAll` and the room probe one `LootRewardKinds.canAddAll`, with no grant loop or reward-kind switch here. The retry queue is the `CommerceEngines.installRetryQueue` seam, and a payout capability zc-loot lacks is added to zc-loot.
- Every gate is a `progress.gate.GateSpec` answered by the shared `GateEvaluator`, its refusal passed through; there is no commerce-local requirement model. `CommerceDefaults.install` lists every locked offer and gated board slot in `progress.gate.GatedContent` (`CommerceGatedContent`), so a reader of a requirement (the Reputation page's ranks) can say what it opens.
- Engines read no clock: a time-dependent entry point takes `nowMs`, and one day number derived from it serves the whole transaction, so a purchase spanning midnight checks and records against the same day.
- A refusal is a token (`limit:daily`, `cost:currency:<id>`), never player text; the consumer maps it to words.
- Probe before draining (the reroll and fit probes), refund the receipt rather than the price (an `Any` price charges one component), and a purchase that delivered nothing refunds and does not count.
- Commerce never imports zc-dialogue: a conversation opens a shop or a board through the `ui/route/Destinations` registry.
- A storefront's or a board's `Where` is enforced against the viewing player's current world, never validator-only: every player-facing list, unnamed default and open asks `isAvailableIn(WhereAxis.viewer(...))` (`listedIn`, `firstListedIdIn`, `boardsIn`, `firstShopId(viewer)`, both pages). The viewer-less forms (`listed()`, `firstListedId()`, `boards()`, `firstShopId()`) ignore `Where` and serve only the admin verbs and server-wide questions; a surface with a player in hand never reads them.
- Writes into the commerce state store are absolute, so an import that runs twice leaves the same state, and a one-time migration is claimed (`claimMigration`), never checked and then run.
- `ziggfreedcommon.commerce.lang` holds page chrome only; shop, category, grade, offer and contract names are content keys in the authoring mod's namespace. The `/zigcommerce` wording lives in `ziggfreedcommon.commerce.admin.lang`.
