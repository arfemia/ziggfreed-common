# objectives/calendar/ - what a calendar event's start and end do to the rest of the library

- A start or an end, and a condition's rise or lapse, forces a placement sweep of every live world (`CalendarPlacementSweep`), because a placement's `Requires` is read only when a sweep runs and the reconciler latches a world after its first. Every path that changes whether a run is going (its dates, `/zigcalendar force`, an owner switch read by `/zigcalendar reload` or a pack reload, the boot's resumed start) reaches `CalendarEventStartedEvent` or `CalendarEventEndedEvent`; a Moon or Live event has no run and fires neither, so its rise and lapse reach the sweep through the tick's look (`CalendarPlacementSweep.onTick`, a `CalendarTicker.listen` listener, the boot's look included). Listen there, never to a command.
- A placement that exists only while an event is live (a run or a condition) authors `Season: <Id>` (zc-core `SeasonGate`, read by `PlacementGates` on every sweep); a hand-written `ziggfreedcommon:feature` `<Id>_Live` condition reads the same switch. A switch on an event that is not running changes `<Id>` and fires no event, so a placement gated on `<Id>` alone changes only at the world's next ordinary sweep.
- A forced sweep despawns only what is resident: give such a placement `Lifecycle.KeepAlive`, or one whose chunk sleeps through the end stands in its saved chunk until that world is swept again.
- Every look of the calendar's tick that began or ended something, a run or a condition (`CalendarTick.changed`), re-syncs the boost tiles (`CalendarBoostTiles`, a `CalendarTicker.listen` listener, since a Moon or Live event's rise and lapse fire no native event); zc-track's `Boosts.onCalendarChange` decides whether any timed boost reads a changed event, so a quiet look costs one check.
- The events arrive on the calendar's tick thread or the boot thread, never a world thread: `NpcPlacementReconciler.forceSweep` only queues onto each world's own thread, so never call `sweep` from here.
