# objectives/bonus/ - the library's bonus rows on the produced moments

- `BonusRowReactions` is a `MomentListener` registered at library-default rank (`BonusRowBootstrap`). It reads only `loot/trigger/BonusRowConfig`, never a consumer's table, and decides with no world handle first (`rowFor`: the kind, the producer's own payload, a covering row that is not a hole).
- It pays through the moment's own quest subject, so a consumer's notification preferences reach a cue toast; a `PlayerRefSubjectHandle` subject stands in when the runtime built none.
- Its kill and break passes layer a `ChestSite` (`BonusMoment.libraryCarries`) and stand the first `Reward_Chest` file it collected through zc-instance's `SpoilsChests.stand`, at the corpse or the block, for the credited player alone, under a fresh `chest:<uuid>` key.
- `DropCredit` tells zc-loot's `drops/DropContext` who a native drop list rolls for, and does nothing until a ZigLootable decodes (`DropContext.live`): a produced break at once, for the one roll of the block's lists the engine makes right after its break event (`ZigBlockBreakProducer` says nobody first for every break it sees, so an uncredited break never inherits an earlier credit; a tool that only changes a block's state fires no break, so its list rolls for nobody), a produced kill kept per victim until `DropCredit.Stamp`, after `DeathSystems.TickCorpseRemoval` (so it reads the corpse timer the pass reads) and just before the engine's `NPCDamageSystems.DropDeathItems`, names each NPC that pass may drop with its drop list and its credit, in stamp order (a death answers only a roll of its own list, the first ask after the engine marks it); `DropCredit.Close`, just after, clears the tick. It never asks a kill's attribution again: the moment's credited player is the answer.
- A break a gather shape makes for the player rolls only where `world/gather/ShapedBreaks.rowsAllowed` says the shape lets it (its `Rows` block), so a vein or a felled tree pays the library's rows once; `DropCredit` reads the same answer and credits such a break to nobody, so a ZigLootable's player-only rows in a block's drop list pay once too, on the block in hand (R879).
- A break's and a hand harvest's row adds the player's gathering yield (zc-world's `GatherYields`) to the `Chance` it writes, and a kill's row the killer's kill yield (`KillYields`, the `KillYield` stat, R916); `DropCredit` carries a break's gathering yield and a kill's kill yield onto each written roll `Chance` of a `ZigLootable` (`DropContext.Who.chanceBonus`).
- A row reads the loot vocabulary the rolling kinds read (`LootRewardKinds.installedFactors()`), and its context carries the player, a kill's victim (`target`) and a harvest's stack (`item`). No consumer payload rides it, so a consumer factor that needs one answers nothing in a library row.
