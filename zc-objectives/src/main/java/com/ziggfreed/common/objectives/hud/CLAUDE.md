# objectives/hud/ - the tracked-quest HUD

- `TrackedQuestHud` repaints on the quest engine's six events through zc-presentation's `RepaintCoalescer`, never a tick; a burst paints once, on the player's world thread.
- Its attach rides `PlayerReadyEvent` at LATE priority and is not behind `usesDefaultStores()`: it reads the runtime's own subject, so it shows the right list whoever owns the stores.
- That event fires once for every world a player enters, so the tracker is rebuilt per world; `configuredPosition()` steps a top-right tracker below the game's Portal panel there (zc-presentation's `ui/hud/PortalPanel`), which is what clears it in a portal world and puts it back on leaving.
- A player's own Show and spot pick are zc-presentation's `PlayerSettings` (surface `Quest_Tracker`): the player's Show, under their hide-all switch (`PlayerSettings.visible`), is asked before the consumer's `HudAudience`, which can only narrow it, and a pick is folded over the server's position by `TrackedQuestSpot` (only a spot whose `Panels` names `Quest_Tracker` is offered; any other pick falls back to the server's position). The owner's switch and the server's position are the player-settings record's `QuestTracker.Enabled` and `.Position` (`TrackerRules`, the deps' default seams), written by the HUD layout page; a consumer keeps no copy of them. A settings change re-anchors that player's tracker through the `PlayerSettings` watcher, and every read of `player-settings.json` re-anchors everyone's; the consumer still pushes `TrackedQuestHuds.repaint(playerRef)` for a world rule.
- A quest the panel is drawing draws none of its toasts in the corner: `TrackedQuestFeedback` decorates the library's feedback hook (`runtime/ProgressionBootstrap`) and adds `FeedbackEngine.ON_SCREEN_ARG` to the four quest moments from `TrackedQuestHuds.drawing`, the last paint (the quest engine's own event only queues the next one), and the engine honours it at every level for a toast marked `PlayerLevel`. Drawn into an open page (a menu covers the tracker) such a toast still shows, graded by the level. For a toast an owner unmarked, the older rule still holds: an ordinary `Quest_Objective_Progressed` tick sends nothing to the corner feed (`TrackedQuestHuds.alreadyShows`, a `FeedbackSurfaces.Reader`) and the tick that finishes a step still announces, unless the moment's file draws no toast for it (the shipped `Quest_Objective_Progressed` draws none for a `TURN_IN` step's finish).
