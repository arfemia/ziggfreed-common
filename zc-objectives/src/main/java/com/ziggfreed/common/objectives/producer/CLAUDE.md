# objectives/producer/ - the always-on native-event producers

- `ProgressDispatch.fire` hands every moment to all `MomentListener`s before the subject test and the system gates, so a player with no subject and a server with both systems off still get every reaction. The alias route (`fire(..., DispatchOptions)`) reaches the engines only, never the listeners, or a reaction would pay twice.
- There is deliberately no "is anything listening" short-circuit before the engines: the observer tap and the listeners must see moments no content wants (a lifetime counter counts every break).
- The 6-argument `fire` is the stable entry point for a net-new moment. The producers use the payload overload, and `MomentPayload` is an open marker a fourth party implements on equal terms.
- `ZigMobKillProducer` asks the composed `KillAttribution` (for a non-player attacker) and `KillQualifier` once, at fire time; the first real answer wins. There is no second qualified re-fire: an unqualified criterion already matches every kill, so a re-fire would count one kill twice.
- `ZigBlockBreakProducer` declares itself `AFTER` zc-entity's `UseGateBreakSystem`, so a break a use gate refused (cancelled) never produces a moment; keep that dependency.
- The break and pickup producers skip what the player placed (`world/placed/PlacedBlockLedger`). The place producer counts through `PlacedBlockRecorder.placementCounts`, because `PlaceBlockEvent` fires before the engine refuses a placement.
- `STAT_THRESHOLD` has no producer and never will: it names a state the engines read themselves.
- The craft producer's query stays unfiltered (`Archetype.empty()`) and targets the crafted output item's id. A workstation craft does not count, because `CraftRecipeEvent.Post` names no crafter: fix it the day the engine exposes one, never by reflection.
- The bus producers (`ZigInstanceRoundProducer`, `ZigEncounterProducer`, `ZigCalendarProducer`, `ZigLootReceivedProducer`, `ZigQuestCompletionProducer`, `ZigReputationProducer`, `ZigGearSetProducer`) resolve each player's own world and hop there through `PlayerMomentDispatch`.
- `ZigQuestCompletionProducer` owns `COMPLETE_QUEST`: one moment per `QuestClaimedEvent` (the collect, never the completion, which also fires for a parked quest), qualified by a registered `QuestCompletionQualifier` or else the quest's `QuestCadence.qualifier()`. A consumer never dispatches the kind itself; it registers a qualifier answer instead.
- `ZigLootReceivedProducer`, `ZigReputationProducer` and `ZigGearSetProducer` dispatch through `PlayerMomentDispatch.fireDeferred`, never inline: `LootReceivedEvent` and a rank check can fire from inside an engine payout, and a gear-set flip from inside the equip bridge's recompute, and an inline dispatch would re-enter the engine mid-way.
- `ZigGearSetProducer` owns `GEAR_SET_TIER` (its kind file ships with the gear-set engine in zc-entity): one moment per tier that came on, Target the set id, Amount the tier's size (`ZigGearSetTierChangedEvent.tierSize`), value-based so a step keeps the largest tier; a tier going off and a hydrate credit nothing.
- `ZigTrackProducer` owns `TRACK_LEVEL` and `TRACK_TIER` (their kind files ship with zc-track, `TrackObjectives` is the contract): off `ZigTrackChangedEvent` when the best level rises, and again for every usable track at each ready, through `fireDeferred` (a change can land inside a Track reward's payout); only the default climb counts. Both kinds are value-based because they are restated: never fire an accumulating amount there. A `TRACK_TIER` goes out at 1 per tier reached (Target the tier) plus once on a blank Target with the count reached, which only a step naming no tier reads.
- `ZigDamageProducer` owns zc's `DEAL_DAMAGE`, a creature hit a player is credited with (as a kill is), Target the creature, Qualifier the attacker's held item, the amount capped at the health its Filter-group half noted on the damage (`DamagePayload.dealt`, exact). It goes through `ProgressDispatch.fire`, the listeners then both engines, so a hit counts once for a track source, a stat file, a quest and an achievement alike; a consumer never dispatches the kind itself, or each hit counts twice. A consumer whose combat leaves targets out (a dummy, a passive animal) registers a `DamageHitFilters` filter, asked on a `DamageHit` before the moment exists; with none, every credited hit counts.
- `ZigHealProducer` owns `HEAL_GIVEN` (its kind file ships with the heal in zc-core), off zc-core's `ZigHealGivenEvent`: a heal a player gives themselves (Target `Self`) or an allied player (`Player`), Qualifier the heal's source, credited only what `RecentHostileDamage.draw` gives (the health restored out of the healed player's recent creature damage, held to what they are missing), through `fireDeferred` since a heal fires inside whatever healed. A track source pays the exact credit off `HealPayload`; the moment's amount, what quests and achievements count, is its whole points, the healer's fraction carried to their next heal (`wholeOf`, dropped at death and disconnect), never a rounding per heal. A heal on anyone else, or crediting nothing, fires nothing. A consumer never dispatches the kind itself.
- `ZigTalkProducer` owns `TALK_TO_NPC`: it is the library's `TalkCredits` sink, firing the primary id through the full dispatch with a `TalkPayload` and each further answered id through `TARGETED_ONLY`, each alias behind its own `TalkCredits.claim`. A consumer reacts to the moment through a `MomentListener` and never registers a sink that dispatches the kind itself, or every conversation counts twice.
