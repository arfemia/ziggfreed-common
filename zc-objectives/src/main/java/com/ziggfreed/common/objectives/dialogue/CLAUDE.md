# objectives/dialogue/ - what the library adds to the dialogue engine from above it

- `DialogueBootstrap` fills the seams zc-dialogue declares and cannot fill itself (the factor slot, the default quest slot, the persistent memory store, the active-objective header) and registers the vocabulary it cannot host (`Grant`, `Requires` with its deprecated `Gate` spelling, `HasActiveBounties`), because this module sees zc-dialogue, the reward vocabulary, the payout core, the runtime's subject and the boards together. It holds registration only (`RootRegistrationOnlyTest`).
- `Requires` (`RequiresDialogueCondition`) reads its block only through `gate/RequiresCheck` for the runtime's subject; `Gate` (`Requirements`) is its own class over the same evaluator, kept so old files load, and `DialogueAudit` reports each use (`GATE_CONDITION_DEPRECATED`). `HasActiveBounties` asks the boards the way a board surface does (the runtime's subject, `boardsIn` the viewer's world). Never a consumer copy of either.
- `Grant` (`GrantDialogueAction`) pays the quest `Rewards` entry shape through `objectives/interaction/InteractionRewards`; never a second payout path. It pays every time its line runs: the line's own `Once` (or a `Once` with a `Period`) is the guard, and it is kept per file for a line one file puts into many conversations, so `Grant` keeps no once-key of its own.
- Never register `Reward`, the Type or the shorthand: a consumer may own both, and this library registers first, so it would read that consumer's files into this library's action.
- `RuntimeDialogueQuests` (the default quest slot) gives only answers another surface already gives: the engine's reads, the runtime's subject, the giver list's answer set (`NpcQuestPages.resolvedDeps().answerSetOrOwn`), `journal/QuestVerbs` for accept and hand-in, the book's `ActionFeedback` for the accept announcement (where no consumer filled it, the book's own `BookVerbs.acceptedToast` through `ToastDelivery.deliverWhenSettled`, never both), and the folded pool's completion conversation. A conversation hands in and never collects: a parked quest is collected from the character's list.
- `DialogueAudit` is the library's one conversation audit (the structural validator, `UNKNOWN_QUEST_ID` as a WARNING with the quest store's mod-gate refusals exempt, each `Requires` block through the shared `GateValidator` even on a line held shut, and the completion-conversation check), run once at the first `PlayerReady` (`runLateAudit`) or at `BootEvent` under zc-core's boot-audit switch (`claimLateFindings`). A consumer that reports it in its own content report calls `claimLateAudit` at setup and the pure `auditConversations` and `completionFindings` itself, passing the lines it holds shut; never a second copy of a check here.
- A payout is labelled `dialogue:<conversation id>`; the subject is the runtime's own (`InteractionRewards.subjectFor`), resolved only once there is something to pay, and a click with no player behind it pays nothing and reports nothing.
