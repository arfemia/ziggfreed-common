# objectives/dialogue/ - what the library adds to the dialogue engine from above it

- `DialogueBootstrap` fills the seams zc-dialogue declares and cannot fill itself (the factor slot, the default quest slot, the persistent memory store, the active-objective header) and registers the action it cannot host (`Grant`), because this module sees zc-dialogue, the reward vocabulary and the payout core together. It holds registration only (`RootRegistrationOnlyTest`).
- `Grant` (`GrantDialogueAction`) pays the quest `Rewards` entry shape through `objectives/interaction/InteractionRewards`; never a second payout path. It pays every time its line runs: the line's own `Once` (or a `Once` with a `Period`) is the guard, and it is kept per file for a line one file puts into many conversations, so `Grant` keeps no once-key of its own.
- Never register `Reward`, the Type or the shorthand: a consumer may own both, and this library registers first, so it would read that consumer's files into this library's action.
- `RuntimeDialogueQuests` (the default quest slot) gives only answers another surface already gives: the engine's reads, the runtime's subject, the giver list's answer set (`NpcQuestPages.resolvedDeps().answerSetOrOwn`), `journal/QuestVerbs` for accept and hand-in, the book's `ActionFeedback` for the accept announcement, and the folded pool's completion conversation. A conversation hands in and never collects: a parked quest is collected from the character's list.
- A payout is labelled `dialogue:<conversation id>`; the subject is the runtime's own (`InteractionRewards.subjectFor`), resolved only once there is something to pay, and a click with no player behind it pays nothing and reports nothing.
