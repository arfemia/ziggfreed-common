# objectives/questlist/ - the NPC quest page

- What a character lists combines four answers in `NpcQuestSections.belongsHere`, through `CharacterQuestListing` (which the quest indicators reuse): offers from `NpcOfferProviders`, `nextStepNamesPlace` (never `readyToTurnInAt`, which counts a hand-in that names no place as here everywhere, so a board contract would list on every character), `acceptSiteOf`, and `canCompleteAt` (asked only of a quest waiting to be collected, or every carried quest would list everywhere). "Given here" is engine data; a consumer registers nothing for it.
- The default offer provider walks the whole catalogue on every ask. Do not index offers by giver until the engine publishes a catalogue generation: a stale giver index is a character offering quests that are no longer theirs.
- A finished quest collected elsewhere reads as parked: ask `canCompleteAt` once per id the character answers to, and claim at the id that answered.
- Accept, hand-in and collect all thread the site id. Accept and hand-in are `journal/QuestVerbs` (`acceptAt`, `handInAt`), the verbs the book and the library's conversation binding press too; never a scope lambda of the page's own. A collect, or a hand-in or accept that finishes the quest, raises no toast of its own (the engine's notices, drawn into the page as they fire, are the one announcement, R877): it hands off (`deps.completion().handOff`) and repaints only when nothing took the screen.
- The page keeps instance state (the list, the selection, the open sections, the kit's `LedgerIndex`) and reopens as `this`, because a partial update runs against the last full build's DOM; an action repaints the whole list and page in one partial (`ZigNpcQuestPage.LIST_IN_PLACE` turns that into a reopen). What a quest reads like comes from `journal/QuestReader.page(quest, here)`, the book's own page with this character's buttons.
- The three action-bar buttons and the header's Track toggle are bound once per build with no quest id and dispatched on the live state through `journal/QuestActions` at this character; never put a quest id in their bindings.
- `NpcQuestPages.open` reads the player's own reference off `player`, never off `ref`: at a press-F, `ref` is the character's entity.
- A board is a host too: `CommercePages.openBoard` opens this page through `NpcQuestPages.openBoard` (`ZigNpcQuestPage.atBoard`), answering to the board's own id alone, and `BoardHost` adds what a board brings: its header (`#HostPic`, `#HostLine`, `#HostClock`, the wallets), its closed state where `!isAvailableIn`, a refused press where `!existsIn`, and Reroll in Secondary on an Available or Locked posting (the board's `canReroll` probe, `ConfirmArm` twice when paid, the reroll inside the progression call scope, `BoardEvents.fireRerolled`). Its listing is `CharacterQuestListing.atBoard`: a board's Here lists only its postings, what was taken there and contracts, never a finished quest merely collectable anywhere (`listsAsCollectableHere`), while `collectionSite`, and so Collect and the Mine tab, read as at a character; a character keeps `belongsHere` whole. A board speaks no closing conversation: its hand-off passes no character.
- A board's `Hosts` puts the board's id in its characters' answer sets (`HostedBoards.answerSet`, inside `NpcQuestPageDeps.answerSetOrOwn`, so the page, the overhead mark and the conversation agree; map marks read the identity set and see no postings). `CharacterQuestListing` lists each such board's postings (open in the viewer's world, deduped to the first board by `Order`) by the board's own rules (`postingOf`, `acceptCheck`, `doneThisRotation`), and a posting is taken only through `QuestVerbs.acceptPosting`. Only the page looks at a board (`HostedBoards.look`: the lapse re-arm and the rotation notice); a listing never does, since the mark asks one every sweep.
