# objectives/authoring/ - the quest editor

- `QuestWizard` is an `AuthoringWizard` on zc-presentation's frame (`authoring/`); `QuestEditorBootstrap` registers it with its tool (`AuthoringTools.wizardTool`), and every save goes through zc-core's `ServerContent` (the quest file, its words, a new giver's role), never a direct store write.
- `QuestDraft` is the one reader and writer of the quest file the editor saves, pure: it writes over the file it edits, so a leaf the editor has no row for survives, and it writes every reward as a `Claim` (M428). `QuestDraftTest` is the gate on that file's shape and its keys.
- A step's key is minted once (`QuestDraft.keyFor`, kept in the session with the kind it was saved as) and never renamed: progress is saved under it. A changed kind takes a new key in the old one's place; an emptied step leaves the file. Every key that leaves is retired in the file's own `Meta.ziggfreedcommon.RetiredSteps`, and no mint takes a retired key (`QuestDraft.taken`). A step with no `Kind` is no slot of the editor's and is kept as written.
- A save closes up an emptied reward's Claim row, so the wizard seeds its reward slots from the written file after each save: a slot always names the row at its place.
- A new giver is its own character type: `QuestGivers` writes a `Variant` of `Template_Zig_QuestGiver` naming only `NameTranslationKey` (`ServerContent.writeRole`, its words `npcs.<Id>.name`), then places it once the role and the quest have landed.
- A page's dynamic rows (a slot's heading, a reward kind's parameters) are labelled with `WizardField.withLabel`, their field id as the label key. The frame repaints a page only on Back, Next or a search, so a row that depends on another's value (a target on its step's kind, a parameter on its reward's kind) sits on the page after it.
