# objectives/authoring/ - the quest and achievement editors

- `QuestWizard` and `AchievementWizard` are `AuthoringWizard`s on zc-presentation's frame (`authoring/`); `QuestEditorBootstrap` and `AchievementEditorBootstrap` register each with its tool (`AuthoringTools.wizardTool`), and every save goes through zc-core's `ServerContent` (the files, their words, a new giver's role), never a direct store write.
- The editors share their parts: `KeyedRows` (a document's keyed objective rows: mint, keep, replace, retire), `ClaimSlots` (the Claim rows by slot), `DraftJson`, and on the wizard side `ObjectiveSlotPages` and `RewardSlotPages` (the kind, target and reward pages, read under the same key names from each editor's own lang file through `EditorWords`) and `Typed`. A change to one of these changes both editors.
- `QuestDraft` and `AchievementDraft` are the one reader and writer of the file each editor saves, pure: each writes over the file it edits, so a leaf the editor has no row for survives, and writes every reward as a `Claim` (M428). `QuestDraftTest` and `AchievementDraftTest` are the gates on those files' shapes and keys.
- A row's key is minted once (`KeyedRows.keyFor`, kept in the session with the kind it was saved as) and never renamed: progress is saved under it. A changed kind takes a new key in the old one's place; an emptied row leaves the file. Every key that leaves is retired in the file's own `Meta.ziggfreedcommon` (`RetiredSteps` for a quest, `RetiredCriteria` for an achievement), and no mint takes a retired key (`KeyedRows.taken`). A row with no `Kind` is no slot of the editor's and is kept as written.
- A save closes up an emptied reward's Claim row, so the wizard seeds its reward slots from the written file after each save: a slot always names the row at its place.
- A new giver is its own character type: `QuestGivers` writes a `Variant` of `Template_Zig_QuestGiver` naming only `NameTranslationKey` (`ServerContent.writeRole`, its words `npcs.<Id>.name`), then places it once the role and the quest have landed.
- The achievement editor opens the server content pack's achievements and the ones a pack ships; saving a shipped one writes a same-id copy into the server content pack, started from the shipped file, which the store serves over it (the pack loads last, and a live save lands last in the asset chain). A shipped file under a `_`-marked folder is refused, since the copy would take another id. A server copy offers "put the pack's version back" (`ServerContent.remove`).
- The achievement editor keeps the text keys a file already holds (`AchievementDraft.keptKey`): words the pack saved are rewritten under their key, shipped words left as they were keep the shipped key (and its translations), and only retyped or new words take a server key. It refuses a file with `Parent`, `Abstract`, `Occurrence`, `MetaChildren` or `MetaSelector`.
- An achievement's title is its one `Auto` row (R327); every other `Auto` row is kept as written, and the Claim reward kinds leave out the title kind. A new title's display line is saved under `title.<id lower case>.display` (`AchievementDraft.displayKey`), the only key `TitleText` reads it from; after a comma writes none, so the shared line applies. Save order is the words, a new category, a new title, then the achievement, so the title row never names a title that has not loaded.
- A page's dynamic rows (a slot's heading, a reward kind's parameters) are labelled with `WizardField.withLabel`, their field id as the label key. The frame repaints a page only on Back, Next or a search, so a row that depends on another's value (a target on its row's kind, a parameter on its reward's kind) sits on the page after it.
