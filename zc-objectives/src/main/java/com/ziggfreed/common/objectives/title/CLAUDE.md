# objectives/title/ - titles a player earns and shows

- A title is a `TitleAsset` (`Server/ZiggfreedCommon/Titles/<Id>.json`; the file name is the id, lower-cased): `Enabled` (false hides it everywhere without taking it from anybody), `Text`, `Order`, `Hidden` (true keeps it off "Not earned yet" and out of the count until earned, R166); owner file `mods/ziggfreedcommon/titles.json` through `TitleOwnerLayers`, whose file-level `$AutoShow` and `$Chat` are read on each reload into volatiles, never per use from the file. `TitleConfig.shown` is the one "is this title on offer" read, `listing` the one picker order (Order, then id), and `tally` the one read of a player against what is on offer (`TitleConfig.Tally`): the picker's lists and every "n of N" come from it.
- `ZigTitles` is the public facade: `grant`/`revoke` by player id from any thread (an online player by a hop to their world, after paying anything already queued; an offline one queued in zc-entity's `PendingTitles`, answered `Outcome.QUEUED`, then paid at once if they came online meanwhile), and the any-thread reads `earned` (off `ActiveTitles`), `nameOf` and `display`. `Outcome` grows only by appending.
- `TitleQueue` pays the queue at every player-ready on the world thread, one beat before `TitleBackfill` (`READY_PRIORITY`, `LATE - 1`), each change through `TitleUnlocks` on its own guard; a player with no title record keeps their queue.
- `TitleFactors` contributes `ziggfreedcommon:title_earned` and `title_shown` (Param a title id; 1 or 0 off `ActiveTitles`, `title_shown` 1 only for a title on offer, as players see it; both need a live subject on its world thread and answer null for a blank Param or none), each named by a `Factors/Title_*.json` overlay.
- Auto-show (R114, R214): `TitleUnlocks.write` activates a NEW unlock through `activateWrite` (so `ACTIVATED` fires) only while `$AutoShow` is on, the player shows nothing, `ChoseNone` is unset and the title is on offer; in a login's burst the first unlock shows.
- What a title is called, and where it sits around a player's name, is `TitleText` (its class javadoc holds the name ladder and the display line).
- Every write onto a player's titles goes through `TitleUnlocks` (unlock, revoke, activate, deactivate), on the world thread: only a real change refreshes `ActiveTitles` (shown title, earned set, username) and fires `ZigTitleChangedEvent`, and only a new unlock draws the `Title_Unlocked` moment.
- `TitleValidator` is the `title` content audit (a consumer folds `audit()`): a title's own file, and every `Title` reward in the achievement and quest catalogues, read only once `ProgressionRuntime.isBuilt()`; `auditForcingBuild()` builds the runtime first, for a caller past every plugin's `start()` (zc's boot audit). A reward naming a title no file defines is a WARNING, one the grant refuses an ERROR; a switched-off title is still a known one. `TitleRewardKind.isTitleReward` is the one "is this a Title reward" test, and `titlesIn` the one read of which titles a reward list gives.
- The `Title` reward kind and `/zigtitle grant` and `revoke` write through `TitleUnlocks`: an unknown id is granted with a warning (the pack naming it may load later), a blank or reserved id is refused and never replayed. The command family is `command/` (its router), the picker `page/` (its router). `TitleBootstrap` registers the command, the `Titles` destination, the factors, both ready handlers, the name-seam contribution and the chat listener.
- `TitleBackfill` runs at every player-ready (LATE, on the world thread, not behind `usesDefaultStores()`; its class javadoc says which rows it reads): every title an earned achievement or a collected quest owes is unlocked through `TitleUnlocks`, each on its own guard, so a save from before a title shipped gets it at the next login. A system switched off for the player is skipped, a read that throws costs only its own half, and a title an admin revoked comes back while its achievement or collected quest stands.
- Titles are one contribution to zc-presentation's `PlayerDisplayNames` (`TitleDisplay.contribution()`, owner `TitleDisplay.OWNER` at `ORDER` 100), which reads only `ActiveTitles` and `TitleConfig`, never an entity store; a title switched off, unknown or no longer theirs shows nothing, online or not (`TitleDisplayTest`).
- A title in chat is `TitleChat` (R55: behind `$Chat`, off by default, never the nameplate; its class javadoc is the reference): it sets its own formatter only over the engine's `PlayerChatEvent.DEFAULT_FORMATTER`, naming the sender through the whole display-name seam, and nothing it runs may throw into the engine, since a throw drops the line for everyone.
