# objectives/title/ - titles a player earns and shows

- A title is a `TitleAsset` (`Server/ZiggfreedCommon/Titles/<Id>.json`; the file name is the id, lower-cased): `Enabled` (false hides it everywhere without taking it from anybody), `Text`, `Order`, `Hidden` (true keeps it off "Not earned yet" and out of the count until earned, R166); owner file `mods/ziggfreedcommon/titles.json` through `TitleOwnerLayers`, whose file-level `$AutoShow` (true when absent, true with one warning when not a boolean, the `AlmanacOwnerLayers` pattern) is read on each reload. `TitleConfig.shown` is the one "is this title on offer" read, `listing` the one picker order (Order, then id), and `tally` the one read of a player against what is on offer (earned, still to earn and not hidden, hidden still to earn): the picker's lists and every "n of N" (earned of earned plus not-hidden still to earn) come from it.
- `ZigTitles` is the public facade: `grant`/`revoke` by player id from any thread (an online player by a hop to their world, after paying anything already queued; an offline one queued in zc-entity's `PendingTitles`, answered `Outcome.QUEUED`, then paid at once if they came online meanwhile), and the any-thread reads `earned`, `shown` (both off `ActiveTitles`), `onOffer`, `nameOf`, `display`, plus `openPicker`. `Outcome` grows only by appending.
- `TitleQueue` pays the queue at every player-ready on the world thread, one beat before `TitleBackfill` (`READY_PRIORITY`, `LATE - 1`), each change through `TitleUnlocks` on its own guard; a player with no title record keeps their queue.
- `TitleFactors` contributes `ziggfreedcommon:title_earned` and `title_shown` (Param a title id; 1 or 0 off `ActiveTitles`, `title_shown` 1 only for a title on offer, as players see it; both need a live subject on its world thread and answer null for a blank Param or none), each named by a `Factors/Title_*.json` overlay.
- Auto-show (R114, R214): `TitleUnlocks.write` activates a NEW unlock through `activateWrite` (so `ACTIVATED` fires) only while `$AutoShow` is on, the player shows nothing, `ChoseNone` is unset and the title is on offer; in a login's burst the first unlock shows.
- What a title is called is `TitleText`: `Text.TitleKey`, else `title.<id>.name` from any loaded lang file, else `Text.DisplayName`, else the id spelled out; `title.<id>.flavor` describes it, and `title.<id>.display` places it around a player's name (`{0}`), else the shared `display` line follows the name after a comma.
- Every write onto a player's titles goes through `TitleUnlocks` (unlock, revoke, activate, deactivate), on the world thread: only a real change refreshes `ActiveTitles` (shown title, earned set, username) and fires `ZigTitleChangedEvent`, and only a new unlock draws the `Title_Unlocked` moment.
- `TitleValidator` is the `title` content audit (a consumer folds `audit()`): a title's own file, and every `Title` reward in the achievement and quest catalogues, read only once `ProgressionRuntime.isBuilt()`; `auditForcingBuild()` builds the runtime first, for a caller past every plugin's `start()` (zc's boot audit). A reward naming a title no file defines is a WARNING, one the grant refuses an ERROR; a switched-off title is still a known one. `TitleRewardKind.isTitleReward` is the one "is this a Title reward" test, and `titlesIn` the one read of which titles a reward list gives.
- The `Title` reward kind and `/zigtitle grant|revoke|list` both write through `TitleUnlocks`: an unknown id is granted with a warning (the pack naming it may load later), a blank or reserved id is refused and never replayed. `--player` takes a player online or not (the shared walk's typed-name form; `command/TitlePlayers` resolves an exact online name, then the record's last username, then a UUID, then a partial online name, then the engine's profile lookup, which needs an authenticated server): an online one keeps today's path after its queue is paid on its world thread (`TitleTargetCommand.buildTarget`), an offline grant or revoke queues through `ZigTitles`, and an offline list reads the record. `TitleBootstrap` registers them, the `Titles` destination, the factors and both ready handlers, and is registration only.
- `TitleBackfill` runs at every player-ready (LATE, on the world thread, not behind `usesDefaultStores()`, over the runtime's own achievement subject): each earn-time `Title` row of an earned achievement, and each collect-time row of a collected one, is unlocked through `TitleUnlocks`, each on its own guard, so a save from before a title shipped gets it at the next login; a player the achievement switch is off for is skipped. A title an admin revoked comes back the same way while its achievement stands; revoke the achievement to take it for good.
- Titles fill zc-presentation's `PlayerDisplayNames` (`TitleDisplay`), which reads only `ActiveTitles` and `TitleConfig`, never an entity store: a menu on any world thread can name any player. An offline player's row shows the same title it would online (the record keeps their choice across a leave and a restart), so a title never tells a viewer who is online; a title switched off, unknown or no longer theirs shows nothing either way. `TitleDisplayTest` pins both; its restart tests read back a file `ActiveTitles` wrote through the engine's atomic writer, which loads on Update 7 only under the engine's log manager, so they alone are tagged `engine-items` (zc-entity's `entity/title/CLAUDE.md`).
- The picker opens only through `page/TitlePickerPages.open` (the `Titles` destination, `page/TitleDestinations`, registered by `TitleBootstrap`, opens it too, and `/zigtitle open`, a player verb in the adventurer group inside the admin family); what it lists is the pure plan `page/TitlePickerRows`: earned titles as tiles (`Pages/ZigTitleTile.ui`, on the Memories tile faces) under an "n of N" head, and the titles still to earn that are not hidden as kit lines, each naming the first visible achievement that grants it (`page/TitleSources`) and opening the book on it, or saying to collect it when a visible granter pays the title only on collect and is earned but not collected (`Source.collect`; such a granter wins over an earlier one). A hidden achievement is never named. With nothing earned and only hidden titles left, the empty state reads `picker.secret_only`; `none_on_server` is for a server with no title on offer. A consumer themes it through `TitlePickerPages.deps`; Back returns to the Settings tab unless the consumer says otherwise, and an open given a Back destination (`open(..., back)`, `TitleDestinations.titles(back)`, a Java-only field no file can author) goes there instead. The Settings tab's Title tile shows while any title is on offer (a hidden one counts), reads the record's earned set for its count and opens the picker with Back to Settings. zc-presentation's `UiDocumentSyntaxTest` reads its documents with every other zc module's, and `TitlePickerDocumentTest` holds every id the page addresses.
