# objectives/title/ - titles a player earns and shows

- A title is a `TitleAsset` (`Server/ZiggfreedCommon/Titles/<Id>.json`; the file name is the id, lower-cased): `Enabled` (false hides it everywhere without taking it from anybody), `Text`, `Order`; owner file `mods/ziggfreedcommon/titles.json` through `TitleOwnerLayers`. `TitleConfig.shown` is the one "is this title on offer" read and `listing` the one picker order (Order, then id).
- What a title is called is `TitleText`: `Text.TitleKey`, else `title.<id>.name` from any loaded lang file, else `Text.DisplayName`, else the id spelled out; `title.<id>.flavor` describes it, and `title.<id>.display` places it around a player's name (`{0}`), else the shared `display` line follows the name after a comma.
- Every write onto a player's titles goes through `TitleUnlocks` (unlock, revoke, activate, deactivate), on the world thread: only a real change refreshes `ActiveTitles` and fires `ZigTitleChangedEvent`, and only a new unlock draws the `Title_Unlocked` moment.
- `TitleValidator` is the `title` content audit (a consumer folds `audit()`): a title's own file, and every `Title` reward in the achievement and quest catalogues, read only once `ProgressionRuntime.isBuilt()`. A reward naming a title no file defines is a WARNING, one the grant refuses an ERROR; a switched-off title is still a known one. `TitleRewardKind.isTitleReward` is the one "is this a Title reward" test.
- The `Title` reward kind and `/zigtitle grant|revoke|list` both write through `TitleUnlocks`: an unknown id is granted with a warning (the pack naming it may load later), a blank or reserved id is refused and never replayed. `TitleBootstrap` registers them and is registration only.
- Titles fill zc-presentation's `PlayerDisplayNames` (`TitleDisplay`), which reads only `ActiveTitles` and `TitleConfig`, never an entity store: a menu on any world thread can name any player. An offline player's row shows the same title it would online (the record keeps their choice across a leave and a restart), so a title never tells a viewer who is online; a title switched off, unknown or no longer theirs shows nothing either way. `TitleDisplayTest` pins both; its restart tests read back a file `ActiveTitles` wrote through the engine's atomic writer, which loads on Update 7 only under the engine's log manager, so they alone are tagged `engine-items` (zc-entity's `entity/title/CLAUDE.md`).
- The picker opens only through `page/TitlePickerPages.open` (and `/zigtitle open`, a player verb in the adventurer group inside the admin family); what it lists is the pure plan `page/TitlePickerRows`: earned titles as tiles (`Pages/ZigTitleTile.ui`, on the Memories tile faces), and the titles still to earn as kit lines, each naming the first visible achievement that grants it (`page/TitleSources`) and opening the book on it. A hidden achievement is never named. A consumer themes it through `TitlePickerPages.deps`; Back returns to the Settings tab unless the consumer says otherwise. zc-presentation's `UiDocumentSyntaxTest` reads its documents with every other zc module's, and `TitlePickerDocumentTest` holds every id the page addresses.
