# Track Schema Reference

Generated by `gradlew :zc-track:generateSchemaDocs` from the live asset codecs (`TrackSchemaDocs`, through zc-progression's `SchemaDocWriter`). Do not hand-edit; regenerate it after changing a track, curve or category codec.

One track is one file under `Server/ZiggfreedCommon/Tracks/` (subfolders are the author's own grouping), one curve one file under `Server/ZiggfreedCommon/TrackCurves/`, one category one file under `Server/ZiggfreedCommon/TrackCategories/`, and in each the FILE NAME is the id; a track id may not contain `@`. A file may carry `"Parent": "<id>"` to start from another one, every leaf inheriting on omission. The server owner retunes a track in `mods/ziggfreedcommon/tracks.json`. A `ZigTrack` reward is a native reward file under `Server/Rewards/`, which an encounter script's `GrantReward` pays as a Claim.

Every field is optional and defaults to `null` unless its Default column reads *(required)*.

| `Curve` | `string` | `null` | The curve that turns this track's value into levels, by id (a file under Server/ZiggfreedCommon/TrackCurves); tracks share one. Skill_Hybrid ships with the library. A track whose curve is not loaded answers nothing. |

| `Points` | [Points](#field-trackasset-points) | `null` | Points a player earns to spend on this track's picks as it levels. Leave it out for a track whose picks cost no points. |
| `Mirror` | [Mirror](#field-trackasset-mirror) | `null` | A native stat this track's level is written onto, so anything reading stats (an item, an effect, a hytale:stat requirement) sees it. Leave it out for no stat. |
| `Prestige` | [Prestige](#field-trackasset-prestige) | `null` | Whether a player may prestige this track: start the climb again from the bottom, keeping the best level they ever reached, so nothing they unlocked locks again and no unlock pays twice. Leave it out for a track that never prestiges. |
| `Unlocks` | array of [Unlock](#field-trackasset-unlocks-item) | `null` | Rewards for reaching levels: each row pays its Rewards as a Claim the player collects, once for each of its levels the best level ever reached passes, and never twice, whatever a prestige does. A row added later pays what is already behind the player. A player's record knows each row by its Id (or, unauthored, by its levels), never by its place, so the rows can be reordered freely. ### TrackAsset.Unlocks[]

| Key | Type | Default | Documentation |
|---|---|---|---|
| `Id` | `string` | `null` | What this row is known by in a player's record and in the ids of its Claims (letters, digits, _ and -; anything else reads as _, and case does not matter). Rows can then be added, removed or reordered on a live track and none pays twice or is skipped. Unauthored, the row is known by its own levels (At [2, 5] is at_2_5, Every 4 is every_4, both together at_2_5_every_4), so changing those levels on a live track makes it a new row that pays again: give it an Id before you do. | `Beyond` | [Beyond](#field-trackcurveasset-beyond) | `null` | What lies past the last piece's top level: each Every more value is one more level, without end (a track's Cap stops it). Leave it out and the last level is the top. |
| `Tiers` | map of [Tier](#field-trackcurveasset-tiers-item) | `null` | Names for ranges of levels, by tier id: each tier holds from its From level to the next tier's. A requirement can ask for a tier (ziggfreedcommon:track_tier) and a quest step can count reaching one (TRACK_TIER). Under Parent this merges by tier id. |

## RewardEntry

| Key | Type | Default | Documentation |
|---|---|---|---|
| `Kind` | `string` | `null` | Which registered reward kind pays this out, by id: Item, Lootable, Stamped_Item, Effect, Droplist, Command and Flair come with the framework, and a kind a mod brings carries that mod's prefix (Yourmod_Coin). A kind nothing registered is reported rather than silently skipped, so an owner can see which mod was expected to provide it; a row that only some servers can pay names its mod in Requires instead. |
| `Params` | map of `scalarString` | `null` | The kind's own parameters. Which keys matter is documented by whoever registered the kind; nothing here interprets them. A number or true/false may be written bare (Amount: 50), a value with any other shape takes quotes. |
| `Requires` | [Requires](#type-requires) | `null` | What a player must meet for this reward row to pay, in the Requires shape quests use, every condition read. A plain { "Factor": "hytale:mod_installed", "Param": "Group:Name", "Min": 1 } leaves the row out where that mod is not installed (it pays nothing, shows nowhere and is not reported); the rest is asked of the player when the row pays, and a row they do not meet pays them nothing while the rest of the list pays as written. |

<a id="type-requires"></a>
## Requires

| Key | Type | Default | Documentation |
|---|---|---|---|
| `Factors` | array of [FactorCondition](#type-factorcondition) | `null` | Numeric bounds on the shared factor vocabulary; all of them must pass. A factor no installed mod can answer fails closed, so the content stays locked. |
| `Permission` | `string` | `null` | A permission node the player must hold, read through the engine's own permission check. It is the short spelling of a hytale:permission factor bound, so both give one answer; where nobody can be asked, it refuses and the content stays locked. |
| `Quests` | array of `string` | `null` | Quest ids the player must have finished AND collected the reward for (stored status COMPLETED); a quest sitting finished-but-unclaimed, which is where a quest with Claim rewards waits, does not satisfy it. Use it to chain a story in order instead of hiding every later step behind a separate flag. |
| `Custom` | map of map of `scalarString` | `null` | Requirement kinds registered by other mods, keyed by their namespaced id, each with that kind's own parameters. A kind nothing registered refuses. A parameter that is a number or true/false may be written bare; other values take quotes. |
| `AllOf` | array of [GateClause](#type-gateclause) | `null` | Extra groups that must ALL pass, on top of the leaves above. Use it to keep unrelated requirements readable side by side. |
| `AnyOf` | array of [GateClause](#type-gateclause) | `null` | Groups of which at least ONE must pass - the way to say 'either route into this will do'. An empty list asks for nothing. |
| `Not` | array of [GateClause](#type-gateclause) | `null` | Groups that must NOT pass - the way to say 'only while this is not yet true'. Each entry is one group that has to fail, so listing two things in one group means 'not both', and two separate groups mean 'neither'. |
