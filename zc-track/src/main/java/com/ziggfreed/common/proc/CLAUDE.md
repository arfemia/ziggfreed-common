# proc/ - procs, counters and held effects (a package of zc-track)

- A knack is data, never a stat of its own (R758): a proc file (`ProcAsset`, `Server/ZiggfreedCommon/Procs/`) opens on its `Requires` (a talent's `ziggfreedcommon:track_pick`, its rank read in the numbers' formulas), answers one `ProcTrigger`, and runs `ProcAction` groups. Its numbers are `FactorFormula`s; the bounded families gear and buffs raise for every proc (`ProcChance`, `ProcStrength`, `ProcCooldownCut` held at `ProcCooldownCutMax`, `CounterSize`, zc-entity stat JSON) are read by `Procs` alone. Never add a stat per knack.
- The package lives in zc-track because it is the one module that sees every part a proc touches (zc-entity's hit reads and conditions, zc-effects' effect adds and crowd control, zc-cast's chain fire, zc-progression's moments, the picks a reach audit reads); it names no track concept beyond the `track_pick` audit and stays generic: a proc gated on a held item works the same.
- Every trigger has one producer: Hit and SprintHit ride zc's `DEAL_DAMAGE` moment (`ProcMoments`, through `HitPayload`, which zc-objectives' `DamagePayload` implements), Kill, BlockBreak and Harvest the kill, break and pickup moments; HitTaken, Blocked, Dodged, Landing and CrouchStill are `ProcSystems`'; Dodge, GuardStart and Cast fire only once the move truly happened (`MoveProofs`, settled by the holder pass): a Dodge once a `Dodging`-family effect (zc-entity's file) lands after the player's own Dodge chain starts, a GuardStart when the engine's current wielding goes from none to one, a Cast once the player's own Ability chain finished or still runs half a second on (a chain whose root a consumer claims through `ProcAbilities.Namer.castsItself` never counts: that consumer fires `Procs.cast` as its cast goes off, and calls `Procs.handBack` before it runs the move its key displaced, whose server chain is then proven like a press). One dodge landing proves one press; a Dodged needs every other cancel reason the engine has ruled out (`ProcSystems.Taken.otherCancel`). EffectLanded and EffectEnded are `EffectWatch`'s looks (the engine fires no event). Crit only through `Procs.crit`. Never add a second ECS system on an event one of these covers, and never `setOnCompletion` on a chain (one slot, which a third party may own): poll its state.
- Procs on one moment run in the order of their ids compared lower-cased (`ProcConfig`), and content relies on it (Shatter's proc is named to run before every freezing one): keep the explicit sort, which `ProcOrderTest` pins.
- A proc's strength (its `Strength` times `ProcStrength`) counts once, where an action gives the world something: an applied effect's damage multiplier, a stat change. A counter's add is never scaled (a stored share of a hit is spent by an effect that takes the strength), nor a push or a taunt's time (`ProcActions.counterAdd`, `scaledMultiplier`). A refund that gives back a cost writes `ChangeStat.Scaled: false` (`statAmount`): gear must never make it pay back more than was spent.
- A proc's `Hit` group is the conditional stats' (`ConditionalStatAsset.Hit`, read by `HitReads`), never a copy; `OverTime` reads false unless written, and a hit taken is read as its attacker dealt it. `Ability` asks the move: `Roots` against `ChainRoots` (a player's chain starts, recorded by type only while a live proc asks, a hit reading its own type's latest), `Names` against a consumer's `ProcAbilities` namer (the MMO names its abilities' hits and casts).
- An entry's `Area` aims its target groups at every foe in reach (`Nearby.foesAround`, hostile or locked on), or with `Allies` every ally (zc-core's `entity/Allies`: the party's members, else other players while PvP is off; zc-instance fills its party half), nearest first, held to `Max`; its `OnSelf` groups and `Counter` run once. Bosses and elites stay out through zc-entity's `Zig_Boss_Or_Elite` NPC group asked with `Inverse` (`{ "Id": "ZigFoeFamily", "Groups": [ "Zig_Boss_Or_Elite" ], "Inverse": true }`). `Push` is one Add on the engine's `Velocity`, never the knockback component (a null config multiplies by 25). `Taunt` is zc-effects' `AggroControl.tauntOne`, never a second taunt. `BreakGuard` clears the current wielding and cancels the guard chain, never `Stamina_Broken` (infinite; only the stamina system lifts it). A guard that is up is the engine's own `Wielding` condition.
- Waits are `ProcCooldowns` (per player by entity UUID, per target by ref, dropped when the target leaves and at disconnect); counters are `Counters` (by holder ref, never saved; their modifiers keyed `zigtrack:@counter:<id>`, which the stat grant writer leaves alone and the 1.7.x rollback sweep clears, R755; a holder's first pass sweeps what an earlier session left; a `PerTarget` counter keeps stacks per foe, gives no modifiers and shows nothing, and `counter_stacks` reads it about the context's target). zc-cast's `ArmedStateStore` is next-hit slots, not a cooldown map; never build a third store.
- No proc runs inside another's actions (a per-thread guard), and a hit a proc dealt itself is no moment for any proc or counter clear (`ProcMarks`: an effect a proc applied, its instance held weakly; a hit whose `Damage.INTERACTION_TYPE` is the procs' chain label). A proc's chain runs as `InteractionType.EntityStatEffect`, the engine's own server-run label (blocked by no input, no default cooldown), never an input type the triggers listen to.
- A counter's `ClearedBy` skips a damage-over-time tick unless it writes `ClearOverTime`; a counter empties when its own `Requires` fails on the holder pass (a respec, a build swap) and when its holder dies (`ProcSystems.Died`). A held effect's `Hold` and `Linger` are times per holder and file (`HeldEffects.step`), never saved.
- Threads: a target leaving one world walks every holder's counters, watched foes and per-foe stacks (`Counters.targetGone`, `EffectWatch.forget`) while another world's thread adds to its own, so those maps are concurrent and a state's target fields volatile; every other per-holder field is touched by that holder's world thread alone. Keep any new cross-world walk on concurrent maps.
- `ProcValidator` is the boot audit pass: an unknown effect, stat, RootInteraction, effect family, counter or trigger is an ERROR (the brief's rule for this store: each would silently do nothing), a proc that cannot run as written, a group that does nothing as written, or a file no live pick reaches a WARNING.
