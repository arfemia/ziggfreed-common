# proc/ - procs, counters and held effects (a package of zc-track)

- A knack is data, never a stat of its own (R758): a proc file (`ProcAsset`, `Server/ZiggfreedCommon/Procs/`) opens on its `Requires` (a talent's `ziggfreedcommon:track_pick`, its rank read in the numbers' formulas), answers one `ProcTrigger`, and runs `ProcAction` groups. Its numbers are `FactorFormula`s; the bounded families gear and buffs raise for every proc (`ProcChance`, `ProcStrength`, `ProcCooldownCut` held at `ProcCooldownCutMax`, `CounterSize`, zc-entity stat JSON) are read by `Procs` alone. Never add a stat per knack.
- The package lives in zc-track because it is the one module that sees every part a proc touches (zc-entity's hit reads and conditions, zc-effects' effect adds, zc-cast's chain fire, zc-progression's moments, the picks a reach audit reads); it names no track concept beyond the `track_pick` audit and stays generic: a proc gated on a held item works the same.
- Every trigger has one producer: Hit and SprintHit ride zc's `DEAL_DAMAGE` moment (`ProcMoments`, through `HitPayload`, which zc-objectives' `DamagePayload` implements), Kill, BlockBreak and Harvest the kill, break and pickup moments; HitTaken, Blocked, Dodge, GuardStart, Cast, Landing and CrouchStill are `ProcSystems`' (a chain start counts only from the player's own input: the engine numbers server chains below 0, so an MMO ability body fired as `Dodge` never reads as a dodge); Crit only through `Procs.crit`, which a consumer that rolls crits calls. Never add a second ECS system on an event one of these covers.
- A proc's `Hit` group is the conditional stats' (`ConditionalStatAsset.Hit`, read by `HitReads`), never a copy; `OverTime` reads false unless written, and a hit taken is read as its attacker dealt it.
- Waits are `ProcCooldowns` (per player by entity UUID, per target by ref, dropped when the target leaves and at disconnect); counters are `Counters` (by holder ref, never saved; their modifiers keyed `zigtrack:@counter:<id>`, which the stat grant writer leaves alone and the 1.7.x rollback sweep clears, R755; a holder's first pass sweeps what an earlier session left). zc-cast's `ArmedStateStore` is next-hit slots, not a cooldown map; never build a third store.
- No proc runs inside another's actions (a per-thread guard), and a hit a proc dealt itself is no moment for any proc or counter clear (`ProcMarks`: an effect a proc applied, its instance held weakly; a hit whose `Damage.INTERACTION_TYPE` is the procs' chain label). A proc's chain runs as `InteractionType.EntityStatEffect`, the engine's own server-run label (blocked by no input, no default cooldown), never an input type the triggers listen to.
- A counter's `ClearedBy` skips a damage-over-time tick unless it writes `ClearOverTime`; a counter empties when its own `Requires` fails on the holder pass (a respec, a build swap) and when its holder dies (`ProcSystems.Died`).
- Threads: a target leaving one world walks every holder's counters (`Counters.targetGone`) while another world's thread adds to its own, so a holder's counter map is concurrent and a state's target fields volatile; every other per-holder field is touched by that holder's world thread alone. Keep any new cross-world walk on concurrent maps.
- `ProcValidator` is the boot audit pass: an unknown effect, stat, RootInteraction, effect family, counter or trigger is an ERROR (the brief's rule for this store: each would silently do nothing), a proc that cannot run as written or that no live pick reaches a WARNING.
