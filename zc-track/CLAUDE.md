# zc-track

A named value a subject climbs, read as levels on a shared curve (B113). Edges: core, loot, progression, entity; zc-objectives (the `TRACK_*` producer) and later zc-reputation sit above it, and it never imports either.

- Every read and write of a climb goes through `TrackService` over the `TrackStore` its key's subject kind has (`TrackStores`; the library fills `player`, `PlayerTrackStore` on `TrackComponent`). `TrackKey(subject, namespace, track, run)` reserves namespace and run (R583): only the default climb pays unlocks, mirrors and credits objectives.
- `TrackService.add` is the one write path, behind the `TrackGain` seam (`TrackService.gain`, default lands as asked) a gain pipeline sits in. A committed move parks unlock Claims and fires `ZigTrackChangedEvent` (behind `hasListener`); only when a reading moved (`TrackChange.readingsMoved`: the level, the best level or the prestige count) does it write the mirror and bump the player's gate epoch, so a stream of small gains stays off the gate's hot path. A write is the live subject's own thread only, an offline climb is read (`load`) and never written.
- Gates read the best level ever (`track_level`), which a prestige never lowers; the current climb is `track_climb`. All four readings are `Volatility Player`: a track or curve fold moves the server epoch (`TrackConfig`, `TrackCurves.invalidate`), so keep both if a reading ever reads anything else.
- Unlocks pay as Claims (`TrackUnlocks`, id `<track>:<row key>:<level>`, M428) against a per-row paid-through mark read against the best level, so a prestige or a climb back pays nothing twice and a row added later pays what is behind; `markPaidBelow` is the migration's way to say an older system already paid. A row is known by its key (`TrackAsset.Unlock.key`: its optional `Id`, else built from its own At and Every, never its index), in the Claim id and in the record's `PaidThrough` map alike, so rows may be added, removed or reordered on a live track; changing a keyless row's levels makes it a new row, and two rows with one key are the validator's `DUPLICATE_UNLOCK_KEY` warning.
- A pass is `plan` then `pay`: the moved marks are saved first, then the Claims written, and a Claim that throws puts its row's mark back to the last level it wrote and is saved again (`TrackService.keepPaying`), so a failure never loses or doubles a Claim. Keep that order.
- `TrackComponent`'s save format is append-only: a new fact is a new leaf, never a rename or a reshape of a leaf (a reshaped one would fail to decode a saved player).
- A curve is tabulated once per id (`TrackCurves`, its generation the `LevelCurve` pattern); `CurveTable` is pure and its first Hybrid piece is the MMO's formula to the bit (the MMO's `SkillCurveFileTest` holds `Skill_Hybrid` to `LevelCurve`).
- The prestige `Build` setting (Keep, Remember, Clear; `TrackDef.prestigeBuild`) is kept here and acted on by the picks pass; nothing here touches picks.
- Native first (R700): the level mirror is a native stat modifier (`StatMirror`), and `ZigTrackReward` is a native `RewardAsset` Type (registered unguarded in `TrackBootstrap`) that parks a Claim of the zc `Track` reward kind.
- After changing a track, curve or category codec, run `:zc-track:generateSchemaDocs` through the lane and commit `SCHEMA.md`; `SchemaDocDriftTest` fails the build on drift.
