# zc-track

A named value a subject climbs, read as levels on a shared curve (B113). Edges: core, loot, progression, entity, world, effects, cast, presentation (the kit's ledger seam only), commerce (the one price, `api`), encounter (the live run index only); zc-objectives (the `TRACK_*` producer, the `DEAL_DAMAGE` producer) and zc-reputation (each reputation a track, SK4) sit above it, and it never imports either.

- Every read and write of a climb goes through `TrackService` over the `TrackStore` its key's subject kind has (`TrackStores`; the library fills `player`, `PlayerTrackStore` on `TrackComponent`). `TrackKey(subject, namespace, track, run)` reserves namespace and run (R583): only the default climb pays unlocks, mirrors and credits objectives.
- `TrackService.add` is the one write path, behind the `TrackGain` seam (`TrackService.gain`), which ships filled with `gain.GainPipeline`. `set` puts a value that already moved elsewhere (an engine copy an admin moved) past the seam and commits it like `add`; `seed` is a migration's silent import into an empty climb (no Claims, no event), and `raiseBest` its silent raise of a climb's best level; `markPaidBelow` and `markPaidThrough` only raise marks. `ZigTrackChangedEvent.startedEmpty` tells a module whose climbs start elsewhere (a reputation's starting value) that a move landed on a fresh climb. A committed move is stored first; only when a reading moved (`TrackChange.readingsMoved`: the level, the best level or the prestige count) does it write the mirror and bump the player's gate epoch, so a stream of small gains stays off the gate's hot path; then it parks unlock Claims (planned after the store and the epoch, so a reward gated on the track's own reading sees the move) and fires `ZigTrackChangedEvent` (behind `hasListener`). A write is the live subject's own thread only, an offline climb is read (`load`) and never written.
- A module that derives tracks or curves from its own assets (zc-reputation's ladders) hands them over with `TrackConfig.provide` and `TrackCurveConfig.provide` (per owner, the defaults layer, under every pack file and the owner's word), then runs `TrackOwnerLayers.reload` so a `tracks.json` entry retunes one leaf by leaf.
- The gain pipeline (`gain/`): a track's `Gain.Factors` names factors in order (`GainFactors.DEFAULT_ORDER`, the MMO's award order, when unwritten); a consumer adds one with `GainFactors.register` (an id nobody registered changes nothing). Each is compiled once per subject and track into a `GainStep` (`GainPlans`), kept until the server counter (a factor registration, a track fold, a world rule or gameplay config load) or the subject's (a world change, a permission change, `GainPlans.invalidate`) moves, so the hot path looks nothing up. The library fills `World` (`world/TrackWorldRules`), `Boost` (the boosts below), `Prestige` and `Rested` (the record's pool, off unless the track writes `Gain.Rested`, R572, filled at login from `TrackComponent`'s `SavedAt`). A loss skips the factors. The breakdown is built only by `TrackService.explain`.
- Boosts (`boost/`) are the `Boost` factor (`BoostFactor`, registered over the neutral one by `BoostBootstrap`), never a second pipeline: standing, server and personal boosts naming the track or its category, summed and held under `BoostSettings.Cap` (+200% unless written, R669) by the pure `BoostStack`. Bonus and Boost add rather than multiply because `Gain.Additive` (default `Bonus`, `Boost`) runs them as one `AdditiveStep`, the MMO's `bonus + (boost - 1)`. Every start goes through `Boosts.start` (the `ZigBoost` interaction and reward Types, the `Boost` reward kind on Collect, `/zigboost start`), which keeps it first, then moves the plans (`GainPlans.invalidate`, `invalidateAll` for a server one) and the tiles; an end needs nothing, since the compiled step carries the earliest end and rebuilds past it. Personal starts and waits ride `TrackStore.boosts` (the `Boosts` leaf of `TrackComponent`), server starts `ServerBoosts` (`server-boosts.json` beside the owner files, read on `BootEvent`). Tiles are `TimedBuffs` (`BoostTiles`), whose tile is a native EntityEffect while the record stays the truth, shown only while the boost lifts (present, its `Requires` met); a calendar change re-syncs them through zc-objectives' `CalendarBoostTiles` (`Boosts.onCalendarChange`).
- `Prestige` (`PrestigeGainFactor`) pays a prestiged climb's constant `Prestige.GainPercent` (10 unless written, R642), read off the gain's record, so a prestige needs no plan rebuilt.
- Sources (`source/`): `TrackSourceAsset` files fold into one zc-core `MomentTable` per track (`TrackSources`, rebuilt on a source or track fold); `TrackSourceReactions`, a library-default `MomentListener`, pays the most specific row the player's current level has reached (`Level` is a soft gate: below it the next matching row pays). A kind nobody names costs one lookup (`TrackSources.listens`, which the `DEAL_DAMAGE` producer asks before producing). Frequent kinds (`TrackSources.batches`) are summed per player, track and source and paid once a tick (`SourceBatch`); a player's sums leave a world with them (`RemovedPlayerFromWorldEvent`, on that world's thread) and are paid at the next world's ready settle, a disconnect drops them, and a sum is never paid off its player's own world thread. `Diminish` counts in memory only; `SkipSpawnerMobs` reads the victim through `VictimPayload`, an exact amount through `ExactAmountPayload`.
- World rules (`world/`): `TrackRules` is the native gameplay config group `Plugin.ZigTrackRules` (registered unguarded in `TrackBootstrap`) and the `Rules` of a `TrackWorldRuleAsset` (`Where`, `Enabled`); a world's own config wins whole over the files, then the most specific `Where`. Its lists and switches only take away, one to one with the MMO's World Rules. `Grants` (`Enabled`, `Kinds` by grant kind or a kind's `family()` word, and the same per track or category under `Tracks`) is read by the grant rebuild through `TrackWorldRules.grantsOn` (the MMO's StatBonusesEnabled is `Kinds.Stat`, CombatBonusesEnabled `Kinds.Combat`, AbilitiesEnabled `Kinds.Ability`).
- Picks (`pick/`, R599): `TrackPickAsset` is the one pick shape (choice `Groups`, or a pick bought outright with `Cost`, `Repeat`, `SpendCap`, `Where`, `Grants`), its options shared `PickOptionAsset` files whose `Grants` are a template the pick's `Vars` fill through zc-progression's `GeneratorCore`, its offers drawn by a `PickDeckAsset` on a `PickRoad` from the files alone, `Offers` pinning a level: no seed, player or roll (R724, R653; `PickRoadTest`). `TrackPicks` folds them once per load; `PickService` is the one reader and writer (owed picks derived, never Claims; undo held server-side, `PickUndo`, R650; respec, which keeps only what a trainer taught, a `Where` naming placements (`taughtByTrainer`), and clears every other pick, Mastery and `KeptThroughPrestige` ones included, its points back; the prestige `Build`), and `PickClaims` lists what waits on the Claims tab through the kit's `LedgerContributions.CLAIMS`. A slot is `<pick>/<group>/<level>` in the record's `Picks`, so a group's key, like an unlock row's, never moves on a live track.
- Trees (R736): a pick's `Branch` counts its cost toward that branch, read by `ziggfreedcommon:track_branch_spent` (Param `<Track>:<Branch>`, `TrackPicks.branchSpent`, the one reader); picks sharing a `Node` on a track are one choice (`PickDef.otherFaces`, linked by the fold), a face taken locking the rest (`NODE_TAKEN`). An undo pops the newest pick and is refused (`NEEDED`) when a pick still held would lose a gate it met, weighed by a trial write. Saved builds (`Loadouts.Max`) are snapshots of every pick a prestige would not keep (`PickState.snapshot`), in the order made (`TakeOrder` holds slot keys and take ids interleaved); a swap writes the build in use back over its saved build keeping every saved pick it could not load (`Loadout.writtenOver`: a swap never loses a saved pick; a `Node` face taken since in place of the saved face stands in that face's place, read through `PickDef.otherFaces`), is refused (`UNSAVED`) with no build in use while picks would be lost unless forced, clears to the kept picks and re-spends the build in that order through the same rules a pick obeys (`takeInto`, `chooseInto`), never setting a state directly, and it is refused in combat (zc-entity `CombatState`) or mid-encounter (`EncounterRuns`). A swap's and a respec's price is the one `CostAsset`, charged through `PickPayments` (refund the receipt); a swap to the build in use resets it to as saved, free. Remember's takes are re-spent in order only on the player's confirm (`respendRemembered`, R598), and `spendInOrder` is the same walk for a starter build.
- Grants: zc-entity's `grant/` holds the kinds' registry (`Grants.register` into the native `Grant.CODEC` union with the kind's one `GrantWriter`; the library ships `Stat`, a flat native `StaticModifier` on the stat's maximum, a percent written as its flat share of the stat's base). `TrackDerived.rebuild` is the one idempotent writer of a player's grants, keyed `zigtrack:<track>:<pick>` (a track's `Points.Grants`, once per point of its pool spent, `zigtrack:<track>:points`, so a pick id `Points` is the validator's `RESERVED_PICK_ID`), run at every ready settle, after every pick, undo, respec and prestige, and for everyone online after a pick, option, deck, track or world-rule fold; never write a `zigtrack:` modifier anywhere else.
- Gates read the best level ever (`track_level`), which a prestige never lowers; the current climb is `track_climb`. All four readings are `Volatility Player`: a track, curve or pick fold moves the server epoch (`TrackConfig`, `TrackCurves.invalidate`, `TrackPicks.invalidate`, which `track_branch_spent` needs: it reads the picks' `Branch` and `Cost`), so keep them all if a reading ever reads anything else.
- Unlocks pay as Claims (`TrackUnlocks`, id `<track>:<row key>:<level>`, M428) against a per-row paid-through mark read against the best level, so a prestige or a climb back pays nothing twice and a row added later pays what is behind; `markPaidBelow` is the migration's way to say an older system already paid. A row is known by its key (`TrackAsset.Unlock.key`: its optional `Id`, else built from its lowest At level and its Every, `at_2_every_4`, never its index), in the Claim id and in the record's `PaidThrough` map alike, so rows may be added, removed or reordered and a level added above a row's lowest keeps its record; changing a keyless row's lowest level or its Every makes it a new row, and two rows with one key are the validator's `DUPLICATE_UNLOCK_KEY` warning.
- A pass is `plan` then `pay`: the moved marks are saved first, then the Claims written, and a Claim that throws puts its row's mark back to the last level it wrote and is saved again (`TrackService.keepPaying`), so a thrown failure never loses or doubles a Claim (a crash between the mark and the Claim loses that Claim by design). Keep that order.
- `TrackComponent`'s save format is append-only: a new fact is a new leaf, never a rename or a reshape of a leaf (a reshaped one would fail to decode a saved player).
- A curve is tabulated once per id (`TrackCurves`, its generation the `LevelCurve` pattern); `CurveTable` is pure and its first Hybrid piece is the MMO's formula to the bit (the MMO's `SkillCurveFileTest` holds `Skill_Hybrid` to `LevelCurve`).
- The prestige `Build` setting (Keep, Remember, Clear; `TrackDef.prestigeBuild`) is applied in `TrackService.prestige` (`PickState.afterPrestige`; trainer and `KeptThroughPrestige` picks stay, held by design even when a branch gate they met no longer is: nothing re-gates a held pick, at the rebuild or after, and `KeptThroughPrestige` governs a prestige alone), and sets a track's pick level (`PickService.pickLevel`: the best level under Keep, else the current climb's).
- Native first (R700): the level mirror is a native stat modifier (`StatMirror`), `ZigTrackReward` is a native `RewardAsset` Type and `ZigTrackRules` a native gameplay config group (both registered unguarded in `TrackBootstrap`).
- After changing a track, curve, category, source, world rule, boost, pick, option, deck or grant codec, run `:zc-track:generateSchemaDocs` through the lane and commit `SCHEMA.md`; `SchemaDocDriftTest` fails the build on drift.
