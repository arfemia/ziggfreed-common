# calendar/asset/

- A calendar event is `CalendarEventAsset` at `Server/ZiggfreedCommon/CalendarEvents/<Owner>/<Id>.json`; the FILE NAME is the id and folders are inert, so ids collide across owners unless prefixed. An id `Calendar`, `Almanac` or ending in `_Live` (another switch's, `ID_RESERVED`) or carrying `|` or `@` (the attendance save format's separators, `ID_UNSAVABLE`) never runs and declares no feature (`CalendarEventAsset.isReservedId`).
- A Window is `Start`/`End` (`MM-DD`, BOTH days in), a `Rule` (`WindowRules`, a `Type` union) that wins over them, and `Years` that win over both: each entry is `WindowRules.YearDays`, never a Rule arm, and dates that WHOLE year. The shapes, how runs are numbered and each problem code are in `CalendarEventAsset`'s and `WindowRules`' javadoc and the codec documentation; the dates maths is `AnnualWindow` over `YearRule`. A run's number is its rule's name for it (a list place, a month, a calendar week), 1 to `Occurrence.MAX_NUMBER`, so a `Runs` list of more spans is unreadable; a number set aside (`RUN_SET_ASIDE`) or skipped (`Skip`) is never reused.
- `Moon` (`MoonPhaseRange`, the engine's key and wrap rule, `moon/MoonRange`; `World`, blank for the default) and `Live` (`AnyOf`, `AllOf`, `NoneOf` event ids) replace a Window: Live wins over Moon, either over a Window (notes `WINDOW_UNUSED`, `MOON_UNUSED`), and neither needs a FirstYear.
- `CalendarEventValidator` is the calendar's content audit (domain `calendar`; a consumer folds `audit()`): `CalendarEventAsset.problems()` under their own codes, an ERROR when the event never runs (`NEVER_RUNS`), else a WARNING, plus icons, Presentation and Herald keys, each spawn's Event against the loaded set (`SPAWN_RIDES_CONDITION` for a Moon or Live event), a Moon's World and range against the loaded worlds, and a Live's ids (`LIVE_UNKNOWN_EVENT`) and loops (`LIVE_CYCLE`), each a WARNING.
