# stats/ - item-carried stats as native modifiers

`com.ziggfreed.common.stats` is a split package: `StackStats`, a pure item-metadata record, lives in zc-core so any module can stamp a stack. Gear sets (`gearset/`) keep their own router.

- `stats/` and zc-core's `counter/` never merge: an item-carried stat lives here, a per-subject tally in `counter/`, and a tally that must reach a stat channel is mirrored onto it with `StatMirror`.
- `StackStats.Entries` stores percent channels in whole percent points (`10.0` is +10%) and flat channels raw; which family a channel belongs to is its owner's business. `merge` is the one summing authority, and `stampReplacingWithCount` writes the count it is given (it never increments).
- A retired stat id lives on in zc-core's `StatAliases` (old id to one or more successors, each taking the old value in full, or times the alias's scale for one whose successor counts in another unit, `registerScaled`): `StackStats.entriesOf` and `merge` normalize through it, so a saved roll applies under the new ids and a restamped stack stores them. A consumer registers its own retired ids at setup and routes any other place it reads or writes a stat id by name through `StatAliases.resolve`, times `StatAliases.scale`. In the library, an id authored elsewhere (content, a factor's `Param`, an audit's subject) is read through `StatIndexCache.resolveCurrent` (a retired id's one successor at scale 1; a pool a cost spends too) and written through `StatIndexCache.landingsOf` (every successor at the alias's scale: grants, bound grants, counter rows, `ChangeStat`, `Onto`, gear set tiers), and an audit passes a retired id with the one retired warning (`resolvesForWrite` for a write); `resolve` stays strict for the library's own constants, derived families, `StatChannelAudit` and the writers' own ids. An owner layer keyed by stat id files an entry under a renamed id's one successor (`StatIndexCache.currentId`, through `OwnerLayerReader`'s `idOf`, as `ConditionalStatConfig` does), and `StatMirror.set` names a stat nothing loads once (`warnUnknownOnce`), never skips it silently.
- A stat id a consumer answers from a record it keeps (a level, a track's `Mirror`) is claimed once at setup through `MirroredStats.claim` (zc-track claims every track's mirror, `TrackMirrors`), and every reading of it as a value asks the claim before `resolveCurrent`: `hytale:stat` (`HytaleFactors.resolveStat`), `station_stat` and `station_share` (no bound share on one), a proc's stat, and a consumer's authored read (`claimOf`, `readAt`), so no gear, effect or grant line on it counts. A claimed id is a reading that needs no stat file (a consumer's levels ship none, a track's `Mirror` may name one no file ships, whose write `TrackService.mirror` then skips quietly): every audit that would call an id unknown asks the claim first (the gear set tier, a held effect's stat, a track's `Mirror`), and the gear set audit warns `MIRRORED_STAT_ON_GEAR` on a tier line naming one. A new reader of an authored stat as a value asks `claimOf` first. A stat nobody claims reads its fold.
- The engine (`StatModifiersManager`) never applies a held item's own `Utility.StatModifiers`, so the bridge does. It does apply the utility-slot (offhand) item's, so the bridge applies only that item's `StackStats`, or the bonus doubles.
- The library installs the ONE bridge (`EntityBootstrap.installEquipStatBridge`, namespace `ziggfreedcommon`) and its three trigger subclasses. ECS systems are class-keyed, so never install a second bridge or register your own triggers: read it through `EntityBootstrap.equipStatBridge()` and hang derived work on `addAppliedListener`, which runs after every recompute (keep it cheap and idempotent).
- `EquipStatBridge.equippedSnapshot(store, ref)` answers what the entity has on by item id (`EquippedSnapshot`), through the same container reads the stat walkers use, so a listener never re-derives the slot layout.
- `planUtility` and its `UtilityPlan` / `UtilityPut` / `StatKey` types are public and permanent (2.2.0): the bridge and a gear-set tier share one diff-skip and stale-key core so they agree on what "stale" means.
- The library recomputes every player through the bridge at a LATE `PlayerReadyEvent` (`GearSets.onPlayerReady`); a consumer adds no ready-time `recomputeAll` of its own.
- The triggers ride only non-deprecated inventory events, never the `Legacy*ChangeStatSystem` family.
- Touch an `EntityStatMap` only through keyed `putModifier`/`removeModifier`, never `setStatValue` or `addStatValue`.
- Resolve a stat index through `StatIndexCache`, not `util.AssetIndexCache`: a custom channel can legitimately sit at index 0, which `AssetIndexCache` answers as unresolved.
- Run `StatChannelAudit` once, late (the first `PlayerReadyEvent`), after dynamically registered channels exist.
- The `CategoryGain_Reputation` stat (whole percent points, Min -100; the Reputation category's line of the track gain stats, `CategoryGain_<Category>`) ships here as JSON only: zc-reputation reads it, with a pack's own `TrackGain_<Id>`, at its one writer (`ReputationGain.scale`), so no code here knows it; the retired `ReputationGain` ids alias onto them (R911).
- `KillYield` (whole percent points on a kill find's chance, R916) ships here as JSON only, read by zc-objectives' kill bonus rows (`bonus/KillYields`).
- A cap nothing raises is no stat (R1098): it is a `ZigCeiling` tag on the capped stat's own file (`"Tags": { "ZigCeiling": [ "200" ] }`), read through `CeilingTags.ceilingOf(stat, fallback)` with its `Parent` merged, the last value winning, kept until that stat loads again, the caller's Java constant (the shipped number) standing in, warned once a load, when the file names none. `BuildThrift`, `GatherCare`, `GatherSpeed`, `GrowthSpeed`, `KnockbackResist`, `MoveSpeed`, `ProcCooldownCut` and `TrackGain` carry one; a server owner changes a cap by shipping the stat's file. A cap gear or an effect raises stays a stat (`DamageBonusMax`, `DamageResistMax`, `WeakSpotMax`).
- The SK6d stats (R706, R648, R734) ship here as JSON only, each read by its one owner elsewhere: `MoveSpeed` and `KnockbackResist` by zc-effects' `effect/movement/`, `Regen_Health` and `Regen_Mana` by zc-core's `health/StatRegenSystem`, `HealingPower` by zc-core's `HealthUtil.heal(store, healer, target, amount)`, `TrackGain` by zc-track's `gain/BonusGainFactor`.
- Every living entity with an `EntityStatMap` carries these stats, a creature as much as a player (R860): every per-entity pass of a stat family (zc-effects' stat-to-effect sync and effect-length pass, the conditional holder pass) asks `StatCarriers` (a player every tick, a creature every `CREATURE_EVERY_TICKS` world ticks, staggered by entity index), and every per-hit step reads any attacker. Never add a player-only check to one; a consumer's rule that is about a player's grants (the MMO's world combat rule) answers for players alone.
- Crits and lifesteal (R865, R866) are `com.ziggfreed.common.damage.onhit`, JSON stats here: `CritChance`, `CritDamage` (base 50, a crit deals 1.5 times) and `Lifesteal`, whole percent points. `CritSystem` (Filter, after `WeakSpotSystem`) rolls once per direct hit of any attacker: the chance stat, every conditional stat whose file `Pays.CritChance` and counts on the hit (`ConditionalStats.critPoints`) and every `Crits.registerChanceSource`; a crit multiplies by one plus the crit damage (`registerDamageSource` added), marks the hit (`Crits.hitKey`), fires `ZigCritEvent` (zc-track's Crit procs hear it) and shows `WeakSpotSettings`' `CritText` word to the attacker alone (R896), unless their own Settings switch is off (`Crits.installWordRule`, which the wiring root fills with `PlayerSettings.critWord`; the owner's `CritText.Enabled` stays the switch for everyone). `LifestealSystem` (Inspect, once the hit is applied) heals the attacker that share through `HealthUtil.heal` with no healer (a drain) and fires `ZigLifestealEvent`. One consumer `HitRule` each (`installHitRule`) refuses a hit; a consumer never rolls a crit or heals a percent lifesteal of its own. `RoutedStats` is the one routed-source registry the weak-spot, crit and lifesteal sources share; `HitWords` the one combat-text helper.
- Crit by damage type (R936, R937): `CritChance_<Type>` and `CritDamage_<Type>` (whole percent points, JSON only) add to a hit's chance and crit damage when its cause is that type or inherits from it, the nearest such cause winning (`Crits.typeStats`, one map read a hit, rebuilt when `DamageTypes.generation()` moves). The library ships them for Fire, Ice, Lightning and Arcane alone, the types something grants (every stat type costs every entity a slot, `StatTypeCeiling`); a pack's other type ships its own pair. Each element has one stat family (damage, crit chance, crit damage, resist), never a per-school or per-spell copy. `CritChance_VsControlled` is the one conditional crit stat (`Pays.CritChance`, a Controlled foe).
- The weak-spot stats `WeakSpotDamage` and its ceiling `WeakSpotMax` (R708), each way's own `WeakSpotDamage_Head`, `_Back` and `_Staggered`, and `WeakSpot_FoeLow` (a health percent at or under which every hit is a weak spot) ship here as JSON only, read by this module's `com.ziggfreed.common.damage.weakspot` step (`WeakSpotSystem`), which pays one weak-spot bonus a hit (a head box, the rear arc, an effect tagged `ZigWeakSpot` or listed in `WeakSpotSettings`, one tagged `Once` too coming off with the hit it paid, an attacker's effect tagged `ZigWeakSpot_Next` spent by their next landing hit, both decided once a hit for all its causes (`HitNote`), a foe low enough; a hit it paid reads `Hit.WeakSpot`) with each matching way's stat and every consumer source (`WeakSpots.registerSource`, a weapon skill's own on the hits its line counts on) added in, and never on top of a vanilla `Head` TargetedDamage headshot or rear `AngledDamage` backstab branch (the larger of the two, decided once a hit for every cause, `VanillaWeakSpots`). The `WeakSpot` grant kind retired into these stats (R757): a weak-spot rule is a stat, never a grant.
- `condition/` is conditional stats (R757): an ordinary entity stat made conditional by its `Server/ZiggfreedCommon/ConditionalStats/<Stat>.json` file (`ConditionalStatAsset`: `Holder`, `Target` and `Hit` conditions, `PerFoe`, `Max`, and what it `Pays`; `Max` holds every payout, since the engine never clamps the stat maximum its modifiers raise, R761), folded `defaults < pack < owner` (`conditional-stats.json`). The conditions are the engine's own entity `Condition`s plus the library's, registered into `Condition.CODEC` (`ZigFoesNear`, `ZigPlayersNear`, `ZigNight`, `ZigOpenSky`, `ZigHeight`, `ZigStatPercent`, `ZigMoving`, `ZigCrouching`, `ZigFoeFamily`, `ZigEffectFamily`, `ZigHolding`, `ZigWorkingAt`), so an effect's `ApplyConditions` may name them too. Who is near is `Nearby`'s one walk (foes, allies, players); an ally is zc-core's `Allies` rule (R859: the party, else other players while PvP is off; a creature has none), so `ZigPlayersNear` counts allies and every "allies near" reads `Nearby.alliesAround`. `ZigStatPercent` and `hytale:stat_percent` read one range (`HytaleFactors.percentOf`, the engine's min-to-max). Holder conditions are read a few times a second per holder (`ConditionalStatSystems.HolderPass`: every player, and a creature once it holds one of these stats above 0) and cached; a hit reads only the cache, its target and the hit (`HitReads`, `FirstHits`; `Hit.Classes` reads the hit's own damage class (a damage-over-time tick's too: it carries its effect's calculator), else for a hit with a calculator that is no such tick the class its attacker's worn effect gives by its `ZigHitClass` tag, `HitReads.CLASS_TAG`, never the engine's own class; the engine classes a damage naming none `UNKNOWN`, never null, so `HitReads.classFor` reads `UNKNOWN` as no class; `Hit.LaterTarget` reads the engine's own count of a swing's hits, noted in the Filter group by `ConditionalStatSystems.SwingOrderStamp` before the engine's sequence step counts the hit). A damage payout is one route term of the per-type bonus step (`TypedDamageBonuses.registerRouteTerm`), held under `DamageBonusMax`; a `CritChance` payout is the crit step's (`ConditionalStats.critPoints`); `Like` follows another stat's line (`TypedDamageBonuses.countsOn`); a healing payout is zc-core's `HealthUtil` healing term; `Onto` writes one `zigtrack:@cond:<stat>` modifier per stat it names, only on a change, and a player's first pass sweeps any saved before; the key sits under the track grants' owner because it lands on stats 1.7.x knows (`DamageResist_<Type>`), so the 1.7.x rollback sweep of `zigtrack:` keys clears it (R755), and the stat grant writer spares every `zigtrack:@` key (`StatGrantWriter.isRuntimeKey`: this fold's and a counter's `zigtrack:@counter:`; no track id holds an `@`, so no grant key collides). Any other saved modifier on a stat 1.7.x knows takes `zigtrack:` the same way. A foe family is a native NPC group (`Zig_Foe_<Family>`, `Server/NPC/Groups/`), since a role carries no `Tags`; `Zig_Boss_Or_Elite` beside them holds, as one include list, every boss and elite the families exclude (asked with `Inverse` to keep them out), the world's roaming bosses through `Zig_World_Bosses`, which a consumer that treats them its own way includes rather than keeping a list (Mob Scaling's boss tier), and neither side names the other, since the engine refuses a group that reaches itself through its own descent; an effect family is `EffectFamilyAsset` (vanilla's listed, a mod's own through its `ZigEffectFamily` tag), whose `Duration` group zc-effects' `effect/duration/` reads. `StatTypeCeiling` is the boot audit's count of loaded stat types (R759): every living entity ticks a slot for each, so a new family is merged into an old one before it is added.
- Bound grants (R933, R934): a Stat grant's `While` and a gear set tier's `While` (entity conditions from `Condition.CODEC`: the engine's, the library's, a consumer's own kind) make a stat count only while every condition holds on its holder. A writer hands its whole bound list per owner to `condition/BoundGrants.set` (the stat grant writer per placement key, the gear set engine under `GearSetPlan.BOUND_OWNER`), each id stable across rebuilds; the holder pass evaluates them (a player every tick, so a weapon swap counts on the next swing, never throttled like the conditional fold; a creature on its carrier cadence once `BoundGrants.has` it) and puts or takes each modifier under `zigtrack:@bound:<owner>:<id>` only on a flip, so a hit reads their conditions only through the hit term below. A writer handing over a changed amount under the same condition array (a counter's stacks, a rank) has an on modifier written over at once, never dropped for a tick. The grant writer spares that key (`isRuntimeKey`), the 1.7.x rollback sweep clears it, and an entity's first pass sweeps every bound key it no longer wants. Never ship a per-weapon, per-skill or per-tool copy of a shared stat: grant the shared stat bound `While` instead (the library's own held copies retired so, aliased onto their plain stats at setup, `ConditionalStats.RETIRED`, and the held-tool damage onto `DamageBonus` in `RenamedStats`, the one table of the library's renamed stat ids). `ZigHolding` is the one "while holding": `Items` takes `MatchKey`s (`ItemTag:Family=Sword`, any item tag, a name pattern read along the item's `Parent` line), answered once per item id until `MatchSets.generation()` moves; a consumer whose rule is its own (what trains a skill) registers a condition kind into `Condition.CODEC`, never a stat.
- The bound hit term (R945): a bound modifier that is off, whose list names a `condition/HitAwareCondition` (a consumer's `Condition` subclass that also answers `evalOnHit` for a hit its holder dealt, its `Inverse` applied; the MMO's weapon-skill condition), pays on a hit where every condition holds on that hit (`BoundGrants.hitPoints`, through `HitAwareCondition.allHold`): an additive amount on the maximum only, never an on one (it is already on the stat), and a list with no hit-aware condition is never asked. Every per-hit reader of a stat adds it: the per-type bonus (the route term `BoundGrants.damagePoints`, each stat whose line `countsOn` the hit, under `DamageBonusMax`), `Crits` (`CritChance`, `CritDamage` and the type's pair; `mayCrit` asks `hasHitTerms`), `WeakSpotSystem` (its five stats), `Lifesteal`, the conditional hit payouts (the pass keeps a 0 reading `mayPayOnHit` may raise) and zc-track's procs; a new per-hit read of a stat a talent may raise adds `hitPoints` too. A consumer routed source (`RoutedStats`) takes none: a weapon talent grants the shared stat bound.
- The bound off and on readings: a roll made away from the act a modifier binds to (a reward rolled at collect time, an unattended payout) reads the stat plus `BoundGrants.offPoints(accessor, ref, stat, standsIn)`, each off additive-on-maximum modifier whose list names a condition the consumer's predicate accepts and whose other conditions hold as the pass reads them (an on one is already on the stat and never counted again, as on a hit), and may take back out `onPoints(ref, stat, names)`, each on additive-on-maximum modifier whose list names a condition its predicate accepts (another owner's share); no modifier is in both.
- Working at a station (R935, R948, R976): `ZigWorkingAt` (`Stations`, a station's own id as its mod names it, case-insensitive, none for any; and orthogonal knobs on the work, `CyclesMin` and the piece's `ItemLevelMin`, `QualityMin`, `DurabilityBelow`, `Stamped`, read as the `hytale:item_*` factors and `item_stamp_points` read the stack, once per piece, `StationWork.pieceOf`) asks `condition/StationWork`, the seam a station mod fills at setup (RPG Stations, from its live sessions: a `Work` of station, cycle and piece); unfilled it never holds and logs that once, so a file naming it loads on any server. Its `Source` answers from a map, asked once per entity per world tick however many conditions ask (`StationWork.workAt` keeps the tick's answer, dropped on `Left`), and the station mod calls `StationWork.workChanged(accessor, ref)` on the world thread as a work begins and ends, which reads that entity's bound grants at once (`BoundGrants.evaluate`), so the work's first read (a ritual's pace) never waits a tick for the holder pass. Not hit-aware. A station's stat is read away from the work through `ziggfreedcommon:station_stat` (`StationStatReading`, Param `<Stat>@<Station>`: the stat, less the on shares bound to another station, plus the off shares that count at this one, their knobs taken as holding, R958), which at a station its share names reads exactly the stat (the pass read the knobs live); `ziggfreedcommon:station_share` reads only the shares bound to that station, on or off, for a roll that pays the talents and never gear.
- The shared conditional damage stats (`Damage_<Condition>`, each with its `ConditionalStats` file and tooltip label: `VsDot`, `VsHealthy`, `VsUnaware`, `VsLowHealth`, `VsControlled`, `WhileCrowded`, `WhileHealthy`, `WhileMoving`, `WhileSprinting`, `WhileUnhurt`, `ChargedHit`, `ProjectileHit`, `AtReach`, `FirstHit` and the rest) each fix their own threshold in their file. A consumer's talent grants the shared stat (bound `While` its weapon) and takes that threshold, never a copy with a threshold of its own.
- The gathering stats ship here as JSON only, each read by zc-world's `world/gather/` steps (that router lists them): speed, care, thrift, growth (`GrowthSpeed`) and yield (`GatherYield`, and its `_While<Condition>` forms with their `ConditionalStats` files). Their ids are frozen (R861). A stat named for a consumer's skill (`GatherYield_Harvesting`, `GatherYield_Fishing`) ships with that consumer, never here (R922, M513): it reaches the gather steps through the consumer's `GatherStatSources` source. A skill with a held tool has no such stat: its share is the shared `GatherSpeed` or `GatherYield`, bound `While` its tool is in hand (a consumer's condition kind, as for weapons).
- The proc families (R758) ship here as JSON only, read by zc-track's `proc/` alone: `ProcChance`, `ProcStrength`, `ProcCooldownCut` (its cap a `ZigCeiling` tag), `CounterSize`. `condition/` also serves the procs: `Hit.Headshot` (the weapon's own head branch, `WeakSpots.headBranch`), the `ZigCrouching` condition, and `Nearby.foesWithin` (nearest first), so a proc reads a hit and a foe exactly as a conditional stat does.
- `damage/` is the per-type damage bonus (R245, R567): a damage type is any loaded cause with a loaded `DamageBonus_<Type>` stat (`DamageTypes`, read off the files, never a list, R858; a pack's cause or Element ships its own file), and the library's `DamageBonus_<Type>` (whole percent points) and the every-type `DamageBonus` stats and every source a consumer registers (`TypedDamageBonuses.registerSource`, a type or `EVERY_TYPE`, with an optional gate asked only of a source reading nonzero) reach a hit as vanilla adds Enrage, through the ENGINE's outgoing step, from the native effects zc-effects' `effect/outgoing/` keeps in step per carrier (each type's sum held to the attacker's `DamageBonusMax`). There is no flat damage stat (R854): a flat amount is an ability's or a talent's own modifier, and the retired `DamageBonusFlat_<Type>` ids alias onto their type's percent (`registerRetiredFlatAliases`, 4 points a flat point). Never sum the percents per hit as well: a fold that did would pay the same points twice. `TypedDamageBonusSystem` (any attacker) adds the route lines: a `registerRouteSource` line counts on the hits its `Route` names (a Hit tag, a projectile). It joins the hit's engine sum through `NativeOutgoing.addToSum`, the one helper any later step adding a percent or an ability's flat uses, so additions compose as `(a + flat) * (1 + P)` (`withFlat` answers the same flat without writing the hit, for a fold that writes its amount once); a step that multiplies the whole hit (the weak-spot step, the crit step, Mob Scaling's toughness) records its factor with `NativeOutgoing.scaleHit`, so a later flat lands at the product too: `(a + flat) * (1 + P) * weakSpot * crit * toughness` (R992), a crit or weak spot a rule refuses never recorded; a consumer fold that must see them orders itself AFTER the system class. `NativeOutgoing` reads the engine's own sum (`of`, `snapshot` for a tooltip). One consumer rule may switch every bonus off for an attacker (`installAttackerGate`, the MMO's per-world combat-bonus rule); with none installed every bonus counts.
- `damage/DamageResistances` is the per-type resistance family: `DamageResist_<Type>` (whole percent points, base `Max` 0) for every loaded cause with such a file (`DamageTypes.resistTypes`: the damage types and the resist-only `Fall`), the every-type `DamageResist` (every damage type, so never `Fall`; a conditional stat's `Onto` folds into it), a consumer's own stats counted toward a type or `EVERY_TYPE` (`registerSource`, with an optional hold), the rolled-landing stat `RollLanding`, and the ceiling stat `DamageResistMax` (its asset's `Max` is the default ceiling), which bounds a type's SUMMED resistance, worn armor and every other effect on the key included. Nothing here applies it: zc-effects' `effect/resist/` keeps the engine's resistance in step, keyed on exactly the type's own cause (R674: `Physical` does not reduce a Crush hit, as armor's does not), and no damage step reads these stats. Its seams are `installGate` and `installCeiling`. `damage/NativeResistance` reads the engine's own sum (`percentFor`, `of`, `percentsByKey`, through the engine's armor merge) and carries a hit's armor penetration (`setPenetration`, a `Damage` meta key): a page or a fold reads resistance there, never by adding the stats up.
