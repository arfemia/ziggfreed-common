# usegate/ - use gates

A use gate is content (`Server/ZiggfreedCommon/UseGates/<Gate_Id>.json`; the library ships none, so a zc-only server gates nothing of its own), with the owner layer `mods/ziggfreedcommon/use-gates.json`. An item asks for a level itself through its native `Tags` (`ItemLevelTags`, R750): `"ZigLevel": ["<Track>:<Level>"]` (the track's best level, `ziggfreedcommon:track_level`; every value met; a track the server does not run asks nothing), optionally behind `"ZigLevelFeature": ["<namespace>:<Feature_Id>"]`. Any mod's tag applies wherever the library runs; per-item data rides the item, never a pattern list of ours (R751).

- `UseGates` is the one question every refusal path asks (the break and hit systems, the armor-slot filter, `UseGateKeeps.keepCarried`): target axes first, then the item axes; per axis and `Group`, the first PRESENT gate in `UseGateIndex`'s most-specific-first order applies (a switched-off or feature-hidden gate never shadows a broader one); each applying gate's live `Requires` goes through `GateRuntime.evaluator().check`, and the first refusal answers with `RefusalLines.bestLineOf`. Never a second evaluator or a hand-rolled line. Every path's first read is `UseGates.nothingToAsk` (no gate indexed and no item tagged).
- An item's tag is the LAST candidate of the `ZigLevel` group on `Held` (never for armor) and `Worn`: an authored gate in that group naming the item applies instead (owner precedence), and a switched-off one there (`Enabled: false`) switches the tag off for what it names (`UseGateIndex.switchesOffTag`, the one place a switched-off gate counts). The tag's table is read from the engine's tag index on the first ask after an item load or removal (the root's `FrameworkAssetRegistrar` marks it); a value's track is asked of the seam zc-track fills (`ItemLevelTags.trackLookup`).
- Presence is three orthogonal knobs: `Enabled`, `Feature` (`<namespace>:<Feature_Id>`, its own leaf so an owner's `Requires` retune keeps it) and a top-level plain feature or mod condition lifted out of `Requires` (`FeatureLift.liftKnown`, once per asset instance, read at the moment). Ship a switch as `Feature`, never inside `Requires`.
- A refused break and a refused hit are CANCELLED, never zeroed: `ZigBlockBreakProducer` (zc-objectives) declares itself `AFTER` `UseGateBreakSystem`, and a consumer damage fold that must not see a refused hit orders itself `AFTER` `UseGateDamageSystem` and checks `isCancelled`. A DoT tick is never asked.
- The `Worn` axis is the engine's own per-slot ADD filter, wrapped around `ArmorSlotAddFilter` on the five typed armor slots and installed at every player-ready (the engine resets its armor filters when the container loads). It never removes a worn piece; anything restoring armor writes with `filter=false`.
- A refusal is announced as `ZigUseGateRefusedEvent`; this module never toasts (it may not import presentation). The root's `usegate/notice/UseGateNoticeBridge` tells the player, tagged per gate.
- A kept stack (`UseGateKeeps`, stack metadata `ZigUseGateKeptFor`, a folded group to player ids) passes only the item-axis gates of the group it was kept for, for the players it names, never another group's (an owner's own included) and never a target axis. `keepCarried` stamps only what a present gate refuses right now, per refusing group, optionally one group's; the consumer decides when (an update day), once per player. `keeps` and `stamped` are the pure rule `UseGateKeepsTest` pins.
