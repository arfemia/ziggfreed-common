# entity/title/ - the per-player title record

- `ZigTitleComponent` is the one persisted record of a player's titles (`UnlockedTitles`, `ActiveTitle`): ids lower-cased, `|` and `:` refused, and a shown title is always an unlocked one (`activeTitle()` guards a save that says otherwise). Write it only through zc-objectives' `title/TitleUnlocks`, which announces each change and keeps `ActiveTitles` current.
- `ActiveTitles` is the process-wide record of who shows what, online or not: seeded at connect from the saved record, refreshed by every changed write, and KEPT when a player leaves, so a row names an offline player with the title they chose and a title never tells a viewer who is online. A menu naming another player reads it, never that player's store (they may be on another world's thread, or offline).
- It persists to `mods/ziggfreedcommon/shown-titles.json` (`persistTo` at install; the engine's atomic write with a `.bak`, read back when the file is torn): a change is written a moment later on the server scheduler, and the disconnect hook writes it at once (a server stopping disconnects everyone first). It is single-process: a fleet sharing one database keeps one per server, corrected at the player's next connect there.
- The engine's `FileUtil.writeStringAtomic` loads on Update 7 only under the engine's log manager: a test that reads back a file `ActiveTitles` wrote is tagged `engine-items` (those methods alone, as in `ActiveTitlesTest` and `ZigTitleComponentTest`). In a plain unit JVM the write fails, `flush` swallows it and keeps the change dirty, and the record answers from memory, which the untagged `aWriteThatCannotHappenNeverReachesTheCaller` proves.
