# entity/title/ - the per-player title record

- `ZigTitleComponent` is the one persisted record of a player's titles (`UnlockedTitles`, `ActiveTitle`, `ChoseNone`): ids lower-cased, `|` and `:` refused, and a shown title is always an unlocked one (`activeTitle()` guards a save that says otherwise). `ChoseNone` (saved only while set) is set by every `deactivate` and cleared by an `activate` of an earned title; a revoke never touches it. Write it only through zc-objectives' `title/TitleUnlocks`, which announces each change and keeps `ActiveTitles` current.
- `ActiveTitles` is the process-wide record of each player's shown title, earned set and last username, online or not: seeded at connect from the saved record (`ZigTitleComponent.seed`), refreshed by every changed write (`refresh`), and KEPT when a player leaves, so a row names an offline player with the title they chose and a title never tells a viewer who is online. A menu naming another player reads it, never that player's store (they may be on another world's thread, or offline). `idOf` finds a player by the name they last connected with, any case, the latest connect winning a shared name.
- `PendingTitles` is the queue of grants and revokes owed to offline players (one ordered list per player id), filled and paid only by zc-objectives' `title/ZigTitles` and `title/TitleQueue`.
- Both persist through `RecordFile` (the one helper; never copy its file handling): `mods/ziggfreedcommon/shown-titles.json` and `pending-titles.json` (`persistTo` at install; the engine's atomic write with a `.bak`, read back when the file is torn), a change written a moment later on the server scheduler, and the disconnect hook writing both at once (a server stopping disconnects everyone first). A file without a newer map reads it as empty. Both are single-process: a fleet sharing one database keeps one per server.
- The engine's `FileUtil.writeStringAtomic` loads on Update 7 only under the engine's log manager: a test that reads back a file `RecordFile` wrote is tagged `engine-items` (those methods alone, as in `ActiveTitlesTest`, `PendingTitlesTest` and `ZigTitleComponentTest`). In a plain unit JVM the write fails, `flush` swallows it and keeps the change dirty, and the record answers from memory, which the untagged `aWriteThatCannotHappenNeverReachesTheCaller` proves.
