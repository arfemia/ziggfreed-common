# loot/trigger/ - the moment-keyed bonus table

- One engine, two kinds of table. The library's own rows (`BonusRowAsset`, `Server/ZiggfreedCommon/BonusRows/`, owner file `mods/ziggfreedcommon/bonus-rows.json`) fire from zc-objectives' `objectives/bonus/BonusRowReactions` on every produced break, hand harvest and kill, with no other gate. A consumer with a table of its own builds it from `BonusTable`, `BonusChance`, `BonusRolls`, `BonusPasses` and `BonusRowAudit` and fires it from its own `MomentListener`, after whatever gate it keeps. Tables never share rows: a moment can pay one row from each.
- A row's id is its filename: prefix it with the owner's own prefix, since two packs' rows with one filename are one row. Two rows claiming one pattern in one moment are one answer: the later in fold order wins (the library folds in sorted id order).
- A `Chance` is a PERCENT (`{"Base": 5}` is five percent), read only through `BonusChance.fraction` (NaN is no chance; the moment's unwritten default is the table's own, certainty for a library row). `BonusChance.fires` is the one draw rule. Never re-derive either at a site.
- `BonusMoment.carries()` is the one declaration of what a moment's pass carries: `BonusPasses.run` layers a `MomentItems` only when handed the harvest, and `BonusRowAudit` hands the set to the 4-argument `LootableValidator.auditRef`, so a `Moment_Item` outside a `PickupItem` row is warned.
- A harvest's pass runs in ONE world task after the engine gives the harvest (`BonusPasses.afterHarvest`) and re-reads the event there (`harvestOf`: a later cancellation pays nothing, the final stack is the one copied). Never set the pickup event's stack and never fire a pickup: the placed-item ledger keys the moment by the stack's identity and the engine's give re-enters the producer. zc-objectives' `BonusRowReactionsTest` scans this package for both.
- The landings are fixed per moment: `atBlock` (half a block in, one up, every spilled stack counted as found), `atCorpse` (`GroundSpillSinks.atEntity`), `atHarvester` (the player's pickup routing, the rest one pile at their feet). A new moment is a new `BonusMoment` constant plus its landing, appended last.
- The library's rows resolve the WHOLE ref (`BonusRolls.resolved`: a named table's `Pool` draws too). `BonusRolls.rolls` (rolls only) exists for a consumer whose released rows were never given a pool.
- The library audits its rows only on demand (`/zigloot validate`, through `LootAudit`), against the factor vocabulary the rolling kinds read (`LootRewardKinds.installedFactors()`).
