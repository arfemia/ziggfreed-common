# instance/reward/

- `DeferredRewards.fromSelection` is the one translation from a `LootEngine.select` decision into rewards shown now and paid later. A registered kind with no replayable line is dropped and reported, never promised.
- A deferred registered-kind row keeps the spec it came from (`InstanceReward.spec`), so its chip reads the reward through `RewardChips`, never its console line. Stores write it as `StoredReward`'s optional `spec`, which moves no version; rebuild a row only through `withQuantity`/`withId`, which keep it.
- Every row `fromSelection` makes carries its drop's chance (`InstanceReward.dropChance`, percent per chest, from `LootEngine.Selected.chance`), written as `StoredReward`'s optional `chance` (no version move) and left out of equality; a row without one reads as its item's own quality. `DropRarity` is the one reader of its bands, which are data (R858): one `DropRarityAsset` file per item quality id (`Server/ZiggfreedCommon/DropRarities/<Quality>.json`, `AtMostPercent`, `Enabled`; this module ships the five vanilla qualities), folded by `DropRarityConfig` with the owner file `mods/ziggfreedcommon/drop-rarities.json` (`DropRarityOwnerLayers`) into one ladder, narrowest first, a chance above every band reading as the widest and none before they load; `merge` keeps lines of one item apart across rarities, and the chest page's cards read it.
- At the press `InstanceRewardGranter` pays a spec row through its kind's handler on `RewardKinds.shared()`, at the row's quantity (`DeferredRewards.payableSpec`), so the kind's side effects happen (a reputation's worn gain, Cap, bar, rank notice; M513: nothing registers for it), and what the kind receipted reaches the caller of `grantAllLanded` beside the row (`Landed`; null receipt for a row that paid by itself). The line runs instead only for no live claimer, a throwing handler, an item kind (a Claim never pays through `handToPlayer`), or a line that no longer reads as the kind's own for that reward (a site that rewrote it after deferral, as `EncounterClaims.filled` does).
- Hand `DeferredRewards` a subject named `{player}`, so a deferred command resolves whoever claims it.
- `InstanceRewardGranter` is block-first: an `ITEM` is granted only if all of it fits, otherwise it is held pending, never partly delivered. It fits and lands as the engine gives a pickup (`GroundSpillSinks.pickupFits`, then `pickupRouted`: hotbar, storage and backpack in the player's pickup order), never through zc-core's combined `InventoryUtil.give`/`canFit`, which fills armor and utility slots before the bag (`ClaimItemsLandLikeAPickupTest`).
- Register a consumer's reward-token adapter at `setup()`, before `LoadedAssetsEvent`: preset reward specs parse during the asset fold.
- `NativeLootService`: inside a tick use the `(store, commandBuffer)` spawn form. The one-accessor form re-queues an add the engine rejects mid-tick onto the world thread, and every spawn form answers landed-or-queued versus lost.
- A drop at a dying entity is `NativeLootService.spawnAtEntity(store, buffer, ref, items)`, the corpse ground: it reads the entity's position and head rotation through `store` at drop time, lifts the point `FEET_DROP_LIFT` (one block, the engine's death-drop lift) through `lifted`, which copies the live vector, faces `Rotation3f.IDENTITY` when there is no head rotation, and queues through the tick-safe `(store, commandBuffer)` pair form. Never a site's own transform read.
- Every native drop-list roll goes through `rollNative` (empty when nothing could roll), or `tryRollNative` for a probe that must tell an empty roll from one never made (null); never `ItemModule.getRandomItemDrops` directly.
- A unit JVM never boots `ItemModule`, so `NativeLootService` tests prove its guards against the unbooted engine; what a live drop list produces is checked in game.
- `PendingRewardStore` writes through the engine's `FileUtil.writeStringAtomic`, which on Update 7 loads only under the engine's log manager: a test that reads back a written file is tagged `engine-items` (that method alone, as `PendingRewardStoreTest.everyWriteCarriesTheVersion` is). In a plain unit JVM the write fails, the store swallows it and the queue still answers from memory, which the untagged tests prove.
