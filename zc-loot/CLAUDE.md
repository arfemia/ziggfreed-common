# zc-loot

- Depends on `zc-core` only, and eight library modules depend on it (almanac, commerce, encounter, instance, objectives, presentation, progression, reputation), so any edge upward is a cycle. A grant that needs another module's capability is a reward kind registered from above: the wiring root registers `Effect` (zc-effects is out of reach here) beside `Droplist`.
- What loot IS lives in `loot/` only; anything in `instance/reward/` that reads like a second loot model is a mistake.
- `loot/stamp/StampFactors` contributes `ziggfreedcommon:item_stamp_points` process-wide from the wiring root, because zc-entity, which owns the `hytale:` item readings, has no edge to this module. A test that builds a real `ItemStack` is tagged `engine-items` and swaps the item store through zc-core's test fixture `testing/EngineAssetStores` (`testImplementation(testFixtures(project(':zc-core')))`), never a copy.
- A consumer's own reward token (such as `xp`) is a `RewardAuthoring` adapter on `RewardKinds.shared()`; an unregistered token drops its entry, never grants a phantom reward.
- `loot/claim/` holds a player's Claims (payouts collected on purpose, M428): every payout that writes one goes through `ClaimStore.award`, or `awardOrTopUp` for a payout that keeps coming (a quest step's item), which adds to the Claim the player still holds by that id; both share the one place a Claim is counted, scaled and announced (`ClaimAddedEvent`, once per write or top-up). A Claim the player still holds is never written twice (`award` refuses it, a top-up joins it), a Claim with no rewards (a roll that landed nothing) is never written and spends no clear (R346), and none expires. A press that hands one over, or an item taken from a spoils chest's window, announces what it delivered (`ClaimCollectedEvent`, fired by zc-instance's `ClaimGrants`). A title argument a client must translate rides as `Claim.keyArg` or `itemArg`, read through `Claim.titleParams`. A Claim's optional `fight` (appended, saved, absent from older rows, kept by a put-back and by a top-up that names none; a top-up naming a fight moves the Claim to it) names the boss fight's run that paid it, which zc-instance's spoils chest offers; the store knows nothing else of fights. `PendingRewardStore` stays the retry queue beside it. `loot/diminish/` is the diminishing returns: `DiminishSpec` (Steps, Window) and `DiminishLedger`, whose counts are read and written only through `ClaimStore`'s `award` and `awardOrTopUp`. The Claims tab that shows and pays them lives in zc-instance (`instance/claims/`).
