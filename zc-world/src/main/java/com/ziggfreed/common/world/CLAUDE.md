# world/

## Where (world targeting)

- `Where` (`WorldSelector`: `{Match, GameplayConfig, Placement, ExcludeMatch}`) is the one spelling of "which worlds?" in the family. A bare word under `Match` is an exact world name, so `["default"]` reaches that world alone; `ExcludeMatch` only filters the positive axes, so an exclude-only `Where` matches nothing.
- `Placement` names NPC placement ids (any casing) and matches every world a named placement's own `Where` matches, the owner layer included, at that match's rank, whatever its NPC is doing. zc-world cannot see placements, so it reads them through the `PlacementWheres` seam, which zc-dialogue's `NpcBootstrap` fills at setup (it warns once while unfilled). No chains: `match` drops the `Placement` axis of every answer (`withoutPlacement`), and a placement's own `Where` goes through `WhereValidator.validateForPlacement` (`PLACEMENT_CHAIN`); `validateSelector` reports `UNKNOWN_PLACEMENT` only once the pool has folded, both WARNING.
- `WorldSelector` carries no defaults (each read site applies its own) and answers a `MatchRank` or null, never a boolean. Under `Parent` an authored `Where` replaces the parent's whole: its axes are OR'd alternatives, so a merge would broaden the child.
- `MatchRank` sorts `GameplayConfig` exact > exact name > the partial pattern with the longest literal core > bare `*`, and a tie keeps authoring order. It is zc-core's `NameMatchRank` plus the `GameplayConfig` rung, so never keep a private ladder.
- An instance world is named `instance-<name>-<uuid>`: only the contains form (`*Name*`) reaches it by name, so prefer targeting an instance by the `GameplayConfig` it runs.
- An empty `WorldIdentity.loadedWorlds()` means cannot tell. `WhereValidator.validateAgainstWorlds` therefore runs only in a late audit, and reports a `GameplayConfig`-only selector at INFO, since an instance is usually not running.

## Blocks

- The native place-block event fires before the engine refuses a placement, so anything paying per placement asks `BuildPermission` first; cannot tell reads as allowed.
- The engine asks `World.AllowBlockBreaking` before the breaker's game mode, so false refuses creative too. A world where only creative breaks writes it true plus the gameplay config group `Plugin.ZigBlockRules.CreativeOnlyBreaking` (`BlockRules`), whose `BlockRuleSystems` refuse every other breaker at the damage event (a creative break never damages) and a block-group cycle at its chain's start.
- `BlockOps` is the block read and write a consumer reaches for: it never loads a chunk, null means cannot tell, air reads as `"Empty"`, and identity reads (tags, resource types) go through the block's item. Under it sits zc-core's `world/SectionBlockCursor`, the raw block-id read for a walk over many cells (`SurfaceProbe`) and for a module with no zc-world edge (zc-cast's `BlockRaystep`, zc-presentation's `BlockStateSound`): it never loads a chunk either, keeps the last section it resolved, and reads `BlockType.EMPTY_ID` for air and for a cell it cannot see.
- Never read a block through a `World` or `WorldChunk` accessor (`getBlock(x, y, z)`, `getBlockType(x, y, z)`), nor a cell's environment through a column accessor (`getEnvironment(x, y, z)`): Update 7 deletes them, and the root `BlockAccessorHygieneTest` fails on either. `BuildPermission` reads the environment off the cell's chunk section (`EnvironmentSection.get`), the read the engine's own placement check makes.
- `record/BlockRecordSection` registers before any world loads. Its mutators flag the section for saving; a caller mutating a fetched record in place calls `markDirty`; `clone` deep-copies so an IO-thread save never tears.
- `pattern/BlockPattern` has exactly one anchor cell, and one positive quarter-turn maps `(x, y, z)` to `(z, y, -x)`, the engine's `Rotation.Ninety`, so a matched orientation carries straight into a block write.
- `stash/BlockStashes` is pure storage on world game time (an outage advances nothing); item insertion order, oldest first, is load-bearing.
- Placed-block ledger rules live in `placed/CLAUDE.md`.

## Gathering and building (gather/)

- Every number is a native stat read off the player, never a rule in a grant: speed (`GatherSpeed`, `GatherSpeed_<Family>`, `GatherSpeed_Placed`, `GatherSpeed_Tall_Tree`, `GatherRhythm`, a consumer's `GatherSpeedSources` stat, held at `GatherSpeedMax`) multiplies the hit in `GatherSpeedSystem`; care (`GatherCare`, held at `GatherCareMax`) gives each cared hit's own wear back in a world task after the engine charged it (a hit's wear runs from its start to the next hit's); thrift (`BuildThrift`, `BuildThrift_<Family>`, `BuildThrift_Shaped`, held at `BuildThriftMax`) spares the item through `PlaceBlockEvent.setConsumeItem`, only on a block the `Thrift` family holds, and marks the block spared in the placed-block ledger, naming the block, so its break drops nothing (`ThriftDropSystem` refuses a player's break of it first and breaks it again bare; a shape drops nothing for it; `ThriftDropSystem.Blast`, last on the world-level `DamageBlockEvent` an explosion fires with no breaker, refuses a blow that would destroy it and breaks it bare at once; a physics break fires nothing and still drops); growth (`GrowthSpeed`) credits time to a farming block's own clock for its native placer (`PlacedByInteractionComponent`). The tool's tier always decides first: speed multiplies the engine's damage, which a tool that cannot break the block makes 0. A holder condition reaches a base through its own `<Base>_While<Condition>` stat (`GatherSpeed_WhileUnderground`, `GrowthSpeed_WhileNight`), which zc-entity's conditional `Onto` fold adds to the base's maximum while it holds, so these steps read the base alone (`GatherReads.max`) and never a condition.
- A block family (`BlockFamilyAsset`, `Server/ZiggfreedCommon/BlockFamilies/`) matches the block's item tags as the engine merges them (a `Parent`'s included, so vanilla's woods all read `Family: Oak`: tell them apart by id) or its base id; a block's own `ZigBlockFamily` tag opts it in. Ask `BlockFamilyConfig.familiesOf`, never a pattern of your own.
- A gather shape (`GatherShapeAsset`) is asked at the moment and run in a world task once the engine has made the break or harvest; every further block goes through `ToolTier`, `world/BreakPermission` and the engine's own break call with the player and the drop `ToolTier.dropFor` picks (the `Ref` break overloads drop nothing), inside `ShapedBreaks.run`; a soft block wears no tool. A further harvest fires the engine's `UseBlockEvent.Pre` with the player first, where a claim mod refuses one. A shape stops at its first refused cell (`BreakPermission`, a refused break event or `UseBlockEvent.Pre`), so a claim mod speaks once; a cell the tool cannot break is only skipped. A bonus pass reads `ShapedBreaks.rowsAllowed` (the library's rows and a consumer's), and the break chain skips `ShapedBreaks.active`. A walk's bounds are `ShapeWalks`' (`ShapeWalksTest`).

## Sections and entities

- An entity stays in the world only in a TICKING chunk section. On Update 7 a section loads asleep whatever its column does, and the column's ticking flag no longer reaches it: an entity added into a sleeping section is parked into that section on the spot (the add answers null and the caller's post-spawn never runs) and comes back as a load once a player's hot sphere or a `SET_TICKING` section request wakes it. Read and wake a section through `TickingSections`: `stateAt` reads (`TICKING`, `PARKING`, `ABSENT`), `ensureTicking` wakes a section in memory on the world thread and never loads, `whenTicking` runs a step once the section ticks, `holdTicking` keeps a ticking one awake and never wakes. Never decide from a column's `ChunkFlag.TICKING` or a column request's `SET_TICKING`. A wake brings the section's parked entities back first, so a caller that may have parked its own copy there adopts it before adding another; never wake inside a system's processing window. The root `SectionTickingHygieneTest` fails a main source reading `ChunkFlag.TICKING` or passing `SET_TICKING` outside `TickingSections`.

## Terrain

- `SurfaceProbe` stops on trees decorated after worldgen unless handed the foliage keys from `BlockTypeLists.keys("TreeWoodAndLeaves", "AllScatter")`; `SpawnPlacement` takes a seed and never calls `Math.random`. Neither loads a chunk: a column not in memory answers the caller's fallback, so a caller probing ground no player is near loads it first.
