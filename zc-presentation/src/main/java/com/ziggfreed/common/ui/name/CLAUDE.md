# ui/name/ - how a menu names a player

- `PlayerDisplayNames.displayName(playerId, storedName)` is the one name a menu or leaderboard row paints: the live username, else the stored name, else the first eight characters of the id, wrapped by every contribution a higher module made (`contribute(owner, order, contribution)`; titles contribute under `ziggfreedcommon:titles` at 100). Paint it on a Label's `.TextSpans`: a wrapped name is a parameterized Message, which a `.Text` sink prints with its `{0}` showing.
- Contributions wrap the name built so far, the lowest order first, equal orders by owner id; a second `contribute` under one owner replaces its first, and null withdraws it. `fillDecorator` is the default slot at order 0, ahead of a contribution of the same order: asked with the plain name, its answer replaces the name built so far, so a contribution meant to wrap it takes an order above 0.
- A contribution runs on the viewer's world thread for players who may be on another world: it reads process-wide state only, never an entity store. Each is guarded on its own: one that throws is skipped (the row keeps its name and every other wrap) and warns once until its owner contributes again.
- A contribution answers the same for an offline player as for an online one, so a wrap never tells a viewer who is online (titles keep an offline player's choice in a persisted record for this). Call `displayName` for every row, online or not: a row wrapped only while its player is online tells a viewer who is online.
- Menus and leaderboards always; a chat line only through zc-objectives' `title/TitleChat`, while a server owner's `$Chat` is on, and then the whole name, every contribution included. A notice names a player plainly: `plainName` is that plain name, never wrapped (zc-instance's party invite-sent toast reads it).
