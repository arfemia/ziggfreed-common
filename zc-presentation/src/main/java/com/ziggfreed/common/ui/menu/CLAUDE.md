# ui/menu/ - the shared menu: its frame, rail, tabs and palette

- A page on the menu sits in `$F.@ZigMenuFrame` (its columns go in `#Content` after `#MenuRail`), appends through `ZigMenu.appendThemed`, paints the rail only through `ZigMenu.paint`, keeps the `MenuRail` it returns, declares the `Menu` key (`ZigMenu.EVENT_KEY`) on its codec, and calls `MenuRail.handle` before it reads its own action, since a rail click carries none.
- The library's tabs (`MenuSlot`: Almanac, Quests, Achievements, Records, Reputation, Claims, Settings; the Almanac first by ruling M484) are filled by their owners' bootstraps (`ZigMenu.fill`), and a consumer adds one section through `ZigMenu.consumer`; `/ziggui` lands on the consumer's landing, else the first tab that shows.
- A tab may give a second line (`MenuEntry.withSubline`, a `MenuSubline` asked on every paint): `ZigMenu` then shows the row's hidden `#SubLine` and pushes the row to `MenuFrame.TALL_ROW_HEIGHT` as whole Anchors; a tab without one never addresses it.
- The frame and rail read every colour and texture from ONE `Palette` (`MenuDeps.palette`, default `MenuPalette.defaults()`; with no consumer `theme`, `MenuFrameRetint` paints the frame from it), and no menu colour is spelled anywhere else: `ZigMenuDocumentsTest` holds `ZigFrames.ui` and `Pages/ZigMenuTab.ui` to the default palette and `MenuFrame`'s sizes, and `MenuPaletteTest` holds the default to 4.5:1 (3:1 for the selected tab's bar), judging a translucent fill over what it covers.
- The rail is vanilla's own (pane, row, section label, rule, vertical separator): a document spells an alpha colour `#rrggbb(a)` and Java `#rrggbbaa` (`MenuPalette.fromMarkup`), every fill goes out as a typed `PatchStyle` through `UiRetint.fill`, and the selected tab's gradient mask is authored in the row, since no Java push sets it.
