# ui/hud/ - keyed in-world HUD overlay base + layout value

Router for `com.ziggfreed.common.ui.hud`. Mod-agnostic in-world HUD-overlay primitives lifted from the MMO Skill Tree's `ui/hud/` (no consumer keeps an intermediate base of its own: the MMO's `AbilityCooldownHud`, RpgStations' `StationSummaryHud` and this library's own `TrackedQuestHud` each extend `KeyedCustomHud` directly).

- **[`KeyedCustomHud`](KeyedCustomHud.java)** (RPG Stations extraction, phase 1 leg 1): the shared base every custom in-world HUD extends, `extends` engine `CustomUIHud`. Owns a `HudPosition`-driven anchor on a single root element (fixed-height via `toAnchor` or content-height via `toAnchorContentHeight`, see `usesContentHeight()`), two push-throttle strategies (`dueForPush`/`markPushed` for a tick loop that gates BEFORE reading state, `acquirePush` for a CAS atomic acquire), and the native keyed register/lookup/broadcast over Update 5's `HudManager` (`get`, `forEachOnlineHud`, `refreshPositionForAllOnline`). A concrete HUD supplies only its identity + layout (`rootSelector()`, `panelWidth()`, `panelHeight()`, `configuredPosition()`, `updateIntervalMs()`), calls `applyConfiguredPosition` in `build()`, and pushes via one of the throttle helpers. **Mod-agnostic on purpose**: player lookup (`resolvePlayer`) and world resolution (the "any alive world" broadcast fallback) are self-contained here (no consumer world-lookup utility required), and logging is a locally-guarded `CommonLog.LOGGER` call (unit-JVM safe, mirrors the pattern every other primitive in this jar uses - no consumer logging facade required either). Every consumer HUD extends this directly and adds only its own rendering (the MMO's `AbilityCooldownHud`, RpgStations' `StationSummaryHud`); no mod keeps a HUD base of its own.
- **[`HudPosition`](HudPosition.java)**: the mod-agnostic layout value - a vertical `AnchorEdge` (TOP/BOTTOM/CENTER) + horizontal `HorizontalEdge` (LEFT/CENTER/RIGHT) + pixel offsets. `toAnchor(w, h)` / `toAnchorContentHeight(w)` always set `Width` (and `Height` for the fixed form) and pin EXACTLY ONE edge per axis so an offset moves the panel instead of being neutralized by an opposing stretch - including the CENTER-horizontal case (`Left` only when `offsetX != 0`, never `Horizontal`, which is a LEFT+RIGHT inset that would stretch the panel to fill the screen minus the offset). Carries NO consumer-specific defaults (`parse`/`isValidPreset` cover the config-facing named-corner-preset form); a consumer HUD supplies its own default position (e.g. `MyHud.defaultPosition()`).
- **Consumers**: this library's own `objectives/hud/TrackedQuestHud` (zc-objectives; the tracked-quest HUD, extends `KeyedCustomHud` directly and repaints on the quest engine's native events, no tick), the MMO's `AbilityCooldownHud` (extends `KeyedCustomHud` directly, no per-mod shim), and RpgStations' `StationSummaryHud` (extends `KeyedCustomHud` directly, no MMO dependency). The two throttle strategies are for a HUD driven by a tick loop; an event-driven HUD returns `0` from `updateIntervalMs()` and folds its own bursts through [`RepaintCoalescer`](RepaintCoalescer.java) here (the tracker does exactly that; the progress-bar panel in `bar/` pairs it with the interval gate for a throttled paint whose last change is never dropped). `aliveWorldOf(PlayerRef)` is the executor such a HUD hands the coalescer: the alive world holding the player's entity, read off the entity's own store rather than the reference's last-ticked world uuid.
- **[`bar/`](bar/CLAUDE.md)** - the shared progress-bar HUD built on this base: rows created on demand by `HudBars.moved` / `HudBars.itemMoved` and dressed by the reporting mod's `HudBarDisplay`, the `HudBarReading` a value's move hands over for its fill (no source seam, no registry: the asset store is the extension point), the `HudBars` store as an optional per-row override, the `HudBarPanels` store for placement, and `HudBarHud`. See its router.
- **Conventions**: `@Nonnull`/`@Nullable`; the guarded `warn(...)` here is `KeyedCustomHud`-local (not a shared facade - this jar's other primitives each guard their own `CommonLog.LOGGER` call inline); no em-dashes.
