# ui/hud/ - keyed in-world HUD overlay base, layout value, and what a player says about their HUD

Router for `com.ziggfreed.common.ui.hud`. Mod-agnostic in-world HUD-overlay primitives lifted from the MMO Skill Tree's `ui/hud/` (no consumer keeps an intermediate base of its own: the MMO's `AbilityCooldownHud`, RpgStations' `StationSummaryHud` and this library's own `TrackedQuestHud` each extend `KeyedCustomHud` directly), plus the per-player HUD preference every shared overlay reads and the one page + command family that edit it.

- **[`KeyedCustomHud`](KeyedCustomHud.java)** (RPG Stations extraction, phase 1 leg 1): the shared base every custom in-world HUD extends, `extends` engine `CustomUIHud`. Owns a `HudPosition`-driven anchor on a single root element (fixed-height via `toAnchor` or content-height via `toAnchorContentHeight`, see `usesContentHeight()`), two push-throttle strategies (`dueForPush`/`markPushed` for a tick loop that gates BEFORE reading state, `acquirePush` for a CAS atomic acquire), and the native keyed register/lookup/broadcast over Update 5's `HudManager` (`get`, `forEachOnlineHud`, `refreshPositionForAllOnline`). A concrete HUD supplies only its identity + layout (`rootSelector()`, `panelWidth()`, `panelHeight()`, `configuredPosition()`, `updateIntervalMs()`), calls `applyConfiguredPosition` in `build()`, and pushes via one of the throttle helpers. **Mod-agnostic on purpose**: player lookup (`resolvePlayer`) and world resolution are self-contained here, and logging is a locally-guarded `CommonLog.LOGGER` call.
- **[`HudPosition`](HudPosition.java)**: the mod-agnostic layout value - a vertical `AnchorEdge` (TOP/BOTTOM/CENTER) + horizontal `HorizontalEdge` (LEFT/CENTER/RIGHT) + pixel offsets. `toAnchor(w, h)` / `toAnchorContentHeight(w)` always set `Width` and pin EXACTLY ONE edge per axis so an offset moves the panel instead of being neutralized by an opposing stretch - including the CENTER-horizontal case (`Left` only when `offsetX != 0`, never `Horizontal`, which is a LEFT+RIGHT inset). Carries NO consumer-specific defaults (`parse`/`isValidPreset` cover the config-facing named-corner-preset form); a consumer HUD supplies its own default position. A content-height anchor is only proven for a TOP pin inside a `LayoutMode: Top` wrapper (the quest tracker); a BOTTOM-pinned panel needs an explicit height inside a full-viewport wrapper, which is what the bar panels push with every paint.
- **[`HudPreferenceComponent`](HudPreferenceComponent.java) is what one player said about their own HUD, persisted by the LIBRARY** (maintainer, 2026-09-09: a HUD placement is generic presentation with no product vocabulary, so the MMO stores nothing and every consumer's panel reads the same answer, the way `ZigFlairComponent` holds unlocked flair for whoever renders it). Registry id `ZiggfreedCommon:HudPreferences`; three ORTHOGONAL knobs, never a mode: per panel the spot they picked (`Placements`, packed `panel=spot|...`), per panel whether they hid it (`Hidden`, packed `panel|...`), and one `HideAll` switch over every panel; ids fold lower-case and an id carrying `|` or `=` is refused at the write path rather than corrupting the pack. Registered once at library setup, BEFORE any world loads, and attached to every player at connect (`HudPreferences.install`); every read site guards on `TYPE != null` and reads a missing component as "no preference". A consumer that persists player data elsewhere (the MMO's DB backend) marks its `HUD` domain off the native [`ZigHudPreferenceChangedEvent`](ZigHudPreferenceChangedEvent.java), fired through [`HudPreferenceEvents`](HudPreferenceEvents.java) (a `NativeEventSeam`) for every REAL change and never for a no-op.
- **[`HudPreferences`](HudPreferences.java) is the way in**: `placementPick` / `isHidden` / `isHideAll` (world thread; the panels read them per paint) and `setPlacementPick` / `setHidden` / `setHideAll` (true when something changed, announced once on the bus and once to the `watch`ers that redraw the player's panels; `HudPanels` registers its `repaintFor` at install). A write for a player with no component is refused with one line rather than attaching a component mid-tick from a screen.
- **[`settings/`](settings/HudSettingsPage.java) is the HUD settings page, and it sets a PARADIGM (maintainer, 2026-09-09): a setting about a shared surface is the LIBRARY's page, and a consumer's own settings menu LAUNCHES it.** `HudSettingsPages.open(store, ref, player[, tab])` is the only way in (the MMO's Settings page has a button for it; `/zighud open` is the way in on a server with no such menu); it is deliberately NOT a registered destination, because the Server tab writes the owner file. `HudSettingsDeps` is what a consumer says about it: the `PageTheme` (frame retint), the `AdminAudience` for the Server tab (DEFAULT DENY, a throwing audience denies) and the `BackHandler`; the Mine tab needs no gate. The page is the shared `Pages/ZigForm*Row.ui` templates appended into `#Rows` and addressed by index, so a third panel costs it no markup: Mine is a hide-every-bar switch, the panels in `HudPanels.listing()` order (each panel's `Order` leaf, the World bars first as shipped), then per panel a picker over `HudSpotConfig.offeredFor(panel)` (the server's choice first; entries are `LocalizableString.fromMessageId` so each client names a spot in its own language) and a show switch, every change kept at once; Server is per panel the on-for-everyone switch (kept at once), the spot, and one field per inline leaf (`HudServerLeaf`: `Position.OffsetX` / `OffsetY`, `Columns`, `RowsPerColumn`, `Gap.AfterRow` / `Pixels`, `Cutout.Column` / `Rows`, `MinHeight`, `Color`, in that order) as a draft written by Save through `HudPanelOwnerWriter` in exactly the shape an owner would type: blank REMOVES the leaf, a whole number is `Integer.parseInt`, the colour is `HudCardLook.parse` (the one hex reader every card's file goes through) written normalised, and a value that will not read is refused NAMING the field (`settings.invalid_number` / `settings.invalid_color`) with nothing written for any panel, because Save reads every panel's draft before its first write. **What each tab lists is a PURE plan** (`HudSettingsRows.mine(prefs, panelIds)` / `server(panelIds, panels)`: an ordered `Row` list the page appends through its `appendHeader` / `appendToggle` / `appendDropdown` / `appendField` / `appendNote` helpers, the row-id prefixes living on the plan), because the engine's `UICommandBuilder` cannot be stood up in a unit JVM: `HudSettingsRowsTest` holds each tab's control set (Mine carries NO field: a player picks a spot and nothing more), `HudServerLeafTest` each field's draft-to-leaf mapping, its refusal and what it opens with (a stated `0` shows as `0`, since that is how an owner switches a band or a cut off and a blank would remove it), `HudSettingsSaveTest` the file round trip through the writer and the fold. Every control speaks ONE event shape (`HudSettingsEventData`: `Action`, `Tab`, `Field`, `@Value`); a tab switch reopens, nothing else does, so scroll survives every edit. Document `Pages/ZigHudSettingsPage.ui`.
- **[`command/`](command/ZigHudCommand.java) is `/zighud`**: `open`, `place --panel=<id> --placement=<id|server> [--player=]`, `hide` / `show [--panel=<id|all>] [--player=]`, and the owner verb `default --panel=<id> --placement=<id|server>` (writes the same owner file the page writes, through the same writer, console-capable). The family sits in the engine's adventurer group so every player holds its own verbs (the MMO's page-opener commands do the same); `default` sits in the world-editor group and otherwise needs its engine-derived node. Every line is a key in `ziggfreedcommon.hud.lang` (`HudMessages`, prefix `ziggfreedcommon.hud.`, nine locales), shared with the page and with the shipped placements' and panels' `LabelKey`s; a panel or a spot is named by the nested `Message` its own file answers, never a server string.
- **Consumers**: this library's own `objectives/hud/TrackedQuestHud` (zc-objectives), the MMO's `AbilityCooldownHud`, and RpgStations' `StationSummaryHud` extend `KeyedCustomHud` directly. An event-driven HUD returns `0` from `updateIntervalMs()` and folds its own bursts through [`RepaintCoalescer`](RepaintCoalescer.java). `aliveWorldOf(PlayerRef)` is the executor such a HUD hands the coalescer.
- **[`panel/`](panel/CLAUDE.md)** - the shared HUD panels built on this base (a PANEL holds ROWS, sits at a SPOT and wears a CARD's look; ids `Activity_Ledger` / `World_Bars` and `Top_Left` / `Top_Right` / `Bottom_Left`): two panels, rows created on demand by `HudPanels.moved` / `HudPanels.itemMoved` and dressed by the reporting mod's `HudRowDisplay`, the `HudBarReading` a value's move hands over for its fill, the `HudRows` store as an optional per-row override, the `HudPanels` store for each panel and the `HudSpots` store for the spots they can sit at, resolved per player through `HudSpot` with the pick above. See its router.
- **[`card/`](card/CLAUDE.md)** - the ONE look every HUD card on this base is drawn in (maintainer, 2026-09-10): `HudCardAsset` at `Server/ZiggfreedCommon/HudCards/Default.json` (owner layer `mods/ziggfreedcommon/hud-cards.json`), one `Color` hex MULTIPLIED over the card's shipped frame through `UiRetint.retintColor`, its last two digits a transparency when eight are written (`#ffffffb8` is the shipped card at about 72 percent); the identity `#ffffffff` pushes nothing. `HudCardLook` is the pure arithmetic (parse, `authored` with its one warn-once for a malformed value, `resolve(own, shared)`, `cardColor()`, `opacity()`, `dimmed`). Each card folds its own leaf over the shared record: the bar panels through the spot's and the panel's `Color` in `HudSpot`, the tracker through `TrackedQuestHudDeps.color`, RPG Stations' summary through its `SummaryHud.Color`; the bar dressing follows the card's opacity on its own (`panel/HudBarDressing`). See its router.
- **Conventions**: `@Nonnull`/`@Nullable`; the guarded `warn(...)` in `KeyedCustomHud` is local (this jar's other primitives each guard their own `CommonLog.LOGGER` call inline), the rest of the package logs through `util/SafeLog`; no product vocabulary; no em-dashes.
