# ui/hud/bar/ - the shared progress-bar HUD

Router for `com.ziggfreed.common.ui.hud.bar`. A minimal, semi-transparent stack of up to four bars any mod drives with ASSETS and one registered reading; the library owns every mechanical part and knows nothing about what a value measures. The parent [`ui/hud/`](../CLAUDE.md) router holds the `KeyedCustomHud` base this builds on.

- **[`HudBarAsset`](HudBarAsset.java) is a bar** (Pattern A, the codec IS the schema, PascalCase, every leaf nullable and inheriting under `Parent`), one file per bar at `Server/ZiggfreedCommon/HudBars/<id>.json`: `Source` (an opaque `namespace:local` id this library NEVER interprets; `sourceNamespace()` is the lower-cased half before the colon, `sourceLocalId()` the half after), `LabelKey` (resolved client-side through `i18n/ContentKeys`, a full id passing through), `Icon` (the shared `IconSpec` group), `Color` (a six-digit hex fill), `Order` (lower draws higher), `LingerMs` (how long the bar stays after its last move), `Enabled`. Each getter answers the documented default for an unauthored leaf. **The library ships no bars**; every entry is a consumer's, and a consumer that adds a value ships a file, never Java. Fold: [`HudBarConfig`](HudBarConfig.java) (`AbstractKeyedAssetConfig`, plus `bySource(sourceId)`, the index the panel reads on every change - enabled bars only, rebuilt after any merge, two bars naming one source resolving by `Order` then id); owner layer `mods/ziggfreedcommon/hud-bars.json` through [`HudBarOwnerLayers`](HudBarOwnerLayers.java) + `OwnerLayerReader`.
- **[`HudBarPanelAsset`](HudBarPanelAsset.java) is the panel** at `Server/ZiggfreedCommon/HudBarPanels/<id>.json`: `Enabled`, a nested `Position` group (`Preset` from the closed `HudPosition` roster as an editor dropdown, `OffsetX`, `OffsetY`), `MaxVisible` (held to the document's `MAX_SLOTS` of 4). The library ships `Default.json` (on, TopLeft (16, 216), the left column over the mob inspector card, four bars); a consumer's same-id file wins by pack order and `mods/ziggfreedcommon/hud-bar-panels.json` wins over both. [`HudBarPanelConfig`](HudBarPanelConfig.java)`.current()` always answers (the all-defaults panel before anything loads). `DEFAULT_POSITION` is the one place the default corner is written.
- **[`HudBarSource`](HudBarSource.java) is the value seam** and [`HudBarSources`](HudBarSources.java) its registry, one source per namespace (`register(namespace, source)`, case-folded). The panel splits a bar's `Source` at its colon, finds the namespace here, and hands the source ONLY the local half; the source answers a `Reading(current, maximum)` (`fraction()` held to 0..1, a non-positive maximum reading full) or null for "nothing to draw" (no data yet, an id it does not know, a player who switched the display off). Asked on the player's world thread at paint time, only for a live bar, guarded (a throw costs that bar's paint, logged at fine). A namespace nothing registered is reported ONCE at warn and drawn as nothing. Consumers today: the MMO's `skill/MmoHudBarSource` under `mmoskilltree` (a skill's XP into its level); rpg-stations would author a bar with `"Source": "rpgstations:<its own id>"`, register under `rpgstations`, and call `HudBars.moved` from its work loop, with no change here.
- **[`HudBars`](HudBars.java) is the way in**: `install(plugin)` (attach at `PlayerReadyEvent` LATE, detach at disconnect, live panels in `LIVE` by uuid), **`moved(playerRef, sourceId, delta)` the ONE call a consumer makes** (finds the enabled bar for the source, records the gain, paints; false for no panel / no bar), `repaintAllOnline()` and `refreshPositionForAllOnline()` for the two asset load events, which `FrameworkAssetRegistrar` wires so a reload lands live.
- **[`HudBarHud`](HudBarHud.java) draws it**: a `KeyedCustomHud` (key `ziggfreedcommon:hud_bars`, document `Hud/ZigHudBars.ui`, root `#ZigHudBarsPanel`, content-sized, width 320) whose per-player state is one `LiveBar` (gain since it came up, last move, expiry) per bar id. `moved` records and asks for a paint; paints fold per tick through `RepaintCoalescer` and are held to one per `REPAINT_INTERVAL_MS` (100) with an in-window change deferred to the window's end, never dropped; ONE sweep is armed at the earliest expiry and re-arms itself while anything is live, so a bar goes away on time with no tick. `collectLive` drops expired / deleted / disabled bars and reads the rest through `HudBarSources`; `choose(rows, maxVisible)` (pure, tested) takes the most recently moved bars up to the count and draws them in authored `Order` then id, so the stack never reshuffles; `paint` addresses every slot (`#ZigBar0..3`, each `#Line` with the `IconRenderer` pair + `#IcoGap` + `#Label` + `#Gain`, over `#Track #Fill`), text on `.TextSpans` only, the fill an `Anchor` width push (`TRACK_INNER_WIDTH_PX` 294 must match the document), the colour a `UiRetint.retintColor`, the gain a typed numeric param on `ziggfreedcommon.ui.hud.bar.gain` (`+{0, number}`; a whole number binds as a long). The panel hides when nothing is showing or the owner disabled it.
- **Geometry lives once in the `.ui`** (`@RowAnchor`, `@LineAnchor`, `@IconAnchor`, `@GainAnchor`, `@TrackAnchor`, `@FillAnchor`) and every slot references it; the three widths the Java mirrors (panel 320, row 296, fill 294) are named in the document's header comment. Slots are positional and the count must match `HudBarPanelAsset.MAX_SLOTS`.
- **Tests**: `HudBarAssetCodecTest` (round trip, defaults, `Parent` keeps unrestated leaves, the source split, the `bySource` index over pack and owner layers), `HudBarPanelAssetTest` (the default position, leaf-by-leaf `Position`, unknown preset falls back whole, `MaxVisible` clamp, the fold always answers), `HudBarSlotsTest` (`choose` + `Reading.fraction`), `HudBarSourcesTest` (the registry). The drawing itself is packets and is validated in game (the `.ui` is not compiled).
- **Conventions**: `@Nonnull`/`@Nullable`; `util/SafeLog`; no product vocabulary anywhere in this package (no skill, no XP, no level: bars have a label, a reading and a source, nothing more); no em-dashes.
