# ui/hud/bar/ - the shared progress-bar HUD

Router for `com.ziggfreed.common.ui.hud.bar`. A minimal, semi-transparent stack of up to four rows any mod drives with one call per movement; the library creates a row on demand, dresses it from what the reporting mod says, and knows nothing about what a value measures. Nothing is authored for a row to appear. The parent [`ui/hud/`](../CLAUDE.md) router holds the `KeyedCustomHud` base this builds on.

- **Two parts to a row, orthogonal, never a Kind/Type enum.** A row DRAWS A FILL when it has a reading to draw (its id is a `namespace:local` value id and the `HudBarSource` registered under that namespace answers), and it CARRIES AN ITEM when it was moved as one (`HudBars.itemMoved`; its row id is `item:<ItemId>`, `HudBars.itemRowId`). A fill row is two lines (name + gain over the fill); an item row is the first line alone (the item's own icon and name, the running count beside it, `#Track` hidden). Both share one panel and one `MaxVisible`; fill rows sort above item rows.
- **[`HudBarDisplay`](HudBarDisplay.java) is what a consumer says about a row** beside every move: `label` (a client-resolved `Message`), `icon` (the shared `IconSpec`), `color`, `order`, `lingerMs`, every part nullable; `over(under)` folds two part by part; `forItem(itemId)` is the display an item derives for itself (its name through `i18n/NativeNames.itemNameMsg`, the same two-tier probe every item name in the family uses, so a vanilla item, a pack item and an id never seen before all read; its own generated icon). **[`HudBarLook`](HudBarLook.java) is the settled look** the panel paints from: `resolve(id, override, display)` folds the authored override (if any) OVER the display OVER the defaults (`DEFAULT_COLOR` `#7fb2e0`, `DEFAULT_ORDER` 1000, `DEFAULT_LINGER_MS` 5000); a row with no name from either layer shows its own id.
- **[`HudBarAsset`](HudBarAsset.java) is an OPTIONAL override, never a requirement** (Pattern A, PascalCase, every leaf nullable and inheriting under `Parent`), one file per override at `Server/ZiggfreedCommon/HudBars/<id>.json`: `Source` (the row it retunes, exactly as the owning mod moves it: `mymod:wood` or `item:Wood_Plank`), `LabelKey`, `Icon`, `Color`, `Order`, `LingerMs`, `Enabled`. Every getter answers null for an unauthored leaf (so it changes nothing); `display()` folds the file into a `HudBarDisplay`; `Enabled: false` keeps the row off the panel and makes `HudBars.moved` answer false. **The library ships none, and no consumer needs to.** Fold: [`HudBarConfig`](HudBarConfig.java) (`AbstractKeyedAssetConfig`, plus `bySource(rowId)`, the index the panel reads on every move and paint - every override naming a row, switched off or not, two naming one row resolving by `Order` then id); owner layer `mods/ziggfreedcommon/hud-bars.json` through [`HudBarOwnerLayers`](HudBarOwnerLayers.java) + `OwnerLayerReader` (an entry under an id no pack authored stands on its own, so an owner retunes any row by naming it in `Source`).
- **[`HudBarPanelAsset`](HudBarPanelAsset.java) is the panel** at `Server/ZiggfreedCommon/HudBarPanels/<id>.json`: `Enabled`, a nested `Position` group (`Preset` from the closed `HudPosition` roster as an editor dropdown, `OffsetX`, `OffsetY`), `MaxVisible` (held to the document's `MAX_SLOTS` of 4, shared across both row kinds). The library ships `Default.json` (on, TopLeft (16, 216), the left column over the mob inspector card, four rows); a consumer's same-id file wins by pack order and `mods/ziggfreedcommon/hud-bar-panels.json` wins over both. [`HudBarPanelConfig`](HudBarPanelConfig.java)`.current()` always answers (the all-defaults panel before anything loads). `DEFAULT_POSITION` is the one place the default corner is written.
- **[`HudBarSource`](HudBarSource.java) is the fill seam** and [`HudBarSources`](HudBarSources.java) its registry, one source per namespace (`register(namespace, source)`, case-folded; `namespaceOf` / `localIdOf` split a value id at its first colon). The panel finds the namespace of a fill row's id here and hands the source ONLY the local half; the source answers a `Reading(current, maximum)` (`fraction()` held to 0..1, a non-positive maximum reading full) or null for "nothing to draw" (no data yet, an id it does not know, a player who switched the display off), and a fill row whose source declines and carries no item is kept live but not drawn. Asked on the player's world thread at paint time, only for a live row, guarded (a throw costs that row's fill, logged at fine). A namespace nothing registered is reported ONCE at warn and the row draws no fill; an item row never asks. Consumers today: the MMO's `skill/MmoHudBarSource` under `mmoskilltree` (a skill's XP into its level, its display derived from its skill registry: the skill's own name, icon, category colour and category order); rpg-stations calls `HudBars.itemMoved` for every produced or retrieved stack and authors nothing.
- **[`HudBars`](HudBars.java) is the way in**: `install(plugin)` (attach at `PlayerReadyEvent` LATE, detach at disconnect, live panels in `LIVE` by uuid), **`moved(playerRef, sourceId, delta, display)` for a value** and **`itemMoved(playerRef, itemId, quantity)` for an item** (each creates the row on first sight, records the gain, paints; false for no panel or a row an override switched off), `repaintAllOnline()` and `refreshPositionForAllOnline()` for the two asset load events, which `FrameworkAssetRegistrar` wires so a reload lands live.
- **[`HudBarHud`](HudBarHud.java) draws it**: a `KeyedCustomHud` (key `ziggfreedcommon:hud_bars`, document `Hud/ZigHudBars.ui`, root `#ZigHudBarsPanel`, content-sized, width 320) whose per-player state is one `LiveBar` (the value id and item it was moved with, the display its last move came with, gain since it came up, last move, expiry) per row id. `moved` records and asks for a paint; paints fold per tick through `RepaintCoalescer` and are held to one per `REPAINT_INTERVAL_MS` (100) with an in-window change deferred to the window's end, never dropped; ONE sweep is armed at the earliest expiry and re-arms itself while anything is live, so a row goes away on time with no tick. `collectLive` drops expired rows and rows an override switched off, resolves each row's `HudBarLook` (override over display) and reads a fill row's reading through `HudBarSources`; `choose(rows, maxVisible)` (pure, tested) takes the most recently moved rows of either kind up to the count and draws them in `STACK_ORDER` (fill rows first, then order, then id), so the stack never reshuffles; `paint` addresses every slot (`#ZigBar0..3`, each `#Line` with the `IconRenderer` pair + `#IcoGap` + `#Label` + `#Gain`, over `#Track #Fill`), text on `.TextSpans` only, `#Track.Visible` per row, the fill an `Anchor` width push (`TRACK_INNER_WIDTH_PX` 294 must match the document), the colour a `UiRetint.retintColor`, the gain a typed numeric param on `ziggfreedcommon.ui.hud.bar.gain` (`+{0, number}`; a whole number binds as a long; an item row's running count rides the same key). The panel hides when nothing is showing or the owner disabled it.
- **Geometry lives once in the `.ui`** (`@RowAnchor`, `@LineAnchor`, `@IconAnchor`, `@GainAnchor`, `@TrackAnchor`, `@FillAnchor`) and every slot references it; the three widths the Java mirrors (panel 320, row 296, fill 294) are named in the document's header comment. Slots are positional and the count must match `HudBarPanelAsset.MAX_SLOTS`.
- **Tests**: `HudBarAssetCodecTest` (round trip, an empty file overrides nothing, `Parent` keeps unrestated leaves, `display()`, the `bySource` index over pack and owner layers incl. a switched-off override, an item row's override, and an owner entry with no pack parent), `HudBarPanelAssetTest` (the default position, leaf-by-leaf `Position`, unknown preset falls back whole, `MaxVisible` clamp, the fold always answers), `HudBarSlotsTest` (`choose`: fill rows above item rows, one slot count across both kinds, order then id, `Reading.fraction`), `HudBarSourcesTest` (the registry + the value-id split), `HudBarLookTest` (a row with nothing authored reads its mod's display, an override wins leaf by leaf, an item nobody authored dresses its own row, and the paint draws a fill row as two lines and an item row as one). The drawing itself is packets and is validated in game (the `.ui` is not compiled).
- **Conventions**: `@Nonnull`/`@Nullable`; `util/SafeLog`; no product vocabulary anywhere in this package (no skill, no XP, no level: a row has a label, a reading and an item, nothing more - an item is an engine concept); no em-dashes.
