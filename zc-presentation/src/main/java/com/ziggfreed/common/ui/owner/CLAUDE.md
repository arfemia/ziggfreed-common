# ui/owner/ - the owner menu (/zigadmin), and the owner forms it lists

- `OwnerMenu` is the one owner menu: a mod opens its section once (`OwnerMenu.section`) and adds tiles (`OwnerTile.screen` opens a screen, `OwnerTile.action` acts in place and answers a status line), and every owner form is a tile with no code. A consumer's own admin command opens the same menu with its section first (`OwnerMenu.open(..., owner)`, or a page class extending `OwnerMenuPage` its Back buttons open); never a second menu. It is not a registered destination.
- Who sees any owner screen is zc-core's `owner/OwnerAudience` (a consumer fills it once; default, `/zigadmin`'s node), asked on open and on every event but Close through the one `OwnerPageGuard.stillAllowed` (a refusal is said and closes the page), which the menu, the form and the library's owner pages each call with their own audience; a tile's `shownWhen` only narrows it.
- An owner form is `ui/form/OwnerFormAsset` (`Server/ZiggfreedCommon/OwnerForms/<Id>.json`, owner file `owner-forms.json`), drawn by the one `OwnerFormPage`: each setting is the kit's owner leaf row (`ui/kit/FormLeafPainter`, `Pages/ZigFormLeafRow.ui`), its typed value read by `SettingsForm`'s own parse and written by `OwnerFormWrite` through the file's `OwnerFileBinding` (zc-core `owner/`), never a path built from a form's or a player's text. A new form needs only its file and, for a file no mod has bound yet, one binding line in the bootstrap of the mod that reads the file.
- A form is one of two shapes, told apart by its fields, never a mode: settings (one file's leaves, under `Entry` in a keyed file), or Entries (an `Entries` group: an id-keyed file edited one entry at a time). An Entries form lists through `OwnerFormEntries` (its `Having` path, its `Gate` read on the library's hide axis, `FeatureLift`, so a Pro or mod-gated entry hides as players' content does), opens one entry as a settings plan (`OwnerFormPlan.read(form, id)`, paths inside the entry) and writes only through the store's own entry writer (`OwnerFileBinding.putEntry`/`removeEntry`, over `AbstractKeyedAssetConfig.putOwnerLeaves`, which holds a typed id to the store's id pattern first). One engine and one page: never a second form page, writer or gate.
- A form may name what its file's mod registered in code: an `Audit` (`OwnerFormAudits`, that mod's own content audit, counted on the form) and a `Preview` (`OwnerFormPreviews`, a line under the settings sent again after every change, so it follows what is typed). A file whose shape a form's paths cannot address names a `View` on its binding (zc-core `owner/`), never a second page.
- A setting's `Kind` is the closed list in `OwnerFormKind` (`Signed` is a number of any sign, read by `OwnerFormWrite`), and a field's own `Requires` narrows who of the owners sees and writes that one setting (`OwnerForms.fieldShownTo`, asked at draw and again at Save and Reset), the one way to keep a setting to fewer owners than the form; never a second gate. A console command an owner writes (the boost start command, or a consumer's own) is kept to the server's operators by `{"Factors": [{"Factor": "hytale:operator", "Min": 1}]}` (zc-core `owner/ServerOperators`, the game's own operator status), never by a permission node; a section shows its heading and note only with a setting the viewer sees.
- A form reaches a `$` key only as its file's one reserved setting, which the binding declares (zc-core `OwnerFileBinding.Builder.reserved`): its `Path` is the key's own (`$MenuTab.Show`), it reads and writes from the file's root, and on a form of the Entries shape it is drawn above the list (`OwnerFormPlan.read(form, null, ...)` holds only it there; `OwnerFormPaint.paintEntries` with that plan), saved and reset there. The binding refuses any other `$` key; never widen a form past that.
- Help is a topic on a tile (`OwnerHelp`: a mod's key prefix, its title, subtitle and four parts): a tile carries its own (`OwnerTile.help`) and a mod gives one to a tile it does not own by id (`OwnerMenu.help`, a form's tile being `form:<Id>`). The menu's Help button shows only the tiles carrying one; a press there opens `OwnerHelpPage`, whose Open presses the tile, and a consumer's screen opens a tile's help with `OwnerHelp.open`. Never a help page of a mod's own.
- The menu, the form and the help page take the menu theme's paint through `ZigMenu.appendThemed`, the seam every framed page shares (a consumer's `MenuDeps.theme`, else the palette), never a theme of their own.
- The menu, the form and the help page paint only through `OwnerMenuPaint`, `OwnerFormPaint` and `OwnerHelpPaint`, which `KitSelectorsTest` walks; a new selector goes there.
