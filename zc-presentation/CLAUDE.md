# zc-presentation

- A `ui/` primitive never imports dialogue, instance or progression content: domain surfaces depend on presentation, never the reverse.
- A primitive that paints a consumer's words takes pre-built `Message`s; only a widget the library ships whole labels itself from `ziggfreedcommon.ui.lang` (the search row, the kit's own lines in `KitText`, the menu, the Settings tab, the HUD bar's loss figure).
- A `Notify` tag is the only thing that merges repeated notices: use one tag per wording, and never one tag on two notices a player must both read, since the second replaces the first.
- A feedback moment with no file does nothing, and a consumer's same-id file replaces the library default by pack order (`FeedbackMomentOverrideOrderTest`). A consumer writes a line's `Key` without its lang file's namespace (`FeedbackMomentAsset`'s javadoc is the authoring reference); the library's own moment files write it in full, so it never resolves through a consumer's catalogue: this module's under `ziggfreedcommon.feedback.`, each one shipped in the en-US `ziggfreedcommon.feedback.lang` (`ShippedFeedbackMomentsTest`).
- A page writes a `.Text` property only through `UiText` (`TextSinkGoesThroughUiTextTest`): any `Message` other than a translation in that slot disconnects the client, and `UiText` flattens a parameterized or composite one (server language, bare `{N}` only). A Label takes `.TextSpans` instead.
- A binding carrying a live element value uses an `@`-prefixed key (`"@SearchInput"`), declared the same way on the receiving codec; `SettingsUiUtil.directive` refuses a bare one.
- Never bind a search field per keystroke (a rebuild steals focus); use `ZigSearchRow`, whose `carry` puts the live text on your other bindings.
- `Pages/ZigDetailLine.ui` is the one detail line (`DetailPainter` paints it). `Pages/ZigSelectRow.ui` is an older list row no library page uses (the MMO's `MmoHubPage` still does): a new list is the kit's `LedgerPainter` (below). Their sizes live only in those files. Each ships a hidden picture slot (`#LineIconSlot`, `#RowIconSlot`) that a page fills through `ui/icon/IconRenderer`, setting the slot's `.Visible` from its return; a page that paints none leaves it hidden, and so does a section heading.
- Register a `ui/route/Destination` type in `setup()`, before assets load: an unknown `Type` fails the read, naming the file.
- `UiDocumentSyntaxTest` checks every zc module's documents as one merged tree (ids, braces, alignments, cross-document references; the id rule is in `.claude/rules/ui.md`); this module's `build.gradle` declares those documents as test inputs, so an edit anywhere reruns it.
- The shared menu (its frame, rail, tabs and palette) is `ui/menu/`; its router is `ui/menu/CLAUDE.md`.
- A player's own settings are `settings/` (the record, the facade, the owner's defaults and locks) and the Settings tab is `settings/page/`; their router is `settings/CLAUDE.md`.
- `Common/ZigCards.ui` holds the family's shared card shapes: structure from the admin hub, type from the game's World Event pages. A tile's ids and size are pinned by `ZigCardsDocumentTest`, since other pages paint by them.
- The settings form's styles, its row and its toggle are named in `Common/ZigForm.ui` (`$ZM = "../Common/ZigForm.ui"` from `Pages/`), which the five `Pages/ZigForm*Row.ui` rows read: a page that wants the same look imports those names, never a copy.
- `ui/page/` is the composed page kit: a page's body is its `Sections`, each entry one registered part named by the group it writes (`PageParts.of(<page>)`, filled from a module's `*Bootstrap` before any page decodes; a group no part is named for is kept on the `PageSection` for the page's audit to warn on once). A `PagePart` brings its codec, its template and its painter, and a page's plan names each section's part (`PartPlan`) for `PagePainter`. The shared part assets live here too: `PlateComposition` (one piece under `Parent`, `whole`), `BannerAsset`, `LinkAsset` (a destination no mod registers is left out). A hero or a banner's plate paints through `ui/kit/PlatePainter`, its plan's records implementing `Plate`.
- `ui/kit/` is the family's one list, detail-page and tile vocabulary: a reader builds its pure records (`LedgerModel`, `DetailView`, the tiles) and the painters (`LedgerPainter`, `DetailPainter`, `TilePainter`, ...) append the templates, spell their child ids (never a page, `ui.md`), bind, and swap the named state styles (`ZigStyles`, `Value.ref` into `Common/ZigStyles.ui`); a page never pushes a colour for a row, segment, button or state word itself. A module adds sections to another's list only through `LedgerContributions`.
- A kit picture is a `Picture` (its javadoc is the reference) drawn into an `AssetImage #IcoTex` (`@ZigPicture`) through `IconRenderer.applyPlainIcon`, never an `ItemIcon`; only a reward line keeps an item's own tooltip, through `DetailLine.reward`, and a reward card (`Pages/ZigRewardCard.ui`, a `DetailBlock.cards` block, `TilePainter.rewardCards`) draws an item on its quality's slot art (an `AssetImage` of the quality's `SlotTexture` under an `ItemSlot` with no quality background, inside an `ItemSlotButton` whose `.ItemId` the painter sets as vanilla's barter page does), the quality being the one the line names (`DetailLine.quality`) else the item's own, its word, colour, rank and slot art read through `ui/icon/ItemQualityLook`; any other card shows only the word of a quality its line names.
- A kit list row grows with its title (two lines at most, `@ZigLedgerTitleStyle`) and the standard row with its meta line too: its templates fix no height, `RowSize.height()` is a row's least height, and a list host is sized to scroll, never to a count of rows.
- A page toast's rank (`ToastSpec.PRIORITY_PROGRESS`, `PRIORITY_EARNED`, `PRIORITY_CLAIM`) decides the page's one toast slot as `ToastStore`'s javadoc says (`outranks`, `requeues`, the per-player queue): the slot and its queue change only together, in one `ToastStore` step.
- A banner goes only through `feedback/EventTitles` (its javadoc covers the styles and the sound), the one caller of the engine's `EventTitleUtil`, and an in-place update of an open page only through `ToastablePage.writeInPlace`, the one caller of `PageManager.updateLegacyCustomPage`: the wiring root's `EngineSeamHygieneTest` fails a second caller of either.
