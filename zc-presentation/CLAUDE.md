# zc-presentation

- A `ui/` primitive never imports dialogue, instance or progression content: domain surfaces depend on presentation, never the reverse.
- A primitive that paints a consumer's words takes pre-built `Message`s; only a widget the library ships whole (the search row) labels itself from `ziggfreedcommon.ui.lang`.
- A `Notify` tag is the only thing that merges repeated notices: use one tag per wording, and never one tag on two notices a player must both read, since the second replaces the first.
- A feedback moment with no file does nothing, and a consumer's same-id file replaces the library default by pack order (`FeedbackMomentOverrideOrderTest`). Author a line's `Key` without a namespace; `FeedbackMomentAsset`'s javadoc is the authoring reference.
- Every shipped moment line needs its key in the en-US `ziggfreedcommon.feedback.lang` (`ShippedFeedbackMomentsTest`).
- A page writes a `.Text` property only through `UiText` (`TextSinkGoesThroughUiTextTest`): any `Message` other than a translation in that slot disconnects the client.
- A binding carrying a live element value uses an `@`-prefixed key (`"@SearchInput"`), declared the same way on the receiving codec; `SettingsUiUtil.directive` refuses a bare one.
- Never bind a search field per keystroke (a rebuild steals focus); use `ZigSearchRow`, whose `carry` puts the live text on your other bindings.
- `Pages/ZigSelectRow.ui` and `Pages/ZigDetailLine.ui` are the one list row and the one detail line for every page in the family; their sizes live only in those files. Each ships a hidden picture slot (`#RowIconSlot`, `#LineIconSlot`) that a page fills through `ui/icon/IconRenderer`, setting the slot's `.Visible` from its return; a page that paints none leaves it hidden, and so does a section heading.
- Register a `ui/route/Destination` type in `setup()`, before assets load: an unknown `Type` fails the read, naming the file.
- `UiDocumentSyntaxTest` checks every zc module's documents as one merged tree (ids, braces, alignments, cross-document references; the id rule is in the zc root); this module's `build.gradle` declares those documents as test inputs, so an edit anywhere reruns it.
- The shared menu is `ui/menu/`. A page on it sits in `$F.@ZigMenuFrame` (its columns go in `#Content` after `#MenuRail`), appends through `ZigMenu.appendThemed`, paints the rail only through `ZigMenu.paint`, keeps the `MenuRail` it returns, declares the `Menu` key (`ZigMenu.EVENT_KEY`) on its codec, and calls `MenuRail.handle` before it reads its own action, since a rail click carries none.
- The library's tabs (`MenuSlot`: Almanac, Quests, Achievements, Records, Reputation, Settings; the Almanac first by ruling M484) are filled by their owners' bootstraps and a consumer adds one section through `ZigMenu.consumer`; `/ziggui` lands on the consumer's landing, else the first tab that shows. A tab may give a second line (`MenuEntry.withSubline`, a `MenuSubline` asked on every paint): `ZigMenu` then shows the row's hidden `#SubLine` and pushes the row to `MenuFrame.TALL_ROW_HEIGHT` as whole Anchors; a tab without one never addresses it. The frame and rail read every colour and texture from ONE `Palette` (`MenuDeps.palette`, default `MenuPalette.defaults()`; with no consumer `theme`, `MenuFrameRetint` paints the frame from it), and no menu colour is spelled anywhere else: `ZigMenuDocumentsTest` holds `ZigFrames.ui` and `Pages/ZigMenuTab.ui` to the default palette and `MenuFrame`'s sizes, and `MenuPaletteTest` holds the default to 4.5:1 (3:1 for the selected tab's bar), judging a translucent fill over what it covers. The rail is vanilla's own (pane, row, section label, rule, vertical separator): a document spells an alpha colour `#rrggbb(a)` and Java `#rrggbbaa` (`MenuPalette.fromMarkup`), every fill goes out as a typed `PatchStyle` through `UiRetint.fill`, and the selected tab's gradient mask is authored in the row, since no Java push sets it.
- A player's own settings are `settings/` (the record, the facade, the owner's defaults and locks) and the Settings tab is `settings/page/`; their router is `settings/CLAUDE.md`.
- `Common/ZigCards.ui` holds the family's shared card shapes: structure from the admin hub, type from the game's World Event pages. A tile's ids and size are pinned by `ZigCardsDocumentTest`, since other pages paint by them.
- `ui/kit/` is the family's one list, detail-page and tile vocabulary: a reader builds its pure records (`LedgerModel`, `DetailView`, the tiles) and the painters (`LedgerPainter`, `DetailPainter`, `TilePainter`, ...) append the templates, spell their child ids, bind, and swap the named state styles (`ZigStyles`, `Value.ref` into `Common/ZigStyles.ui`); a page never spells a template's ids or pushes a colour for a row, segment, button or state word itself. A module adds sections to another's list only through `LedgerContributions`.
- A kit picture is an `AssetImage #IcoTex` (`@ZigPicture`) painted through `IconRenderer.applyPlainIcon` (an item draws as its own icon texture, `ItemIds.iconPath`), never an `ItemIcon`; only a reward line whose item tooltip is the point keeps its `ItemGrid` (`Picture.tooltipItem`); a picture that only stands for a reward (a wallet's, a reputation's) draws plain with the reward's name as its tooltip (`DetailLine.reward`).
- A kit list row grows with its title (two lines at most, `@ZigLedgerTitleStyle`): its templates fix no height, `RowSize.height()` is a row's least height, and a list host is sized to scroll, never to a count of rows.
