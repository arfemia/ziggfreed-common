# instance/metadata/ - the generic round-telemetry envelope

Router for `instance/metadata/`. A tiny, dependency-free, PURE-DATA integration envelope a consumer fires alongside its own native outbound event (e.g. Kweebec's `RoundCompletedEvent`) so another mod can read a finished round's shape without depending on the producer's internal types. No engine API, no i18n, no hardcoded ids - the consumer supplies every value (id/mode/preset are free strings, difficulty is the consumer's numeric scale).

- **[`RoundMetadata`](RoundMetadata.java)** - the immutable record `{ String modId, @Nullable String modeId, @Nullable String presetId, int difficulty, int playerCount, long durationSeconds, @Nullable String resultKind }`. `modId` is the only required field (a null is coerced to `""` so the envelope never carries a null producer id); optional string fields are `@Nullable`. Build it via the canonical all-args constructor, the `of(...)` factory, or the fluent `builder(modId).modeId(..).difficulty(..)...build()`. Pure logic, no logging.
- **[`InstanceRoundCompletedEvent`](InstanceRoundCompletedEvent.java)** - the ONE generic "a round is over" moment, a POJO `implements IEvent<Void>` carrying `{ RoundMetadata metadata, List<UUID> participants, List<UUID> winners }` (both lists copied at construction and handed out unmodifiable). `winners` IS the outcome expressed as people: equal to `participants` on a co-op win, the winning team on PvP, EMPTY on a loss or an abort - which is what `isWin()` reads, so no listener has to interpret a consumer's own outcome names. `metadata.resultKind()` is expected to be a `ResultKind` name (`WIN`/`LOSS`/`DRAW`/`ABORT`); build it with the `Builder.resultKind(ResultKind)` overload and it is by construction, while the String overload stays for a consumer whose outcome is genuinely none of the four.
- **[`InstanceRounds`](InstanceRounds.java)** - `fireCompleted(event)`: resolve the dispatcher, guard on `hasListener()` (silent no-op with zero listeners), dispatch synchronously on the calling thread, whole body guarded through `SafeLog` and never propagating. **Fire on the instance world thread** - a listener runs inside the fire, so it can resolve a player straight away and hop with `world.execute` if it needs a `Store` elsewhere. A consumer keeps firing its own richer event beside this one.
- **Who listens today**: zc-objectives' `ZigInstanceRoundProducer` (`INSTANCE_ROUND_ENDED` per participant, `INSTANCE_ROUND_WON` per winner). The edge is one-way - this package announces and never asks anything about progression.
