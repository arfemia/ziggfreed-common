# instance/leaderboard/

- A bucket key is the consumer's own string, except `*`, reserved for the synthesized All tab, and `total_points`, reserved for the total counter and never a consumer stat key.
- `Leaderboard.record` mutates in memory and schedules a debounced off-thread atomic flush (on the server's scheduler 3 seconds later, or on the `Executor` a test hands the constructor); an unreadable file falls back to its `.bak`. `flushNow` writes only what changed since the last write, one write at a time (the engine's atomic writer shares one `.tmp` per file), and a failed write keeps the change for the next. The library's boards are written once more at its stop (`InstanceBootstrap.shutdown`, from the wiring root's `shutdown()`); a consumer's own board writes at its own stop by calling `flushNow`.
- The engine's `FileUtil.writeStringAtomic` loads on Update 7 only under the engine's log manager: a test that reads back a file a board wrote is tagged `engine-items` (those methods alone), and the untagged `LeaderboardStopTest.aWriteThatCannotHappenNeverReachesTheCaller` proves a failed write never reaches the caller.
- The encounter board (`encounter-leaderboard.json`) lives in `mods/ziggfreedcommon/` (`EncounterOwnerLayers.directory()`) and is frozen: nothing writes it. A boss fight's records are the stat store's encounter stats on the stat board, keyed by `EncounterLeaderboardListener.bucketFor` (the binding row's `Bucket`; a row naming none keeps no records), and the old file's rows import once into both (zc-stats `encounter/EncounterBoardImport`); the file stays for an older build rolled back to. Before 2.2.0 it sat in the library's data folder (`mods/Ziggfreed_ZiggfreedCommon/`): `Leaderboard.init(dir, oldDir)` moves a board once through zc-core's `util/DataFileMove`, and a move that fails keeps reading and writing the old file that session.
- `LeaderboardPage` keeps no state across events: every binding round-trips the full state, and every exit path sends a response.
- A `LeaderboardLayoutAsset` difficulty tab's `Id` is the bucket prefix and must equal the preset id on a round's board; a boss fight's layout is named after its bucket, and its tab ids are the difficulty labels and party sizes its records are split by, which name a split fight's Boss Fights tab.
- With two axes a page names a selection's bucket through its deps (`LeaderboardPageDeps.bucketKey`; `UNDERSCORE` unless the board composes its own), and a page never hard-wires a separator.
- `EncounterBoards` maps recorded fight keys to binding rows: a row's split parses the keys it owns, and `fightTabs` makes one Boss Fights tab per recorded key, its key built by the same `bucketFor`, so a tab reads exactly the lines a defeat writes.
- The page is built from zc-presentation's kit and paints every line on a `.TextSpans`, so a `LeaderboardScreenMessages` line may carry parameters; an unnamed tab shows its recorded value as raw text. The one exception is a column header's tooltip, a `.TooltipText` that prints a parameter as written: it is the column label's key with `.tip` added when the server ships that key (`LangCatalog.has`), else `sortTip()`, always a bare translation. The module's own words live in `ziggfreedcommon.leaderboard.lang`.
- A first row whose tabs each bring their own columns (`LeaderboardPageDeps.primaryTabsCarryColumns`: a stat board's sections, its boss fights) is view tabs (`ViewTabPainter`, a picture from `withPrimaryPictures`); every other row, the periods and party sizes and Kweebec's difficulties, is two-line segments (`SegmentPainter.appendTwoLine`, `@ZigSegmentTwoLine`, so a long period name wraps instead of trimming), and both rows wrap. Column headers wrap onto two lines too (`@HeadStyle`, 44 tall). Rows and headers share their widths (Rank 72, Player FlexWeight 2, each figure FlexWeight 1), so change a row template and its header together. `#YouStrip` shows the viewer's place and their figure per column (`@ZigStatTwoLine`, `StatPainter`, captions on two lines) or, with no place, `yourRankNone` and the tab's `withPrimaryHints` line, which the empty state (`EmptyStatePainter`) shows too. Every colour is a `ZigTokens` token or a `ZigStyles` named style.
- A primary tab with a split (`LeaderboardSplit`, `LeaderboardPageDeps.withSplits`, filled by `statboard/StatSplit`) adds `#SplitRow`: its choices as two-line segments (the first the tab's own columns, a choice the viewer sees no pick of hidden) and `#Pick`, a vanilla `$C.@DropdownBox` as the achievements page has it, for one thing alone. The state rides every binding as `Split` and `Pick`; the picker's binding carries no `Pick` of its own and its live value comes back under `@Pick` (`LeaderboardEventData` reads both spellings, `LeaderboardEventDataTest`). A section click clears the split, a period keeps it, and a choice other than the first, or a pick, may pin the period row to `pinnedTab` and hide it. A choice's columns are sums read as the page builds (`StatColumnDef.summing`, `valueOf`), never stored, so every cell, sort and figure reads a column through `valueOf`. A stats tab ranks by the sorted column and breaks a tie on its other columns from the left.
- `RecordsDestinations` is the `Records` destination and the shared menu's Records tab: it first lets the filled board bring the opener's numbers up to date (`RecordsBoard.opening`; a throw costs only that), then opens the board filled through `setBoard` (the stat board, `statboard/`), its first row ending in a Boss Fights link tab (`LeaderboardPageDeps.withPrimaryLink`) that opens `statboard/StatBoardBossFights` while a fight has a record, the page `/zigleaderboard encounter` opens too; the tab shows while the filled board does, or while a boss fight has a record (the boss fights then open alone).
- `LeaderboardPageDeps.menuTab` puts the page on the shared menu's rail with that tab selected (Records); null keeps the page's own frame, as Kweebec's boards do. The body lives in `Pages/ZigLeaderboardPage.ui` and `Pages/ZigLeaderboardMenuPage.ui` alike: change both together (`LeaderboardMenuDocumentTest` holds their ids one for one).
- A board's write never changes an entry's counter bag in place: it swaps in a changed copy (`LeaderboardEntry.counters` is volatile), since a flush and a page read the bag off the bucket's lock.
