# instance/leaderboard/

- A bucket key is the consumer's own string, except `*`, reserved for the synthesized All tab, and `total_points`, reserved for the total counter and never a consumer stat key.
- `Leaderboard`'s class javadoc is its write contract (a debounced atomic flush, the `.bak` fallback, one write at a time, a failed write kept for the next). The library writes its boards once more at its stop (`InstanceBootstrap.shutdown`); a consumer's own board calls `flushNow` at its own stop.
- A board's write never changes an entry's counter bag in place: it swaps in a changed copy (`LeaderboardEntry.counters` is volatile), since a flush and a page read the bag off the bucket's lock.
- The encounter board (`encounter-leaderboard.json`, `mods/ziggfreedcommon/`) is frozen: nothing writes it. A boss fight's records are the stat store's encounter stats on the stat board, keyed by `EncounterLeaderboardListener.bucketFor` (a row naming no `Bucket` keeps no records); `EncounterBoards.holds` and `splits` map those keys to binding rows and party sizes, which Records' Bosses tab reads (`statboard/StatBoardBossFights`).
- A `LeaderboardLayoutAsset` difficulty tab's `Id` is the bucket prefix and must equal the preset id on a round's board.
- With two axes a page names a selection's bucket through its deps (`LeaderboardPageDeps.bucketKey`; `UNDERSCORE` unless the board composes its own), and a page never hard-wires a separator.
- `LeaderboardPage`'s class javadoc is the page's reference (its kit build, its stateless events, its split). Every line paints on a `.TextSpans`, so a `LeaderboardScreenMessages` line may carry parameters; an unnamed tab shows its recorded value as raw text. A column's tooltip is its label key plus `.tip` when the server ships one (`columnTip`), and the module's own words live in `ziggfreedcommon.leaderboard.lang`.
- `Pages/ZigLeaderboardPage.ui` and `Pages/ZigLeaderboardMenuPage.ui` (the shared menu's frame, `LeaderboardPageDeps.menuTab`) hold one body: change both together (`LeaderboardMenuDocumentTest` holds their ids one for one). Rows and headers share the widths their comments give, so change a row template and its header together.
- A split's state rides every binding as `Split`, `Pick` and `Variant`; the picker's live value comes back under `@Pick` (`LeaderboardEventData` reads both spellings, `LeaderboardEventDataTest`). A new choice clears the pick and its variant, a new pick its variant. A choice's, a pick's and a variant's columns are folds read as the page builds (`StatColumnDef.folding`: sum, max or min, each stat's own way through `StatBoardSource.combineOf`), never stored, so every cell, sort and figure reads a column through `valueOf`. A pick in no group (`LeaderboardSplit.ungrouped`) is offered under the first choice alone.
- A `SINCE` cell (a moment, such as a first win) reads through `LeaderboardScreenMessages.since`, as a `DURATION` cell through `duration`: one `cell` paints every row and the viewer's strip.
- `RecordsDestinations` is the `Records` destination and the shared menu's Records tab, opening the board filled through `setBoard` (`statboard/`); its class javadoc is the reference. `/zigleaderboard encounter` opens it on the Bosses tab with a boss picked.
