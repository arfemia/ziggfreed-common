# instance/dungeon/ - the walk-in dungeon

- A dungeon is a type of its own beside the queue's `InstancePresetAsset`: `DungeonAsset` (`Server/ZiggfreedCommon/Dungeons/`, owner file `mods/ziggfreedcommon/dungeons.json`); its copies start from zc's void template `Server/Instances/ZiggfreedCommon_Dungeon_Void/` unless a file names another. `DungeonValidator` is the boot audit's pass, and `/zigdungeon` the admin family.
- `CopyRouter` (pure, asked through `LiveWorlds`) is the one place a party's area is chosen and reserved, copies named `<dungeon>-<n>`. `Areas` pastes and clears an area on the world thread (waking its sections first, sweeping Intangible entities the box query skips), `AreaLayout` fixes a copy's areas when it opens, `AreaMembers` is the 1 Hz membership ticker off the world thread, and `AreaSpawnProvider` (type `ZigDungeonArea`) respawns each player in their own area; never per-player respawn points, which persist by world name while copy names repeat.
- `DungeonEntry` is the one way in (its class javadoc lists the steps), and it refuses a dungeon `DungeonValidator.entryErrors` finds an ERROR in, since the boot audit runs only when asked. A player's way in is `DungeonEntry.enterWithParty` (their zc party's area, a party of one without one; only members who walk in are routed or counted), run by the `ZigEnterDungeon` interaction Type (`ZigEnterDungeonInteraction`, the chain's command buffer as its accessor, Finished only when sent; a pack puts the gate in front, `[ZigRequires, ZigEnterDungeon]`) and the `Dungeon` destination (`DungeonDestinations`, for a placement's press-F or a conversation, its entry queued on a world task of its own since a press-F arrives mid-system); both tell a refusal through `DungeonRefusals` (`entry.*` keys), never a second map. The admin's `enterAlone` keeps its own lines and never pays. `EntryCost` is spent only through `DungeonEntryCost`, inside `DungeonEntry` (its javadoc says who pays), behind `DungeonEntryPrompt`'s confirm screen, and given back only through its `refund`, which hands the items over through zc-loot's `LootRewardKinds.handToPlayer` (the bag with the pickup notice, the rest at the feet), never a raw inventory give (`DungeonRefundLandsLikeAPickupTest`).
- `DungeonRuns` is an area's run, `DungeonGoals` what a player arriving in it is told to do (`Text.GoalKey`, else lines built from `Complete`, then the run's rules) and `DungeonResults` what its end shows (each class javadoc is the reference: begin, a late joiner's own start, clear, fail, the round contract, the completion Claim through `ClaimStore.award`, no Play Again). A dungeon's name reads through `DungeonResults.nameOf`, the one helper. A run's members (who a start counted, who is in it now, a clear's winners) are a `RunMembers`, the one tracker `portal/PortalDungeonRuns` keeps too. zc-objectives' `DungeonObjectives` listener counts a `Complete.Objective` through `countObjective`, since this module never sees the moment stream, and zc-encounter's run-tag seam is filled from `DungeonRuns.runOf`. Its lock is a leaf, and every round event, payout and line is posted to the copy's world thread, never run under a lock.
- A dungeon's gameplay config, `Server/GameplayConfigs/ZiggfreedCommon_Dungeon.json` (its `$Comment` the reference), lets nobody but a creative player break a block and nobody place or gather one (R386, R388).
