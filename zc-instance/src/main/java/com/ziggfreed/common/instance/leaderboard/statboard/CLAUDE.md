# instance/leaderboard/statboard/

- The stat board (`StatBoard`, its class javadoc the reference: file, buckets, debounce) ranks every player's stats; it is a rank index, never the record. The store that keeps the stats (above this module, which never sees it) writes through `StatBoard.add`, `raise`, `lower` and `setAllTime`, imports once through `StatBoard.importOnce`, and fills `StatBoardSource` (on or off, a line's column) through `StatBoard.setSource`. Unfilled, the board knows no column, shows nothing, and Records shows no tab.
- A bucket is `all_time`, `<period id>@<window>` (`weekly@2026-W42`, a SeasonRun's `season@hallows_eve:2026`, `PeriodWindows.runWindow`) or `range@<id>`. A new window's key is the reset: nothing clears a bucket, and a turnover keeps the period's newest `Keep` windows (`Leaderboard.retain`), relying on keys that sort as text in time order; a bucket key never carries `|`.
- A SeasonRun reads zc-core's `Occurrences` on the board's clock: its `Event` (`*` for every live event) writes each live run's bucket, and Records shows a tab per live run and per run the board still holds of an event the server loads, keyed by the bucket itself and named in each player's own language (`StatBoardRecords`); a run's number never reaches a player. The store's `Seasons` bag is the store's, never the board's.
- Only a line some section names is written (`StatSectionConfig.ranked`): a `StatSections` file, or a section the store generates in code (`StatSectionConfig.generated`, an owner's whole set; a file of the same id wins), such as a season page's `season_<event>`; `authored()` is the files' alone, for the audit. A generated section naming no `NameKey` takes its event's title as each page builds (`StatBoardRecords.sectionNameKey`), never at generation, since the calendar may load its events later. A line the source gives no column shows none, and a section left with none shows no tab, so a zc-only server shows no column nobody counts (M513).
- A `Stat/*` line (`StatSection.everyLineOf`) names every line of that stat, never its total: each is ranked. On the sections row it shows one column per line the source lists now (`StatBoardSource.everyLine`, a native stat's reader's things, such as each reputation), within the section's four; a counted stat lists none. The `boss_fights` section's are Records' Boss Fights instead (`StatBoardBossFights`, a fight per tab; its class javadoc).
- A section's tab splits in code (`StatSectionConfig.split(sectionId, StatSplit)`, by whoever owns the lines, at setup); `StatSplit`'s javadoc and `StatBoardRecords.split`'s are the reference (a group's sums read as the page builds, never stored; a split over all-time-only stats pinned to All Time unless `StatSplit.offAllTime` names what it ranks off it). Nothing registered means no split, so a zc-only server's tabs have none.
- Periods are `Server/ZiggfreedCommon/StatPeriods/`; a server owner's overrides and ranges are the top-level entries of `mods/ziggfreedcommon/stats.json` (`StatPeriodOwnerLayers`), whose `$` keys (`$Enabled`) are the store's.
- Records opens this board first (`RecordsDestinations.setBoard`, filled by `InstanceBootstrap.installStatBoard`): sections over periods, each section with its own columns, the Stats view alone and no All tab (`LeaderboardPageDeps.withColumnsByPrimary`, `withoutAllTabs`, `statsOnly`). A section file's `Icon` pictures its tab (a generated section takes its event's icon, anything else `StatBoardRecords.PICTURE`) and its `HintKey` is the line on how to get on its board (else the board's `hint`); the `boss_fights` file's pair serves every fight's tab and Records' Boss Fights tab.
- `StatClock` is the board's time. `/zigleaderboard clock <offset>` moves it in memory only, to smoke a turnover; while the offset is not zero a write lands in `all_time` alone and nothing is pruned (`StatBoard.writeWindows`), so a trial never leaves a future window behind.
