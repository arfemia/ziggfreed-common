# progress/ - the shared cores under both lifecycle engines

- Two peer lifecycle engines, `quest/` and `achievement/`, share these cores and are deliberately not unified: lifecycle special-casing would thread through everything.
- Nothing here may name a lifecycle: no quest or achievement type, no import from `../quest/`. A core that needs owner data takes the owners plus accessors, the way `ObjectiveIndex.of` does.
- A new shared core lands here only when both engines want it; one engine wanting it keeps it with that engine.
- A category or subcategory name and a category accent come only from `CategoryNames` (authored `TitleKey`, the kind's convention key, a caller's key, the id tidied; the accent authored or hashed into its palette). It takes the shared `asset/CategoryPresentationAsset`, which both category types extend (with `CategoryPresentationConfig` for their folds), never a lifecycle type.
- A content name's convention key comes only from `ConventionKeys`: an achievement's `.title` / `.desc` by its BASE id (`AchievementDefinition.conventionId`, so one line names every yearly copy), a quest's and a board contract's `.title` / `.flavor`. Each fold's `textOf` stamps them into `ContentText`; `ConventionKeys.unresolvedTitle` is the one load-time check (skipped while no catalogue is loaded), run by both pool validators and the board validator (through the `Supplier` overload, so a fold that throws costs only that finding). `ContentText.resolvableTitleKey` (an offer's title key) hands the convention key over only when it ships: a fold derives one from every id, so an unshipped one would reach a reader of null as a raw key.
- A row's own title key (`ContentText.titleOwnKey`) names one row apart from its kind and heads the title ladder, above even the explicit key, in `title()`, `resolvableTitleKey()` and `titleKeyShipped()`, but only when it ships: unshipped, it is passed over and never painted.
- An unresolvable reading (a blank target, an unregistered factor, a provider that cannot answer or throws) contributes 0, and 0 as a high-water value is a no-op, so a re-check can never roll a player back.
- Matching is one forgiving rule (`ObjectiveMatch`): targets compare case-insensitively, an empty target matches everything under every mode, and an empty qualifier matches only an unqualified event. Never add a second dialect or a per-engine knob.
- A place (`targetsPlace`) is compared whole id to whole id, ignoring case, never through a `MatchMode`, and a blank target points nowhere.
- `DispatchOptions` stays two independent booleans with named factories; a new combination never needs a new constant. `ObjectiveProgressState`'s `"current/required"` wire form is byte-stable: changing it is a data migration.
- `ObjectiveDef` carries two pairs: `kind()`/`target()` are what the engines dispatch, index and settle on; `authoredKind()`/`authoredTarget()` are what the file said, and every text and icon surface reads them.
- A kind alias (`ObjectiveKindRegistry.alias`) is sugar applied once at the fold: never listed by `ids()`, never producible, and registered at setup before the publish. The engine never learns an alias exists.
- Add a `BUILT_IN_*` kind only when it means something in any game. `BUILT_IN_ACCUMULATING` and `BUILT_IN_VALUE_BASED` partition the kinds by arithmetic; the target facets (`BUILT_IN_PLACE_TARGETED` and its siblings) are orthogonal to them and to each other. A consumer registering its own vocabulary skips every `isBuiltIn` id.
- `ObjectiveComposer` is the consumer-installable slot over the neutral ladder: the step's authored key, then its kind's `Presentation.TextKey`, then `ziggfreedcommon.progress.objective.<kind>`, then `objective.default`. A new kind joins the ladder with a kind file or a lang key, never a closed switch. A kind whose Target is an id in one module's own registry has that module register an `ObjectiveTargetNames` namer for its `{1}`, which a consumer's resolver asks too, never a copy of the lookup.
- A built-in kind's Target, Qualifier and Amount are what its producer fires, and each producer's class javadoc in zc-objectives' `producer/` is that contract: an `INSTANCE_ROUND_*` kind targets `<modId>:<modeId>` (a `<modId>:` prefix matches any mode) qualified by the preset id; an `ENCOUNTER_*` kind the encounter script id for a run, never the boss creature's; `LOOT_RECEIVED` the item a payout handed over (a paid stack the overflow policy dropped at the player's feet included; an item a loot pass dropped on the ground is `PICKUP_ITEM` once picked up); `COMPLETE_QUEST` the quest id, counted at the collect and qualified by `QuestCadence.qualifier()`.
