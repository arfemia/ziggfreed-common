# asset/ - the framework asset-store bases

- A keyed config extends `AbstractKeyedAssetConfig`: the `defaults < pack < owner` fold, ids lower-cased on every layer, each layer rebuilt whole on re-import. Its one entry writer for an in-game editor is `putOwnerLeaves(file, id, leaves)` and `removeOwnerEntry(file, id)`: the id held to `acceptsOwnerEntryId` (override it for a narrower id pattern) before anything is written, the file's own spelling of the id kept, the caller reading the file back. A neutral default the library ships as JSON rides the pack layer, so a consumer's same-id file replaces it by pack order. Override the merge methods (`mergePackLayer`, `mergeOwnerLayer`) to rebuild a derived view, as `LootableConfig` does. `packLayer`, `ownerLayer` and `ownerGatedOut` are read-only copies, for a test or a tool that swaps a layer for a while to hand back afterwards.
- Read an id-keyed owner file (`mods/ziggfreedcommon/<x>.json`) only through `OwnerLayerReader`: each entry decodes against the pack layer's answer for that id with the same codec, `$`-prefixed keys are reserved, and a newer `$SchemaVersion` is refused whole. Owner files follow the mod gate: an entry whose id the last gated pack fold refused (`mergePackLayer(ModGateFold)` keeps it, `packModGateRefused`) goes with that file, and a gated store passes its `missingMod` read so an entry gated on a missing mod takes its whole id out (`mergeOwnerLayer(layer, gatedOut)`: `resolve`, `all` and `ids` drop it on every layer, jar default included, and `modGateRefused` names it); both are counted in the store's owner drop line under its declared label (the `AbstractKeyedAssetConfig(String)` constructor), never named. An owner entry decodes against `resolveBelowOwner`, never the last read's layer. A store whose ids may move (one keyed by stat id) passes `idOf`, the id a key names now, so an entry under a renamed id lands on its successor. A store with its own owner reader (quests, placements) keeps the same rules.
- `AssetStoreWriter` runs a write inline when the caller holds no asset read lock, and otherwise queues it on the `ziggfreed-asset-writer` thread and answers `DEFERRED` at once. Never wait on its completion from a thread holding the read lock, and give a new write shape its own typed method here.
- An Asset Editor dropdown (`EditorDataSets`, `EditorSchema`) is authoring convenience, never validation: it degrades to free text on a server without the editor module and hand-written JSON never passes through it, so every dataset keeps its validator check.
- `EditorSchema.assetRef` refuses nothing at decode: packs load one at a time, so a tier a later pack ships would fail an earlier pack's file; the consumer's content validator, run once every pack has loaded, stays the check.
- A value an author picks in the editor carries an `EditorPick`: the editor's own picker over an asset type (by the editor's type name) only for a value that must be one id, and for a leaf the matcher reads as a pattern or a set key a pick list offered as suggestions through `EditorSchema.suggest` (`EditorDataSets.ASSET_IDS`, `ziggfreedcommon:ids/<Type>`, every asset type's loaded ids from one handler), so a pattern stays typeable. A row whose `Kind` picks its form is a `KindSelectorCodec` (the engine's own type selector, arms asked of a live vocabulary when the editor makes its schemas, always one more arm for a value the list does not name, decode the wrapped codec's own), and a schema doc reads it through `inner()`. `EditorSchemaCheck` names the shapes that break the whole editor; `EditorSchemaAudit` runs it over the engine's own schema set in the boot audit, so a new codec shape is proved there.
- The engine keys an asset by its filename alone, so same-named files in two folders are one id and the later silently replaces the earlier. `NestedAssetId` folds `_`-marked folders into the id, for Quests and Achievements only; renaming a marked folder renames every id beneath it, and saved progress is filed under the id.
- A store that lets a running mod add to an entry at read time holds its sources in one `OwnedSources` (owner matched without regard to case, re-registering replaces, asked in owner id order, a throwing source adds nothing and warns once until it registers again) and composes them in its `resolve` override, keeping `all` the files as written: `LootableConfig`'s roll sources and `RollPoolConfig`'s entry sources. A file that names the one source it reads (a roll pool's `EntrySource`) asks it through `collectFrom`, from an instance keyed by those names. Never a second copy of those rules.
- `AbstractRawJsonAsset` is only for a type whose raw body must survive an `extends`/`params` pre-pass; every other type is a structured codec.
- Adding a framework type: codec keys never `Id`, `Parent` or `Tags` (`AssetBuilderCodec` owns them), a config extending `AbstractKeyedAssetConfig`, a registration in the root project's `asset/FrameworkAssetRegistrar`, and its `CODEC` in `AssetCodecInitTest`. A store whose files decode against another store's content registers `loadsAfter` that store, and the edge goes in `FrameworkStoreOrderTest`'s `REQUIRED_EDGES`.
- A season-bearing store declares `Season` through `SeasonLeaf.append` (one inherited string leaf with its sentence; the overload taking a sentence is for a row inside a file, such as a reputation's kill row, which has no `Parent` or `Requires` of its own) and asks `season/SeasonGate.live` beside `Enabled`, so a season hides and never locks; its audit reports an id no calendar event declares through `SeasonGate.checkKnown`.
- A store whose files may gate on a mod folds through `AssetMergeAdapter.gate("<Store>", map, missingMod)` with its `missingMod` read (`GateSpec` or a store's own): the `ModGateFold` carries the layer and each refused id with its mod (what a store resolving a `Base` needs), and the fold logs the pack drop line. `layer(map, keep)` and `refused(map, keep)` are the same filter without the report. Every store writes its `Requires` as `GateSpec` (zc-core's `progress/gate`), read whole: a store below the quest stores asks the rest of the block of the player through `StoreGates` (that package's router), its accessor is `requires()`.
- A store that gains a top-level `Requires` declares its `MOD_GATE_STORE` label, wires that fold and joins `FrameworkModGateWiringTest`'s lists; a store with none cannot be gated (list it in the test's javadoc), and one whose files carry reward rows, gated or not, joins `REWARD_ROW_STORES`.
- `PackRangeAudit` warns once at `BootEvent` for each loaded pack whose manifest declares a range for this library (required or optional) that the running version fails: the engine compares neither for a pack. It only reports; a code plugin's failed required range is the engine's own SEVERE, and that plugin never loads.
