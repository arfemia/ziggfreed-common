# asset/ - the framework asset-store bases

- A keyed config extends `AbstractKeyedAssetConfig`: the `defaults < pack < owner` fold, ids lower-cased on every layer, each layer rebuilt whole on re-import. A neutral default the library ships as JSON rides the pack layer, so a consumer's same-id file replaces it by pack order. Override the merge methods (`mergePackLayer`, `mergeOwnerLayer`) to rebuild a derived view, as `LootableConfig` does.
- Read an id-keyed owner file (`mods/ziggfreedcommon/<x>.json`) only through `OwnerLayerReader`: each entry decodes against the pack layer's answer for that id with the same codec, `$`-prefixed keys are reserved, and a newer `$SchemaVersion` is refused whole.
- `AssetStoreWriter` runs a write inline when the caller holds no asset read lock, and otherwise queues it on the `ziggfreed-asset-writer` thread and answers `DEFERRED` at once. Publish an id the write creates only from `Result.completion()`, never wait on that from a thread holding the read lock, and give a new write shape its own typed method here.
- An Asset Editor dropdown (`EditorDataSets`, `EditorSchema`) is authoring convenience, never validation: it degrades to free text on a server without the editor module and hand-written JSON never passes through it, so every dataset keeps its validator check.
- A leaf naming an engine asset id (an `ItemQuality` id, say) takes `EditorSchema.assetRef(<AssetClass>.class)`: the editor's own picker, written on each entry of a string array, with nothing refused at decode. Never put the engine's `<Asset>.VALIDATOR_CACHE` on a family codec: its failed check drops the whole file (and at boot the mod with it), and packs load one at a time, so a tier a later pack ships fails an earlier pack's file. The consumer's content validator, run once every pack has loaded, stays the check.
- The engine keys an asset by its filename alone, so same-named files in two folders are one id and the later silently replaces the earlier. `NestedAssetId` folds `_`-marked folders into the id, for Quests and Achievements only; renaming a marked folder renames every id beneath it, and saved progress is filed under the id.
- A store that lets a running mod add to an entry at read time holds its sources in one `OwnedSources` (owner matched without regard to case, re-registering replaces, asked in owner id order, a throwing source adds nothing and warns once until it registers again) and composes them in its `resolve` override, keeping `all` the files as written: `LootableConfig`'s roll sources and `RollPoolConfig`'s entry sources. Never a second copy of those rules.
- A config that overrides the merge methods to drop a derived index: `LootableConfig`, `EncounterBindingConfig` (by-script index) and zc-entity's `GearSetConfig` (item-to-sets index), and zc-dialogue's `DialogueExtensionConfig` (its id-ordered list).
- `AbstractRawJsonAsset` is only for a type whose raw body must survive an `extends`/`params` pre-pass; every other type is a structured codec.
- Adding a framework type: codec keys never `Id`, `Parent` or `Tags` (`AssetBuilderCodec` owns them), a config extending `AbstractKeyedAssetConfig`, a registration in the root project's `asset/FrameworkAssetRegistrar`, and its `CODEC` in `AssetCodecInitTest`. A store whose files decode against another store's content registers `loadsAfter` that store, and the edge goes in `FrameworkStoreOrderTest`'s `REQUIRED_EDGES`.
- A season-bearing store declares `Season` through `SeasonLeaf.append` (one inherited string leaf with its sentence) and asks `season/SeasonGate.live` beside `Enabled`, so a season hides and never locks; its audit reports an id no calendar event declares through `SeasonGate.checkKnown`.
