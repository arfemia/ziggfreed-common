# asset/ - the framework asset-store backbone

Router for `com.ziggfreed.common.asset`. The generic, mod-agnostic plumbing every framework codec asset shares, PLUS the one registrar that wires them. **Common OWNS its framework stores**: a store is keyed by asset Java class in a process-static registry and may be registered ONCE - so common (not a consumer) registers each framework class exactly once, at `Server/ZiggfreedCommon/<Type>/`, and owns the single `LoadedAssetsEvent` merge listener. A consumer authors JSON into those paths and READS the resolved config singleton back; it must NOT re-register a framework class (the second `register` throws at load).

- **[`AssetStoreRegistrar`](AssetStoreRegistrar.java)** - `registerStore(class, map, path, keyFn, codec, loadsAfter)`: registers ONE Pattern-A store, hiding the package-protected `AssetStore.Builder` cast chain. Mod-agnostic (the path is a caller arg).
- **[`AssetStoreWriter`](AssetStoreWriter.java)** - THE one way the family writes an asset store after boot (`writeAssets(what, store, packKey, assets)` / `writeBuffers(what, store, packKey, rawAssets)` over the core `write(what, runnable)`, plus `offThread(what, job)` for a whole pass). Every store mutator takes the process-wide `AssetRegistry.ASSET_LOCK` WRITE lock, and `World.tick` holds its READ lock around the whole tick (so every `world.execute` task, `AbstractPlayerCommand` body and page handler runs holding it); a `ReentrantReadWriteLock` never upgrades, so a direct write from there wedges the world thread forever. The writer tests the caller's read hold: none (boot, a listener fired under the loader's write lock, the writer thread itself) runs the write INLINE and synchronously, boot unchanged; a hold queues it on the `ziggfreed-asset-writer` daemon thread and answers `DEFERRED` at once, never waiting (the writer cannot take the lock until the tick ends). The `Result` carries `ranInline()`/`deferred()`/`failed()` plus a `completion()` future; a caller publishing an id the write creates chains on the completion. `ZiggfreedCommonPlugin.shutdown()` stops the thread. The MMO's `RepoHygieneTest` fails the build on a mutator called outside this file; a new write shape is a new typed convenience here. Engine evidence in hyMMO's `[[world-thread-asset-store-write-deadlock]]`.
- **[`AssetMergeAdapter`](AssetMergeAdapter.java)** - `layer(assetMap[, (id,asset)->mapped])`: folds a `LoadedAssetsEvent` map into an `id -> value` layer, skipping the engine-base (`DEFAULT_PACK_KEY`) entries and lower-casing ids. The generic of the per-type hand-rolled fold.
- **[`AbstractKeyedAssetConfig<T>`](AbstractKeyedAssetConfig.java)** - the generic `defaults < pack < owner` fold base (synchronized writes, concurrent reads, lower-cased ids, idempotent re-import). Every framework config singleton extends it (25 today, across every module: the encounter pair `EncounterBindingConfig` (which OVERRIDES the merge methods to drop its by-script index) + `EncounterParticipationConfig`, the instance/world/loot set `InstancePresetConfig`, `BandedEffectConfig`, `WeightedPrefabPlacementConfig`, `LeaderboardLayoutConfig`, `PartySettingsConfig`, `ArenaDefinitionConfig`, `LootableConfig`, `RewardKindConfig`, `RollPoolConfig`, plus `NpcPlacementConfig`, `NpcIdentityConfig`, `DialogueFragmentConfig`, `DialogueOptionThemeConfig`, `DerivedFactorConfig`, `FeedbackMomentConfig`, the two achievement-taxonomy configs and the four commerce ones - grep `extends AbstractKeyedAssetConfig` for the current set); the singleton adds only its `T` binding + `getInstance()` + type getters. Common ships only a thin floor of jar defaults (`loadDefaults` is optional; the catalogue is consumer pack JSON): the structural `DialogueOptionTheme/*.json`, the `Hytale_*` + progression `Factors/*.json` standard library, `RewardKinds/*.json`, one `ObjectiveKinds/*.json` per engine-generic step kind, the match-all `EncounterParticipation/Zc_Default.json` beside the `Encounters/Zc_Encounter_Example.json` binding row for the shipped example script, and the neutral `FeedbackMoments/*.json` a bare server falls back to. A config may also OVERRIDE the merge methods to rebuild a derived view - `LootableConfig` does, for the contribution fold.
- **[`OwnerLayerReader`](OwnerLayerReader.java)** - the ONE reader of a server owner's id-keyed `mods/ziggfreedcommon/<x>.json` into a keyed config's owner layer: drop the previous owner layer first (a re-read never compounds), decode each entry AGAINST the pack layer's own answer for that id through the very same codec (leaf by leaf, no second schema), skip the reserved `$`-prefixed keys and refuse a newer `$SchemaVersion` whole (`util/OwnerFiles`), one INFO naming the count. Every domain keeping such a file calls it with its own log tag, file path, codec, config and noun (`commerce/fold/CommerceOwnerLayers` for the four economy files, `encounter/asset/EncounterOwnerLayers` for the two encounter files); none carries a reader of its own. The one owner surface that is a FOLDER of per-entry files rather than one id-keyed file, the quest folder `mods/ziggfreedcommon/quests/<Id>.json`, is read by zc-progression's `quest/asset/QuestOwnerLayers` on the same terms (one decode per file through the store's own codec against the entry below it, a malformed file costing that one entry with a finding naming the file, `$`-prefixed and non-`.json` names ignored via `OwnerFiles.isReservedKey`) from the quest store's own fold, since its base is the composed view rather than a keyed config.
- **[`EditorDataSets`](EditorDataSets.java)** - serves the value lists behind the `UIEditor.Dropdown`
  dataset ids this library's codecs declare, so the in-game Asset Editor offers a pick list instead
  of a free-text box. `live(registry, dataSetId, supplier)` answers off a runtime registry at request
  time (a late registration simply widens the next answer); `fixed(registry, dataSetId, values...)`
  serves a closed compile-time set. Both are try-guarded end to end - **a server without the Asset
  Editor module must degrade to free text, never fail startup** - and both must stay cheap and
  side-effect free, since the request is an async event. Holds the two factor dataset ids
  (`ziggfreedcommon:placement_factors`, `ziggfreedcommon:factors`); the composition that answers them
  lives in `ZiggfreedCommonPlugin`, the only place that can see both the placement facade and the
  Factors assets. **A dropdown is authoring convenience, never validation** - hand-written JSON never
  passes through the editor, so every dataset keeps its validator check.
- **[`EditorSchema`](EditorSchema.java)** - schema-only Asset Editor hints attached to a codec field
  with `.metadata(...)`: `defaultValue(...)` declares a nullable leaf's effective unauthored value
  (an `Enabled` meaning true, a `Weight` meaning 1) so the editor shows the real default instead of
  the control's zero-state, and `oneOf(...)`/`oneOfDocumented(...)` declare a CLOSED string
  vocabulary as the engine's enum shape (`enum` + `hytale.type: Enum` + per-value descriptions) so
  the editor offers a dropdown; a string-array leaf gets the set on its items. Decode is never
  touched (null still means inherit-then-default at the read site), and **enum belongs only on a
  vocabulary closed BY CODE** - a pack-extensible id set stays a plain string, because a dropdown
  that rejects a legal pack value is worse than a text box. Consumed across zc, the MMO jar,
  rpg-stations, mob-scaling and kweebec.
- **[`NestedAssetId`](NestedAssetId.java)** - lets an author group asset files into folders AND have
  the folder name become part of the id. The engine keys an asset by its FILENAME alone
  (`AssetStore.decodeFilePathKey`), so `Zones/Wilds/Trork_Trouble.json` and
  `Zones/Ashlands/Trork_Trouble.json` are ONE id and the second silently replaces the first. Marking
  a folder `_Wilds` makes it contribute: `effectiveId(path, typeRoot, filenameId)` folds every
  `_`-marked ancestor (marker stripped, lower-cased, stacked in path order, joined with `_`) onto
  the front of the filename id. An UNMARKED folder contributes nothing, so an existing tree keeps
  the ids it has and nothing moves under an author who did not opt in. `typeRoot` bounds the scan to
  directories below the store's content path, which is what keeps a checkout at `D:\_work\...` from
  putting `work` on the front of every id. **Wired into QUESTS and ACHIEVEMENTS only** (`quest/asset/QuestAsset`'s and
  `achievement/asset/AchievementAsset`'s `afterDecode`, off `AssetExtraInfo.getAssetPath()`); every
  other type keys plainly off its filename. Renaming a marked folder renames every id beneath it, and an id is what saved progress
  is filed under.
- **[`AbstractRawJsonAsset`](AbstractRawJsonAsset.java)** - the raw-Payload base (`Name`+`Payload` BSON, `rawCodec(...)`, `getPayloadAsJsonObject()`). Use ONLY for a type whose raw body must survive a pre-pass, which today means an `extends`/`params` template DSL. (Dialogues used to be the other case and are now Pattern A: their body decodes through a codec graph assembled from the registered vocabulary, behind a deferred codec.) A self-contained type is a structured codec instead. Lifted from the MMO's own copy; carries `org.bson` (available via the Hytale jar's `Codec.BSON_DOCUMENT`).
- **[`FrameworkAssetRegistrar`](../../../../../../../../src/main/java/com/ziggfreed/common/asset/FrameworkAssetRegistrar.java)** - `registerAll(plugin)`, called once from `ZiggfreedCommonPlugin.setup()`. Registers the framework stores + their merge listeners (Dialogues, Instances, **Lootables** (`loot/LootableAsset` -> `loot/LootableConfig`, the named conditional loot tables anything references by id; its config OVERRIDES `resolve` so a table's `ContributesTo` enrichers are already folded in for every reader), BandedEffects, PrefabPlacements, Leaderboard, Arenas, Party, **NpcPlacements** (`npc/placement/asset/NpcPlacementAsset` -> `NpcPlacementConfig`, the NPC placement engine's content; its merge clears the reconciler's per-world sweep debounce + the resolved-position cache, so a reload lands on the next sweep instead of waiting for a world to be entered fresh), **Factors** (`factor/DerivedFactorAsset` -> `factor/DerivedFactorConfig`, a factor id DEFINED as a formula over other factors, the file name being the id; nothing to invalidate - a registry that adopts a derived id re-reads the config every call), **Quests** + **QuestGenerators** (`quest/asset/QuestAsset` + `QuestGeneratorAsset` -> `quest/asset/QuestAssetStore`, one authored quest per file plus the files that write a whole family; the fold into a `QuestPool` is zc-objectives' one shared publish, `ProgressionDefaults.publishAssetContent`, which both listeners ask to run again on a hot re-import, and which reads the owner folder `mods/ziggfreedcommon/quests/<Id>.json` itself, so that folder needs no listener here), **Achievements** (`achievement/asset/AchievementAsset` -> `AchievementAssetStore`, folded by the same publish, its listener asking for the same republish), **AchievementCategories** + **AchievementMilestones** (`achievement/asset/AchievementCategoryAsset` + `AchievementMilestoneAsset` -> their own `AbstractKeyedAssetConfig` singletons: the display taxonomy behind the shared `Listing.Category` leaf, and the points ladder `zc-objectives`' `ProgressionDefaults` publishes into the runtime), **DialogueFragments**, **RollPools**, **StatDisplays** (`loot/stamp/StatDisplayAsset` -> `StatDisplayConfig`, what one stat is CALLED on a stamped item, outranking whatever a mod registered in code), **ObjectiveKinds** (`progress/asset/ObjectiveKindAsset` -> `ObjectiveKindConfig`, one kind of quest or achievement step per file, whose listener also folds it leaf by leaf over the Java registration via `ObjectiveKindFold.foldInto(ProgressionRuntime.objectiveKinds())`), **RewardKinds** (whose listener also folds the authored kinds into `RewardKinds.shared()`, because a consumer's `setup()` is long over by the time assets load), **DialogueOptionTheme** (the one STRUCTURAL default this library ships as its own pack), **NpcIdentity**, **FeedbackMoments**, and the commerce family **Currencies** / **Shops** / **ShopPools** / **ShopEntries** / **ShopEntryGenerators** / **Boards** / **Bounties** (the first three and Boards re-read their `mods/ziggfreedcommon/{currencies,shops,shop-pools,boards}.json` owner layer on that same event rather than at setup, since an owner entry has nothing to inherit from until the pack layer has landed; ShopEntries, ShopEntryGenerators and Bounties instead rebuild the catalogue the purchase and board engines read, because those engines read FROM the store), and the encounter pair **Encounters** (`encounter/asset/EncounterBindingAsset` -> `EncounterBindingConfig`, owner layer `mods/ziggfreedcommon/encounters.json`) / **EncounterParticipation** (`encounter/asset/EncounterParticipationAsset` -> `EncounterParticipationConfig`, owner layer `mods/ziggfreedcommon/encounter-participation.json`), both re-reading their owner file on the same event - thirty-two stores in all). There are THREE ordering edges: ZcDialogue `loadsAfter` DialogueFragments (a conversation splices the shared option groups it names as it is read, so a group that has not loaded yet drops its lines silently), and QuestGenerators `loadsAfter` Quests plus ShopEntryGenerators `loadsAfter` ShopEntries (a generated child is decoded against its `Base` out of the store it inherits from); all three are pinned by `FrameworkStoreOrderTest`. No PackControl gate: common ships neutral defaults for a few of these stores (Factors, RewardKinds, FeedbackMoments, DialogueOptionTheme, ObjectiveKinds, EncounterParticipation, plus one example Encounters binding) so a bare server gets something, and a consumer overrides one BY ID - a later pack's same-id file simply wins - so there is no add/replace decision to gate. To add a framework type: write the asset (PascalCase codec keys, no `Id`/`Parent`/`Tags`) + a config extending `AbstractKeyedAssetConfig`, register it here, and add its `CODEC` to `AssetCodecInitTest` (the static-init / PascalCase guard).
