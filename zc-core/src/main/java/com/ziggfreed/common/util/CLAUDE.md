# util/ - mod-agnostic helper primitives

Router for `com.ziggfreed.common.util`. Small, config-free, reusable helpers; no Kweebec/MMO imports, no i18n. Engine-touching helpers are world-thread only (caller's responsibility) and try-guarded.

- **[`GuardedLogger`](GuardedLogger.java)** - the ONE shared guarded-logging IMPLEMENTATION: an
  instantiable wrapper over a `Supplier<HytaleLogger>` plus an optional prefix, exposing `info`/
  `warn`/`severe`/`fine`/`finer`, each with a `(String)` and a `(String, Throwable)` overload, each
  wrapping its logger call in `try/catch (Throwable)` - the flogger LOGGER throws an `Error` in a
  log-manager-less unit JVM that escapes a plain `catch (Exception)`, so the guard is what lets an
  engine-touching primitive be unit-tested at all; zero cost when nothing throws (an empty prefix
  passes the caller's own String straight through, no concatenation). The logger is SUPPLIED, not
  resolved: the first touch of the underlying flogger field then happens inside the guard rather
  than in a caller's static initializer, where the same failure would escape as an
  `ExceptionInInitializerError` and poison the facade class for the rest of the JVM's life. The
  logging facade of every mod that depends on this library (this module's own `SafeLog` below, the
  MMO's `util.SafeLog`, Kweebec Nightmare's `util.SafeLog`, RPG Stations' `util.Log`) is a thin
  static wrapper over ONE `GuardedLogger` instance holding its own plugin's logger + prefix - each
  facade keeps its own name, ownership and call sites; only the guard shape is shared. The
  zero-dependency `command-interactions` mod keeps its own hand-rolled copy by design (it takes no
  ziggfreed-common dependency at all), so do not "finish the convergence" there.
- **[`SafeLog`](SafeLog.java)** - the ONE guarded logging facade for ziggfreed-common: `info`/`warn`/`severe`/`fine`, each with an optional `Throwable`-cause overload, every message prefixed `[ziggfreed-common]`. A thin static wrapper over one `GuardedLogger` instance (`CommonLog.LOGGER` + the prefix). New code routes through it; the roughly 90 pre-existing raw `CommonLog.LOGGER` call sites each re-rolling their own private guard are NOT retrofitted (a pending follow-up, not a rule exemption).
- **[`AssetIndexCache`](AssetIndexCache.java)** - `AssetIndexCache<T>.of(id, lookup)` / `ofCandidates(ids, lookup)` -> `resolve()`: memoize an asset id (or first candidate) to its map index, caching ONLY a strictly-positive index (the engine's `MIN_VALUE`/`0` are "not ready" and re-resolve). One instance per logical asset (e.g. a sound). Thread-safe (`volatile`).
- **[`DamageCauseCache`](DamageCauseCache.java)** - `getCauseIndex(causeId)`: memoize `DamageCause.getAssetMap().getIndex(id)` in a `ConcurrentHashMap`, caching ONLY a resolved (`>= 0`) index (the cause asset registers AFTER class load); try-guarded, returns `UNRESOLVED` (-1) on miss / not-ready map. Lets a damage observer ID a custom (or vanilla) cause by a cheap integer compare vs `damage.getDamageCauseIndex()`. Generalizes Kweebec's `KweebecDamageSystem.isMoonbloomCause` cache; `invalidate(id)` / `invalidateAll()` drop entries.
- **[`NumberFormatter`](NumberFormatter.java)** - `grouped(amount)` (`1200 -> "1,200"`) / `compact(value, kThreshold)` (`-> "1.2M"`/`"1.2k"`): the single numeric-display source. Pure Java, zero engine coupling.
- **[`CommandExecutor`](CommandExecutor.java)** - `executeAsConsole(cmd[, username])` / `executeAsPlayer(playerRef, cmd)`: run a command string via the engine `CommandManager` as console or a player. The caller builds the final command string (no placeholder substitution here); logging is unit-JVM guarded. **For an AUTHORED command line (a reward, a drop, a station grant), call [`command/CommandRunner`](../command/CLAUDE.md) instead** - it adds map-driven placeholder substitution, the `/give` positional-quantity fix (the engine reads a count ONLY from `--quantity=N`; a positional one silently delivers a single item), and a per-call guard with a `Consumer<String>` failure sink, then dispatches through here. Reach for `CommandExecutor` directly only for a fixed command the mod itself composed.
- **[`HostilityUtil`](HostilityUtil.java)** - `isHostileTowards(store, npcRef, targetRef)`: true when the NPC's `WorldSupport` attitude cache resolves `HOSTILE` toward the target. World-thread only; try-guarded (also swallows a `null` attitude cache on a role that never wired an attitude-consuming sensor, degrading to `false`).
- **[`EntityIdentifierUtil`](EntityIdentifierUtil.java)** - `describeEntity(store, ref)` (human-readable log label) / `getMobId(store, ref)` (THE mob identity: the NPC ROLE name, e.g. `"Skeleton_Fighter"`, `"Test_Dummy"`) / `roleName` + `roleIndex` (the raw NPC role reads, `Store`/`Ref` and pre-add `Holder` forms): identify mobs/players from ECS components for attribution, config matching and logging. World-thread only. **A mob is its ROLE, never the model it wears** - the two usually read the same word only because of how the vanilla assets are named, and two unrelated roles can share one costume (a training dummy is a `Test_Dummy` wearing a `Mannequin`), so a model-keyed rule would quietly govern mobs it never meant. The model asset is read only for an entity NO role drives, so such an entity is still nameable; there is deliberately no public accessor for it.
- **[`SplitMix64`](SplitMix64.java)** - a deterministic SplitMix64 seeded stream (`new SplitMix64(seed)` -> `nextLong()`/`nextDouble()`, plus the static `mix(a, b)` two-long fold) for any path needing REPRODUCIBLE randomness (a chunk-reload-stable roll, a cross-server-stable rotation) that cannot use `java.util.Random`. Pure arithmetic, zero engine coupling, not thread-safe (build one instance per roll). Lifted verbatim from the MMO mob-scaling mod. Do NOT repoint an already-shipped stream at `mix` unless it was bit-identical (a 3-input fold with an extra constant is not reproducible by `mix(mix(a,b),c)`).
- **[`WeightedPick`](WeightedPick.java)** - the ONE weighted-selection primitive: `one(items, weightOf, sample)` picks one in proportion to weight, `some(items, weightOf, count, unique, sample)` picks N (`unique` false draws WITH replacement, true removes each pick and stops when candidates run out), `totalWeight` for a caller reporting per-entry odds. The sample source is a `DoubleSupplier` answering `[0,1)` - pass `random::nextDouble`, or `WeightedPick.from(SplitMix64)` for a seeded stream. It exists because weighted picking is the most re-derived arithmetic in a loot/rotation/spawn codebase and every copy drifts, so the answers are fixed once: a weight reads as `max(0, w)` (a negative is "never picked", not a distribution-bender), a zero-weight entry owns no band and is stepped OVER rather than tested (otherwise it wins whenever the remainder lands exactly on 0), an all-zero-weight set falls back to a UNIFORM pick rather than going dark, an empty list picks nothing without throwing, and `one` consumes EXACTLY ONE sample so a caller can predict the stream. `zc-loot` (roll ladders, stamp draws, score-tiered tables) uses it today; the remaining hand-rolled copies (`zc-commerce/rotation/WeightedSlotDraw`, `zc-instance/encounter/SpawnRoster`, `zc-world/WeightedPrefabPlacementConfig`) re-base onto it as their owners next touch them.
- **[`JsonTreeUtil`](JsonTreeUtil.java)** - the four shared pure-JSON template primitives (`deepClone` / `substituteString` / `substituteParamsInPlace` / `deepMergeInto`) for the `extends`/`params` template resolvers: the MMO's non-dialogue content template resolvers delegate to it (via their own `JsonTemplateUtil`) instead of re-implementing the walk. Gson-only, no engine coupling, freely unit-testable. (The dialogue engine no longer uses it - dialogues are read by a structured codec with native `Parent` inheritance and an `InheritMapCodec` node merge.)
- **[`OwnerFiles`](OwnerFiles.java)** - the FILE-level rules every `mods/ziggfreedcommon/*.json` owner file shares, in one place so the six readers (the four commerce files, `npc-placements.json`, `dialogues.json`) cannot drift: `isReservedKey` (a `$`-prefixed top-level key is documentation or a marker, never an entry id) and the `$SchemaVersion` marker (`declaredSchemaVersion` reads absent as 1; `schemaReadable` refuses a file declaring a NEWER version whole, one shared warning naming the file and both numbers, so a future shape is never silently misread as today's).
- **[`JsonOverrideWriter`](JsonOverrideWriter.java)** - partial-override WRITE-BACK for a codec-authored owner file (the counterpart to a read/fold config that has no `save()` - e.g. a `MobScalingConfig` / an `AbstractKeyedAssetConfig`-fed owner file). `setLeaf`/`setLeaves(path, dottedPascalCasePath -> value)` sets/removes leaves preserving every sibling key + a leading `$Comment` (reuses `JsonTreeUtil.deepMergeInto` for the additive merge; a null value removes; a `List`/`String[]` value emits a JSON ARRAY leaf instead, each element boxed through the same scalar rule, replacing the leaf WHOLESALE like any other); `upsertArrayEntry`/`removeArrayEntry(path, arrayKey, matchField, matchValue, ...)` is the ONE thing `deepMergeInto` cannot do - a top-level array WHOLE-ELEMENT replace/append/remove keyed by a match field (other elements preserved, the owner-over-jar concat-fold shape); `readArrayKeyValues` reads a field off every element (the default-vs-override badge). Number TYPE FIDELITY is the caller's contract (`Integer` for `Codec.INTEGER`, `Double` for `Codec.DOUBLE`); plain-Java-typed public API (String paths, boxed scalars) so a CONSUMER needs no Gson. Gson-internal (server-jar shaded gson), atomic write (temp + `ATOMIC_MOVE`), fully guarded (returns `false` on any IO/parse failure; a malformed existing file is NEVER overwritten). Unit-tested (`JsonOverrideWriterTest`).
- **[`PeriodMath`](PeriodMath.java)** - the ONE answer to "which repeating window is this instant in?": `periodIndex` / `periodStartMs` / `millisUntilNext` / `nextBoundaryMs` / `samePeriod`, every one taking the same two plain numbers - a `lengthMs` and an `anchorOffsetMs` shift added to the clock before the divide - so nothing here learns what the window is FOR (a daily reset, a weekly rotation, a cooldown bucket); `weekdayAnchorMs(DayOfWeek)` is the offset that lands a weekly window on a chosen weekday (zero for Thursday, the weekday the epoch fell on). Indexing goes through `Math#floorDiv`, so it stays monotonic before 1970 too; the offset is the knob rather than a zone id, because a real timezone would have to be persisted per window for an already-stamped instant to keep its meaning after an owner changed it. Two boundary answers are deliberate and worth keeping: `millisUntilNext` is always strictly positive (an instant sitting exactly on a boundary has a WHOLE window ahead of it, which is what a countdown shown to a player has to say), and `nextBoundaryMs` SATURATES at `Long.MAX_VALUE` rather than wrapping, because a wrapped boundary would read as "available now". `SECOND_MS`/`MINUTE_MS`/`HOUR_MS`/`DAY_MS`/`WEEK_MS` are here as well. Pure and static: UTC server clock, no store, no engine type, so every boundary is exercisable by handing it two numbers (`PeriodMathTest`). `zc-progression`'s `quest/RepeatPeriod` and `zc-commerce`'s `rotation/RotationSpec` both delegate their whole period surface to it, which is what keeps a quest reset and a shop rotation indexing the same way.
