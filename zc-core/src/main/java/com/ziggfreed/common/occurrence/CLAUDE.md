# occurrence/ - the one door to recurring events

- A module that must know whether a recurring event is running reads `Occurrences.source()` at the moment of asking and never imports the calendar: zc-calendar fills the slot from `CalendarBootstrap` at library setup.
- Every answer that depends on the time takes the asker's own clock reading (`nowMs`), so an engine on an injected clock asks with it.
- An event the server lacks or its owner switched off is ABSENT: not enabled, never live, no history. Never read "not live" as "switched off"; ask `isEnabled`.
- The two year questions look past the switches: `firstYear` and `currentYear` answer for any LOADED event, so what a player earned in a past run keeps its years after an owner switches the event off. `currentYear` is the year a yearly copy is minted for; whenever `live` answers a run, it answers that run's year. `firstYear` is null for a file with no FirstYear or one outside 1970 to 9999 (such an event never runs), so a reader keeping a copy per year has none to keep.
- An occurrence belongs to the year it STARTS in, and `endMs` is the first instant after it. A run is (event, year, number): `number` names it within its year (an event may run several times a year) and a force or an owner moving its days keeps it; it is a name, never a count or a place in time (numbers skip), so compare runs with `sameRun`, order them with `IN_ORDER` (by start), never by year alone, and never show a number to a player. A number is 1 to `Occurrence.MAX_NUMBER` (54), which zc-calendar enforces, so a reader may keep a year's runs as a set of numbers.
- `datesMove` says an event's days move from year to year (a moving rule or per-year days), or that it comes round several times a year: a reader that would say "every year" asks it first. `after(eventId, year, number)` names the run after a given one, for a reader walking past the runs its player has spent; `dated(eventId, year, number)` dates one run by identity past the switches and forces, as the year questions look past them, for a reader asking whether its own days are over.
- `recurrence(eventId, nowMs)` says how a monthly or weekly event comes round as a neutral `Recurrence` (`Monthly` or `Weekly`: the day or Nth weekday, every N, its months, a run's `Length`), for a reader that says it in words; it never dates a run (ask `next`), and it is null for an event that comes round once a year, a year of its own set days, and a source that knows no rules.
