# inventory/

- `DisposableItemMetadata` is the one server-wide list of item-metadata keys declared safe to destroy with their item. Declare a key once at setup (`declare`); a stat stamper's `Stamper.metadataKeys()` reaches it through `StamperRegistry.register`. Keys match exactly and a declaration is never retracted; a declared key is disposable whoever wrote it, so data that must survive lives under a key its owner never declares. What to do about an undeclared key (refuse, ask) is the consumer's policy. It sits in zc-core because zc-loot (`loot/stamp/StamperRegistry`) and zc-entity (`entity/ItemReadings`) both read it and neither may see the other.
- No unit test runs a `PlayerAccess` accessor body (a unit JVM has no `Player`): after changing one, smoke an item pickup, a block break, a turn-in hand-in and a station Consume step in game.
- `ItemLineage` is an item's id, then each id its `Parent` chain names, read off the loaded asset: an id-pattern classifier (a tool or weapon kind) matches the whole lineage so a `Parent` copy counts as what it copies. Its supplied-lookup overloads are the seam a unit test drives.
- `InventorySections.ALL` is the one list of managed sections (the original six plus Update 7's rune Abilities and Rune Bag): `InventorySnapshot`'s capture and strip walk it and `InventoryStripPolicy` defaults to it, while a restore clears only the sections its own snapshot captured, so a snapshot older than a section never wipes it.
