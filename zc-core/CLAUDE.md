# zc-core

- `LibraryOwner.NAME` (the hyphenated `ziggfreed-common`) is an attribution for logs and admin output, never a lookup key. The per-domain `OWNER` constants carry the unhyphenated `ziggfreedcommon` ids (registry keys, `mods/ziggfreedcommon/`, `Server/ZiggfreedCommon/`).
- `test` runs untagged tests with no log manager, which is where this module's logging guards run (`SafeLogTest` asserts it); the `FactorContextTest` cases carrying a real `ItemStack` are tagged `engine-items` and run in `engineItemTest`.
- Code here is the most likely to run in a bare unit-test JVM with no Hytale bootstrap, so keep every engine-touching try-guard real.
- The one engine asset-store swap for tests lives in this module's `testFixtures` source set (`testing/EngineAssetStores`: `emptyItems`, `qualities`, `statChannels`). Any module's test reaches it through `testImplementation(testFixtures(project(':zc-core')))`, tagged `engine-items`; never copy it into a test. It never ships: the root jar bundles each module's main variant only.
- The one known copy outside the library is the MMO's `PickupBonusPassTest`, which keeps its own `EmptyItemStore`: the MMO compiles against this library's built jar, so it cannot reach these fixtures, and a published zc `testFixtures` jar would retire that copy.
- `season/SeasonGate` is the one reader of whether content's season is running: blank is all year, otherwise the calendar's `<Season>_Live` feature (namespace `ziggfreedcommon`) through `FeatureFlags`, and anything but a definite 1 hides. A store declares its leaf through `asset/SeasonLeaf` and reads it in its presence check, never in `Requires`, and the `_Live` spelling lives only here (zc-calendar's `CalendarFeatures` and `CalendarEventAsset.isReservedId` read it).
- `validation/TextKeyAudit` is the one check a content validator makes of an authored lang key (`UNKNOWN_TEXT_KEY`, a WARNING; every key reads as shipped while no catalogue is loaded).
- `validation/BootAudit` runs the content audits once on `BootEvent` when the process carries `ZIGGFREEDCOMMON_AUDIT_ON_BOOT=1` (the dev harness exports it). It is an environment variable, never an owner key, so it never persists into a run directory. Its lines keep `ValidationReport`'s split (warnings at INFO), so a reader matches them by pattern, and one `[zc] boot audit: ` marker counts them, each at the level its pass gave it; the season boot verdict parses the marker, so change its wording only with the parser. A new pass is wired in the root's `registerBootChecks`: one that stands in for a first-join audit takes that audit's once-per-boot run (`claimLateFindings`, as commerce and placements do), and one that reads a lazily built engine builds it first (`TitleValidator.auditForcingBuild`), or it counts as run while it asked nothing.
