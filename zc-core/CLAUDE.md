# zc-core

- `LibraryOwner.NAME` (the hyphenated `ziggfreed-common`) is an attribution for logs and admin output, never a lookup key. The per-domain `OWNER` constants carry the unhyphenated `ziggfreedcommon` ids (registry keys, `mods/ziggfreedcommon/`, `Server/ZiggfreedCommon/`).
- `test` runs untagged tests with no log manager, which is where this module's logging guards run (`SafeLogTest` asserts it); the `FactorContextTest` cases carrying a real `ItemStack` are tagged `engine-items` and run in `engineItemTest`.
- Code here is the most likely to run in a bare unit-test JVM with no Hytale bootstrap, so keep every engine-touching try-guard real.
- The one engine asset-store swap for tests lives in this module's `testFixtures` source set (`testing/EngineAssetStores`: `emptyItems`, `qualities`, `statChannels`, `statTypes`, `effects`). Any module's test reaches it through `testImplementation(testFixtures(project(':zc-core')))`, tagged `engine-items`; never copy it into a test. It never ships: the root jar bundles each module's main variant only.
- `season/SeasonGate` is the one reader of whether content's season is running: blank is all year, otherwise the calendar's `<Season>_Live` feature (namespace `ziggfreedcommon`) through `FeatureFlags`, and anything but a definite 1 hides. A store declares its leaf through `asset/SeasonLeaf` and reads it in its presence check, never in `Requires`, and the `_Live` spelling lives only here (zc-calendar's `CalendarFeatures` and `CalendarEventAsset.isReservedId` read it).
- `match/When` (an objective kind id, a `Match` and a `Qualifier` pattern) is the one source matcher, and `match/MomentTable` the one fold and most-specific match over it (the Match's rank, then the Qualifier's, then fold order), memoized per kind, target and qualifier: zc-loot's bonus rows and zc-track's sources are both tables on it, so never keep a third ladder. A `Match` or `Qualifier` is a `match/MatchKey`: a name pattern, or a set key (`ItemTag:`, `BlockFamily:`, `NpcGroup:`, R858) ranked under every pattern and over `*` (`NameMatchRank.SET_BAND`), read through `match/MatchSets` (item tags and NPC groups off the engine here, block families through the seam zc-world's `GatherBootstrap` fills); a table holding a set key drops its memo when `MatchSets.generation()` moves (`MatchBootstrap` wires the item, group and role loads). A new form is a new `MatchKey.Form` and reader, never a consumer's own prefix.
- `season/DateWindow` is the one `MM-DD` reader (the calendar's windows, an offer's `Dates`): a yearly span of whole days in UTC, both days in, an end before its start crossing the new year. Pure: the caller passes the moment.
- `damage/HitTags` reads the native asset `Tags` on the interaction that dealt a hit, through the calculator the engine puts on it (`DamageCalculatorSystems.DAMAGE_SEQUENCE`), from `HitTagIndex` (identity-keyed, rebuilt on the first read after an `Interaction` load, which the root's `FrameworkAssetRegistrar` marks); `Hit` is always indexed, any other key a consumer reads is indexed once at setup with `HitTags.indexKey` (R248). A tagged effect's tick names its effect (`HitTags.effectOf`, through the calculator, so it reads alike on every engine line), and an applier finds the damage-dealing effect a tag names (`HitTags.effectsTagged`).
- `validation/TextKeyAudit` is the one check a content validator makes of an authored lang key (`UNKNOWN_TEXT_KEY`, a WARNING; every key reads as shipped while no catalogue is loaded).
- `validation/EffectNameCheck` holds R67: an effect with an effective `StatusEffectIcon` carries an effective `Name` a shipped `.lang` holds exactly as the server registers it (`<file stem>.<key>`, subfolders dotted before it), read from the lang files, never `ContentKeys.known` or `TextKeyAudit` (both accept any namespace); a costume-shaped effect needs an icon. An en-US gap fails every run, another locale's only under `-PlangGate` (counted per root). Each family repo runs it as one `ShippedEffectNamesTest`, and the MMO's `familyTest` over the packs (`PackEffectNamesTest`).
- `content/ServerContent` is the one way anything made in game is saved: an asset into the server content pack (`mods/ServerContent`, made and registered the way the Asset Editor makes a pack, loaded by the engine's own scan from the next start), typed words into its generated `server.lang` pack (never a `.lang` in the watched folder). Every save runs whole on `AssetStoreWriter.offThread` and answers a `Result` whose completion fails with a `ContentRefusedException`; an editor publishes on the completion, shows `AppliesWhen.notice()`, mints an id once with `mintId` and never renames it.
- `validation/BootAudit` runs the content audits once on `BootEvent` when the process carries `ZIGGFREEDCOMMON_AUDIT_ON_BOOT=1` (the dev harness exports it). It is an environment variable, never an owner key, so it never persists into a run directory. Its lines keep `ValidationReport`'s split (warnings at INFO), so a reader matches them by pattern, and one `[zc] boot audit: ` marker counts them, each at the level its pass gave it; the season boot verdict parses the marker, so change its wording only with the parser. A new pass is wired in the root's `registerBootChecks`: one that stands in for a first-join audit takes that audit's once-per-boot run (`claimLateFindings`, as commerce and placements do), and one that reads a lazily built engine builds it first (`TitleValidator.auditForcingBuild`), or it counts as run while it asked nothing.
