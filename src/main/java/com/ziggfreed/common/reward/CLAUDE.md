# reward/ - reward kinds that reach into another domain, registered from the wiring root

- A kind that pays into a domain zc-loot may never see (an effect, a costume) lives here and registers from `ZiggfreedCommonPlugin.registerLootVocabulary`, because zc-loot sits under everything that pays out. These files are held to `RootRegistrationOnlyTest`: guards that return or throw, null-default ternaries, no loop, `switch` or `else`; a real decision belongs in the module that owns the domain (`Costumes`, `NativeEffectUtil`).
- A kind throws when nothing landed (a quiet return reports it paid), except `Costume`'s queued dressing (below), and leaves `retryCommand` null when a replay later would be wrong: a costume is a moment, never parked for a later connect.
- `Costume` never writes the store during the payout: it queues the dressing onto the wearer's world (`World.execute`, on the world `cast/WorldEvictors.worldOf` answers), whose task queue runs outside every system's tick, so it pays the same from a page click, a command, a producer or an interaction chain, and the payout reports it paid, with nothing on the receipt, before it lands. Never ask the store whether it is processing (`Store.isProcessing()` is deprecated): queue.
- A refusal of a wearer still there pays the reward's `FallbackLootable` to the same player as one `Lootable` reward, through the registry the kind was registered into and labelled with the same source. With none, or one that cannot be rolled (no table answers to it, or it is empty), it is one warn line; a wearer gone before the task ran (the reference no longer valid, or no longer on this world's thread) is one warn line with no fallback; a loss with no fallback roll is also a `recordFailure` against the kind. A roll that lands nothing returns quietly, so a fallback table should always pay. Nothing on that path throws into the world's task queue.
- A fallback never rolls a fallback: the roll's subject carries the private `FallbackRoll` mark (`Subject.withFacets`), every reward the roll pays receives it, and a `Costume` paid with it reads no `FallbackLootable`. Without it, a table that pays a costume back re-queues for ever: the world drains its task queue in one pass, and the `Lootable` kind's nesting guard restarts in every task. Inside an interaction chain, the chain's own `ZigCostume` Type still dresses through the chain's command buffer and can branch on a miss.
